# B01 独立盲测执行协议

## 目的

本协议只检验两个候选适配器能否在新的合成输入上稳定输出约定的语义结构：

- D01：评论里的方面、情感与未知主题是否能按局部语义保留。
- D02：购买前搜索表达的意图、情感与机会规则边界是否能被区分。

它承接 Trial 02 的“可进入独立盲测”结论。它不验证真实消费者需求、市场规模、产品机会或经营价值。

## 当前状态

**待独立评审。** 输入包已经建立，拟议金标尚未独立复核并锁定，候选尚未在该包上运行。因此目前没有盲测分数，也没有“通过”或“失败”的结论。

## 独立性怎么做到

1. **独立标注复核人**不得参与本轮候选实现和原有标签设计。其任务是审阅拟议金标、处理歧义、决定最终解释，并创建 `gold/gold_label_lock.json`。
2. **独立执行人**只拿到输入包、候选版本和提交模板，运行时不得改写输入、金标或门槛；提交必须保留 D01/D02 候选代码指纹、执行时间和逐条输出。
3. **结果复核人**在金标锁定、输入指纹和候选输出完整后运行评分脚本，并复核是否达到门槛。

当前本地文件夹没有访问隔离或密码保护；独立性是必须被执行和记录的交接纪律，不是文件名本身能够证明的事实。若无法保证角色分离，应停止在“待独立评审”，不能把该包当成独立盲测。

## 固定门槛

| 检验项 | 门槛 | 失败后动作 |
|---|---:|---|
| D01 逐条方面/情感精确匹配 | 不低于 90% | 回到候选修复，不接触真实数据 |
| D02 意图/情感精确匹配 | 不低于 90% | 回到候选修复，不接触真实数据 |
| D02 机会规则边界 | 100% | 回到候选修复，不接触真实数据 |
| 输入、金标、候选输出的记录集合 | 100% 完整 | 拒绝评分，补齐或重新提交 |

## 执行顺序

1. 独立标注复核人复核拟议金标，并在锁定记录中写入金标 SHA-256、复核责任标识和锁定时间。
2. 独立执行人按输入包运行 D01/D02 候选，完整填充提交模板。
3. 结果复核人运行：

```bash
python3 skill-library/tools/score_b01_blind_submission.py /绝对路径/独立执行提交.json
```

独立执行人可先运行下面的无执行检查；它只核对输入数量、金标锁定状态和候选指纹，不调用候选：

```bash
python3 skill-library/tools/run_b01_blind_candidate.py --check-only
```

金标锁定后，独立执行人使用同一运行器生成新的提交文件。运行器会拒绝覆盖模板、拒绝在金标未锁定时运行，并且不读取金标、不计算分数。

4. 评分结果通过时，下一步只是**设计真实样本数据合同**：授权、脱敏、来源、市场、语言、时间窗、去重、抽样和保存边界。未完成该合同前，不能接入真实数据。

## 明确边界

- 不允许用本盲测的合成记录计数、正负标签或规则命中，推断消费者需求强度或市场机会。
- 不允许将通过结果直接升级为产品定义、投入、投放、采购、发布或业务动作。
- 不允许将通过结果当成岗位、Preset、Agent、权限或生产能力任命。
