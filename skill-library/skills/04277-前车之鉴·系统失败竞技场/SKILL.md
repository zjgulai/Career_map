# 前车之鉴·系统失败竞技场

三角色认知对抗协议：三个角色**各自用不同方法独立分析同一问题 → 找出结论间的张力 → 交集=高可信结论，冲突=真实盲区**。这不是头脑风暴，是结构化的对抗验证。

## 什么时候启动

- 做了正确的事，结果却越来越差
- 团队努力工作，系统却持续退化
- 短期改善，长期恶化
- 引入一个「好的」机制后产生了意想不到的副作用
- 组织/产品/项目陷入「饮鸩止渴」或「舍本逐末」模式

用户没明说但符合上述形态时，也应当启动本协议（在回答中直接采用其结构），并告知用户正在使用该思考协议。

## 竞技场协议（完整推理协议，按此结构作答）

你现在运行「系统失败认知竞技场」模式。三个角色从不同层次分析「为什么做了正确的事，结果却越来越差」——这类问题的答案几乎不可能在第一层分析中找到。

【角色阵容】

角色A — 系统结构分析师（系统思维）
立场：好意图+错误结构=确定失败。你在和反馈回路对抗，不是和具体的人对抗。
推理协议：
1. 列核心变量（存量/流量），识别正反馈/负反馈回路
2. 找「饮鸩止渴」或「舍本逐末」的经典系统基模特征
3. 定位延迟节点：干预效果要多久才显现？在此期间系统如何响应？
4. 找结构性杠杆点（改变规则/目标 > 改变回路 > 调整参数）
核心质疑：你的「解决方案」有没有在系统某处建立一个新的恶性回路？

角色B — 假设审计师（第一性原理）
立场：「这样做会让系统更好」——这句话背后的「更好」是什么定义的？目标定义错了，越努力越偏。
推理协议：
1. 列出系统设计的核心假设：「我们相信X会导致Y」——X和Y各是什么？
2. 逐条追问：这个「X→Y」的关系，是在当前具体系统里被验证过的，还是从别处类比来的？
3. 找「被惯性接受的目标定义」：系统在优化什么指标？这个指标真的代表你想要的吗？
核心质疑：你的目标函数是正确的吗？系统在完美地达成一个错误的目标。

角色C — 第二层思维观察者（第二层思维）
立场：所有人都看到的问题，解法已经被定价进系统了——没有超额效果。你的「显而易见的对策」会产生什么？
推理协议：
1. 识别「当前被广泛认同的解决方案」——所有参与者都在做什么？
2. 问：如果所有人都执行这个方案，系统会变成什么状态？（博弈均衡）
3. 找「非共识但正确」的节点：什么干预是大多数人没有在做、但有充分理由相信有效的？
核心质疑：你的对策是「第一层的显而易见」还是「第二层的非共识洞察」？

【竞技场规则】

Phase 1 — 独立发言：三个角色各自分析，格式不同（回路图/假设清单/共识-非共识分析）。

Phase 2 — 寻找张力（这是关键）：
- 系统分析师找到的「杠杆点」↔ 第二层思维检验：这个杠杆点是不是大家都知道的？如果是，它已经失效了。
- 假设审计师发现「目标定义可能是错的」↔ 系统分析师仍在用原目标优化——谁对？
- 这个三角张力通常会指向：系统在「完美地达成一个错误目标」这一核心悖论。

Phase 3 — 综合：
- 交集 = 三个角色都认为无法绕过的核心约束
- 冲突 = 三者对「解决路径」的分歧（这是最有价值的地方）
- 输出：①系统失败的根本机制 ②当前干预的二阶效应 ③真正的杠杆点

【质量门禁】如果输出的杠杆点是「大家都在谈论的那个方向」——这不是洞察，这是共识。继续找第二层。

## 启动话术（对 Codex/DSH 类对话代理直接粘贴用）

> 请三个角色帮我分析这个系统为什么在失败：

## 停止条件（防拖堂）

当①②③全部给出，且③经过假设审计确认不依赖未验证假设时停止。

综合输出必须落到决策性产物后即停，不再继续比较/分析本身。

## 三角色速览

- **系统结构分析师**（系统思维）—— 立场：好的意图 + 错误的系统结构 = 确定的失败。你在和系统的反馈回路对抗，而不是和具体的人对抗。
- **假设审计师**（第一性原理）—— 立场：你对「什么是成功」的定义本身可能是错的。如果目标定义错了，越努力越偏离。
- **第二层思维观察者**（第二层思维）—— 立场：所有人都看到了第一层问题，所以都在做第一层的修复。第二层是：你的修复行为本身正在创造什么新的系统动态？

## 何时不用 / 转诊

- 单点问题反复出现 → xmind-arena-rootcause
- 在选项间纠结 → xmind-arena-decision
- 竞争格局/多团队互相打架 → xmind-arena-strategy
- 团队迭代回顾 → retro；线上事故 → incident-retrospective

## 安全边界

涉及组织变革、裁员等重大人事决策：只做结构分析，不给出人事处置建议，提示寻求专业管理/法律咨询。
