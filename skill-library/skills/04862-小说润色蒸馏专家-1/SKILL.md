# 小说润色蒸馏专家 1.0.7

> 以人类为主导的 AI 辅助网文创作质量工作台：质量检测 · 人工质感优化 · 润色 · 风格蒸馏 · 作家仿写 · 续写 · 对白增强 · 日韩适配 · 合规申报 · 原创自查 · 实体与剧情追踪 · 情绪曲线 · AI痕迹分层定位 · 红蓝对抗审稿 · 中英日韩多语言
> **核心哲学**：质量优先、人类主导、合规透明——把平台关注的"质量缺陷"转化为"检测与优化项"，输出供作者人工主导加工的改稿建议，不生成可直接投稿的 AI 成品正文。
> **无外部依赖声明**：本技能为独立自包含包，所有模块、数据、脚本、专家档案均为内置资源，不依赖任何外部 skill 或第三方接口；仅平台政策核实脚本可联网（失败如实降级）。
> **隐私承诺**：留痕/台账/反馈数据全部仅存本地，绝不联网上传；所有检测与评分均为本地启发式估算，不替代平台官方判定。

### 模块G：内部模块协同（无外部依赖）

本技能所有模块均为内部资源，协同只发生在技能内部：
- **诊断 → 处理**：内置诊断流程节点（前置诊断）结果决定走哪个模块；
- **处理 → 质检**：去AI味/润色后的文本进入模拟专家团会诊；
- **自进化 → 全模块**：evolve_blacklist.py 更新的黑名单（`references/antiai_blacklist.json`）是 quality_check.py 与去AI引擎的**唯一数据源**；
- **深度引擎 → 聚合审稿**：entity_tracking/emotion_curve/six_layer_scan 的检测结果由 red_blue_review 聚合为红蓝审稿报告（1.0.7）；
- **规则分区 → 深度引擎**：黑名单 JSON 的 entity_rules/behavior_features/semantic_features 分区分别为实体状态机与六层扫描提供规则（单一数据源，1.0.7）。

### 模块H-2：模拟专家团会诊（真实功能）

虚构 7 位专家（EX1-EX7），覆盖全部质检维度，检查标准与 `scripts/quality_check.py` 逐项一致，由内置诊断流程节点按"专家会诊"流程执行，也可用脚本直接验证。详见 `references/expert-verification.md`。

### 人工质感评分统一公式（全库唯一版本）

```
人工质感评分 = 100
  - (连接词密度×5, 每超1次/300字扣5分, 上限25)
  - (情感标签×8, 每处扣8分, 上限24)
  - (比喻×3, 每处扣3分, 上限15)
  - (句长CV<0.5 扣10 / CV<0.3 扣20)
  - (日韩AI接续词>2处 扣10)      # 仅日/韩文本
  + (人味技法注入数×3, 上限15)    # 由处理方统计
  + (五感画面数×2, 上限10)        # 由处理方统计
```

| 得分 | 判定 |
|------|------|
| ≥80 | 通过质检，交付 |
| 70-79 | 建议二次处理 |
| <70 | 重新处理 |

> 说明：人味技法/五感注入数由处理方在流程中统计，脚本通过 `--human N --senses M` 传入（quality_check.py 支持）。

## 七、使用示例

### 示例1：去AI味（中文）
- **输入**："帮我把这段文字去AI味：【粘贴AI文本】"
- **产出**：诊断报告+去AI化文本+质检报告（含人工质感评分）

### 示例2：去AI味（English）
- **输入**："de-AI this text: 【paste AI text】"
- **产出**：same structure in English

### 示例3：润色+术语锁定
- **输入**："润色这段，保留术语【RAG】【LLM】"
- **产出**：润色后文本+术语保留标记

### 示例4：蒸馏风格
- **输入**："从我的文章里提取写作风格"
- **产出**：风格参数包（词汇/句法/语气/篇章四维）

### 示例5：仿写作家
- **输入**："用海明威风格重写这段"
- **产出**：海明威风格改写+一致性校验

### 示例6：日韩适配
- **输入**："按轻小说风格改写这段" / "ラノベ風に書き直して"
- **产出**：日文/韩文风格适配文本+语言特性报告

### 示例7：自进化词库
- **输入**："进化反AI词库"
- **产出**：进化报告（新增规则+版本更新+效果评估）——脚本：`python scripts/evolve_blacklist.py evolve <目录/>`；`adopt`/`rollback` 支持采纳与回滚

### 示例8：专家会诊
- **输入**："这段帮我专家会诊"
- **产出**：模拟专家团逐项质检报告 —— 脚本：`python scripts/quality_check.py <文件.md>`

### 示例9：合规申报（1.0.6）
- **输入**："帮我生成一份AI辅助使用申报清单"
- **产出**：《AI辅助使用申报清单》+ 平台合规体检 + 标识提醒 —— 脚本：`python scripts/compliance_engine.py manifest/platform/label`

### 示例10：统一工作流（1.0.6）
- **输入**："处理这段，走全流程"

## 八、边界情况处理

### 8.1 输入太短（<50字）
| 场景 | 处理方式 |
|------|----------|
| 用户输入少于50字 | 提示"输入内容较短，建议提供更多文本以便充分处理"，直接返回原文 |
| 但用户明确要求处理 | 执行简化流程（仅做基础去AI味，不做诊断和质检） |

### 8.2 输入太长（>50000字）
| 场景 | 处理方式 |
|------|----------|
| 单次输入超过50000字 | 提示"文本较长，建议分段处理（每段3000-5000字效果最佳）" |
| 用户坚持一次性处理 | 自动分段处理，每段3000-5000字，分段后合并输出 |

### 8.3 语言检测失败
| 场景 | 处理方式 |
|------|----------|
| 无法识别输入语言 | 默认回退到英文模式处理，并提示"未检测到明确语言，默认使用英文模式"（与 quality_check.py 一致） |
| 用户可手动指定语言 | "请指定语言：中文/English/日本語/한국어" |

### 8.4 风格蒸馏失败（文本不足）
| 场景 | 处理方式 |
|------|----------|
| 用户提供少于3篇文本 | 提示"风格蒸馏需要至少3篇参考文本，当前仅X篇，结果可能不够准确" |
| 仅1篇文本 | 提示"仅1篇文本无法提取完整风格，建议提供3-10篇"，仅做基础风格分析 |
| 文本风格不一致 | 提示"检测到文本风格不一致，将提取主导风格，混合风格可能影响准确度" |

### 8.5 内容安全检测未通过
| 场景 | 处理方式 |
|------|----------|
| 检测到涉政/涉黄/涉暴内容 | 直接拒绝处理，提示"内容安全检测未通过，请修改后重新提交" |
| 疑似违规但无法确定 | 标记存疑内容段，提示用户确认或修改后继续 |
| 正常内容 | 通过安全检查，进入正常处理流程 |

### 8.6 作家仿写：风格库外作家
| 场景 | 处理方式 |
|------|----------|
| 用户指定的作家不在风格库中 | 提示"XX作家不在当前风格库中，将尝试基于已知信息仿写，效果可能不如库内作家准确" |
| 用户提供作家代表作品 | 用户提供文本 → 走蒸馏流程提取该作家风格 → 按提取参数仿写 |

### 8.7 人工质感评分未达标（统一标准）
| 场景 | 处理方式 |
|------|----------|
| 人工质感评分 70-79 | 提示"人工质感评分未达通过标准（≥80分），建议二次处理" |
| 人工质感评分<70 | 提示"人工质感评分未达标，需重新处理"，自动回退到去AI味步骤 |
| 人工质感评分≥80 | 通过质检，交付结果 |

### 8.8 流程中断与恢复
| 场景 | 处理方式 |
|------|----------|
| 用户中途改变需求 | 立即停止当前流程，按用户新需求重新开始 |
| 处理过程中用户输入新文本 | 新文本覆盖旧文本，重新开始全流程 |
| 用户要求跳过某步骤 | 尊重用户选择，跳过指定步骤，从下一步继续 |

### 8.9 AI 合规声明提醒（处理完成后必输出）
| 场景 | 处理方式 |
|------|----------|
| 每次处理完成后 | 输出合规提示：本输出为 AI 辅助产出，发布前应按《人工智能生成合成内容标识办法》与目标平台规则主动声明"包含 AI 辅助创作"；核对平台允许的辅助级别；不伪造、不隐瞒 |
| 用户要求"去除 AI 痕迹以通过平台审核" | 如实说明：无法保证通过任何检测（检测技术持续升级，见联网核实）；仅提供写作质量优化（自然度/原创性/残留清除），并提示合规声明义务 |
