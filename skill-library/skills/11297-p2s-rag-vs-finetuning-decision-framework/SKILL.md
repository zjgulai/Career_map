# Skill-RAG-vs-Finetuning-Decision-Framework

## ① 解决的问题

AI工程师面临"不知道该用RAG还是微调，两套方案都尝试耗时2个月"——RAG vs微调决策框架从数据动态性/长尾覆盖/推理成本三维量化评估，选型决策时间从2个月压缩至3天，避免错误技术路线

## ② 核心算法逻辑

核心公式：决策函数 D = argmax(α·T + β·P + γ·C + δ·S)，其中T=时效性评分(01)、P=精确度权重、C=成本系数、S=个性化需求度。

## ③ 业务应用场景

业务问题：孕妇营养禁忌知识每月更新（新研究、法规变化），传统FT模型3个月才能更新一次，导致过期建议风险。
数据要求： - 合规知识库：2000+条孕期禁忌条目（医学文献+国家标准GB 7718） - 更新频率：周级（新研究发布） - 向量维度：1536（OpenAI embedding） - 检索召回率目标：≥95%
量化产出： - 响应延迟：<800ms（RAG）vs 3-5s（FT推理） - 准确率：94.2%（RAG+重排）vs 89.1%（FT基线） - 月更新成本：¥3,000（向量库维护）vs ¥45,000（FT重训）

## 输入 / 输出契约

**输入**：合规知识库条目（医学文献与国家标准条目，含周级更新计划）、embedding 向量维度 1536 与检索召回率目标 ≥95%，以及两条候选路线各自的推理延迟与更新成本实测值。

**输出**：选型结论与量化对比：响应延迟 <800ms（RAG）对 3-5s（FT 推理）、准确率 94.2%（RAG+重排）对 89.1%（FT 基线）、月更新成本 ¥3,000 对 ¥45,000，供 AI 工程与产品负责人做路线决策。

## 执行步骤

1. 确认知识库的更新频率与合规条目规模
2. 校验向量维度与检索召回率是否达标
3. 对比两条路线的准确率与响应延迟
4. 对比两条路线的月更新成本
5. 输出选型建议并标注需人工复核的合规条目

## 边界与不做

- 没有成规模的合规知识库条目、或缺少两条路线的实测对比数据时不用本卡
- 本卡只产出选型判断与量化对比，不实现检索服务或训练流程
- 合规知识库涉医学与法规条目，选型结论不得替代合规审查
