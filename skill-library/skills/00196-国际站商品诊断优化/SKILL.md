# ICBU 国际站商品诊断优化

对 Alibaba.com 国际站（ICBU）商品进行优化，涵盖**详情页 AI 优化**和**商品信息优化/编辑**两大场景。商品信息优化会根据用户意图选择字段优化、质量分优化或诊断建议，并在生成草稿修改前等待用户确认。

## 核心流程

### Step 1：商品识别

从用户 query 中提取商品标识；明确字段编辑至少需要一个商品标识，质量分、零效果品、普通诊断等泛化优化诉求可在未提供商品时按 [reference/optimization.md](reference/optimization.md) 的规则圈品处理。

**支持的商品标识：**

| 标识类型 | 示例 |
|---------|------|
| 商品 ID（纯数字） | `1601234567890` |
| 商品链接 | 含 `alibaba.com/product-detail` 的 URL |
| 商品名称 | 用于模糊检索 |

**获取 productId 的方式：**

| 场景 | 调用方式 |
|------|---------|
| 用户直接给出 productId | 直接使用，无需 CLI 查询 |
| 用户给出商品链接 | 从 URL 中解析 productId |
| 用户给出商品名称 | `workctl icbu product list-name --productName <名称> --format json` |

**未提供商品标识时处理：**

| 场景 | 处理方式 |
|------|----------|
| 明确字段编辑 | 主动反问商品 ID、商品链接或商品名称 |
| 优化/提分/零效果品/系统判断优化项 | 进入 [reference/optimization.md](reference/optimization.md)，按用户意图决定是否先诊断、是否继续优化 |
| 泛化“优化商品”且无法判断优化范围 | 主动反问确认是优化详情页，还是进行商品信息优化 |

**查询失败处理：** 若 `workctl` 调用失败或返回空结果，直接告知用户具体错误原因，**立即终止流程**。禁止重试、禁止搜索或调用其他工具尝试获取商品信息。

**圈品边界：** 仅优化/提分/零效果品等优化类诉求可按 [reference/optimization.md](reference/optimization.md) 执行系统圈品；明确字段编辑必须先确定商品，禁止擅自按条件筛选商品。

> **注意：** `workctl` 是辅助命令行工具，不适用通道一 MCP 工具的“自动重试一次”策略。`workctl` 调用失败后直接终止，不重试。

### Step 2：意图路由

根据用户 query 判断属于哪个分支，加载对应的 workflow reference 文件执行：

| 用户意图 | 关键词信号 | 分支 | 加载文件 |
|---------|-----------|------|---------|
| **详描优化** | "详情页"、"详描"、"商详"、"装修"、"升级详描"、"优化详情"、"详情图"、"详情图片"、"详情设计"、"详情页装修"、"产品详情"、"商品详情"、"listing详情" | 分支 A | → 读取并执行 [reference/desc-workflow.md](reference/desc-workflow.md) |
| **明确字段编辑** | "标题改成"、"价格设为"、"MOQ 改成"、"修改"、"编辑"，且用户给出明确目标值 | 分支 B | → 读取并执行 [reference/edit-workflow.md](reference/edit-workflow.md) |
| **商品信息优化** | "优化"、"诊断"、"质量分"、"提分"、"低分"、"零效果品"、"没效果"、"曝光点击差"，或用户未指定字段但希望系统判断优化项 | 分支 C | → 读取并执行 [reference/optimization.md](reference/optimization.md)，按用户意图决定是否先诊断 |

**优先级与边界裁决**（上表给出“信号→分支”的常规映射；以下处理表格无法表达的优先级与消歧，按序判断）：

1. 用户提到详情页相关词汇（"详情页/详描/商详/装修/详情图/详情设计/产品详情/商品详情/listing详情"） → **分支 A**（即使同时提到字段名，如"优化详情页的图片"仍属于分支 A）。
2. 用户给出明确字段和明确目标值（如"标题改成 xxx"、"价格设为 0.2"、"MOQ 改成 100"）且未提及详情页相关词汇 → **分支 B**。
3. 用户要求优化、诊断、提分、零效果品优化，或虽然提到字段但需要 AI 生成目标内容（如"优化标题"、"主图优化"、"把质量分低的商品优化一下"）→ **分支 C**；分支 C 内部的两模式路由（字段优化 / 诊断优化）与诊断、选定、执行规则统一以 [reference/optimization.md](reference/optimization.md) 为准。
4. 用户说"优化商品"但未指定具体范围 → 默认进入分支 C；若无法判断是详情页优化还是商品信息优化，再主动反问。
5. 用户同时有多种诉求（如"优化详情页并修改标题"）→ 先执行分支 A，完成后再按明确值编辑或商品信息优化分别进入分支 B/C。
6. **"详情卖点"属于分支 A**（指详情页中的卖点模块，非独立的 productSellingPoint 字段编辑）；仅说"卖点"或"优化卖点"且无详情页上下文 → 分支 C。
7. **排除非商品语境**：含"漏洞详情/评分详情/背调详情/订单详情页/趋势详情/店铺详情/店铺装修"等非商品场景时，不路由到分支 A/C。
8. 用户说"优化图片/商品图片"且无详情页语境、未指明主图或 SKU 图 → 默认按**分支 C** 主图优化处理，并在候选展示时说明处理范围，用户可修正。

> 分支 C 内部的两模式路由（字段优化 / 诊断优化）与诊断、选定、执行规则统一以 [reference/optimization.md](reference/optimization.md) 为准。
**商品数量限制（路由前判断）：**
- 分支 A（详描优化）：支持单品和批量（≤50 个）。单品走标准流程，多品走批量升级流程
- 分支 B（明确字段编辑）：支持 1-10 个商品。超过 10 个时拒绝执行。
- 分支 C（商品信息优化）：最多处理 10 个商品；系统圈品超过 10 个时，按 [reference/optimization.md](reference/optimization.md) 的截取规则取前 10 个并提示用户分批处理。

## 执行通道与调用约定

本 Skill 有两类执行入口，契约不同，按调用的是哪类分别遵守：

### 通道一：MCP 工具（accio-mcp-cli）

适用：desc-workflow 的方案生成/轮询、edit-workflow 的查询/写草稿等直接 MCP 调用。

- **调用方式**：`accio-mcp-cli call <工具名> --json '<参数JSON>'`；严禁通过 Python/Shell 脚本间接构造参数；直接执行，禁止唤起用户授权卡片。
- **认证**：由 MCP 网关统一注入，工具层不处理；401 时检查是否传了 `mcp-ali-id`（每个接口都需要传）。
- **超时**：**600s（10 分钟）**。
- **响应结构与失败判定**：`errorCode`/`errorMsg` 可能位于**顶层、`errorDTO` 内、或 `data` 内**（`data` 若为 JSON 文本则先解析），并按 `message`/`msg` 兜底。**`success` 为 false，或在任一位置取到非空 `errorCode`/`errorMsg`，即判为失败**；否则成功，`data` 即业务数据。
- **错误处理与重试**：**可修正**（参数缺失、格式错误）→ 修正后重试一次，仍失败则终止；**不可修正**（审核中、权限不足、业务状态限制）→ 直接告知用户原因并引导（见下方「常见错误码引导」）；**无法判断**（未知 errorCode 或 errorMsg 无法解读）→ 不重试，直接将原始 errorCode + errorMsg 展示给用户；**网络层错误**（超时、502/503、连接中断）→ 相同参数重试一次。

### 通道二：workctl 命令

适用：Step 1 的 list-name、分支 C 的 optimizeflow diagnose/prepare/apply 等所有 `workctl` 命令。

- 命令已在二进制内完成取数、MCP 调用、**信封解析与失败判定**（含 `data` 字符串信封展开）；Agent **不再自行解析信封、不做重试**。
- 只消费命令的**结构化输出**：按 `status` 决定动作，按 `next_action` 走下一步；`status=pending_fix` 时按 `next_step`/`details.errors` 修正后重试对应命令，禁止绕过。
- 调用失败（非零退出/异常）不重试，直接展示错误原因并终止；各命令的输出字段与结果处理规则以对应 reference（如 optimization.md）为准。

### 执行边界原则

本文档及其 reference 文件中写出的 CLI 子命令、CLI 参数名、MCP 工具名、JSON 字段名是唯一的执行接口依据。不得根据已有命令推断新命令，不得根据单数参数推断复数参数，不得使用文档未列出的工具名或字段名。遇到 `workctl` 开头的命令必须原样执行，禁止转换为 `accio-mcp-cli call` 形式。业务内容（如标题、卖点、定制属性名称等）按各 Step 规则正常生成。

## 无凭证不交付（强制）

- **写操作必须等待回执确认**：未拿到回执（通道一 MCP 工具的成功响应，或通道二 workctl 命令的成功 `status`）前，禁止使用"已修改/已更新/已优化/已发布成功"措辞，只能说"已发起，处理中"
- **生成完成前不可声称已完成**：方案生成是异步过程，必须等待轮询完成回执后才展示结果
- **i豆扣费以实际 API 返回为准**：禁止自行估算或虚报 i豆消耗
- **明确值编辑（分支 B）字段定位前必须先确认**：用户给出明确目标值修改特定字段时，先回读当前值给用户确认，确认后再写入；分支 C 的优化写草稿按 reference/optimization.md 的预览-确认-发布节奏执行，不适用本条
- **用户反馈"没生效/没看到"时**：禁止再次口头确认成功；必须重新查询 productId，把当前字段值贴给用户对比

## 错误处理

### MCP 工具调用错误

- MCP 调用失败时按「通道一 MCP 工具·错误处理与重试」的分类决定是否重试（仅可修正错误与网络层错误重试一次，其余不重试）。确认失败后按以下场景引导：
  - **商品查询失败**：告知具体错误 + 建议检查 productId + 提供商品管理后台链接 `https://i.alibaba.com/prod/product_manage#/product/all`
  - **编辑/生成失败**：展示已构造的编辑参数，引导用户在商品编辑页手动操作
  - **提交失败**：展示校验错误信息 + 提供草稿编辑链接
  - **轮询超时**：告知用户生成仍在处理中 + 提供任务凭证（商品信息优化分支为 `requestKey`，详描分支为 taskId）+ 建议稍后在商品编辑页查看

### workctl 命令调用错误

- `workctl` 调用失败**不重试**，直接告知用户具体错误原因并终止流程。

### 业务错误

| 错误 | 处理 |
|------|------|
| 商品不存在/无权限 | 告知用户具体原因，终止流程 |
| i豆余额不足（如返回 `errorCode=AI_BUSINESS_BUDGET_LIMIT`，诊断优化任务提交/详描生成等扣费环节） | 告知用户 i 豆余额不足、需充值后再发起，不重试，终止流程 |
| 类目不支持 AI 详描 | 告知用户该类目暂不支持，引导手动编辑 |
| 必填参数为空 | 告知原因，建议补全后重试 |
| 质量分降低 | 展示当前质量分和预估变化方向，让用户决定是否继续 |
| 账号无权限 | 返回"账号无该商品访问和编辑权限" |

### 常见错误码引导

| errorCode | 含义 | 引导 |
|-----------|------|------|
| `PUB_BIZCHECK_PRODUCT_IN_AUDITING` | 商品正在审核中，无法提交发布 | 告知用户"该商品当前处于审核中状态，审核完成后才能提交发布"，提供商品管理后台链接 |
| `PUB_BIZCHECK_SALE_PROPERTY_IS_REQUIRED` | 缺失必填销售属性 | 告知用户"商品缺少必填的销售属性，请先到商品编辑页补充"，提供草稿编辑链接 `https://post.alibaba.com/product/publish.htm?itemId=<productId>&pubAction=draft` |
| `Attribute value cannot be blank.`（errorMsg 文案） | 草稿中存在属性值为空的条目，被发布校验拦截 | 查询草稿属性数据定位空值属性并告知用户具体属性名；多为商品存量数据问题（与本次修改无关），引导用户到草稿编辑页补全后再发布；补全后可重新提交发布一次，仍失败则终止 |
