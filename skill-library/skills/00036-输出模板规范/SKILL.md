# 输出模板规范

> **引用方**: 全体Agent通用
> **使用说明**: 所有Agent输出文件/报告时，必须遵循本规范中的格式标准，确保团队输出风格统一。

---

## 一、Excel格式标准

### 1.1 配色规范

| 用途 | 颜色值 | 示例场景 |
|------|--------|---------|
| **表头背景** | `#1F4E78`（深蓝）+ 白色文字 | 所有数据表第一行 |
| **交替行A** | `#DEEBF7`（浅蓝）| 奇数数据行 |
| **交替行B** | `#FFFFFF`（白色）| 偶数数据行 |
| **高亮/注意** | `#FFF2CC`（浅黄）| 需要人工确认的字段 |
| **通过/达标** | `#C6EFCE`（浅绿）| 指标达标、审核通过 |
| **警告/不达标** | `#FFC7CE`（浅红）| 指标异常、需整改 |

### 1.2 排版规则

| 规则项 | 要求 |
|--------|------|
| 字体 | **Arial**（英文/数字）|
| 字号 | 表头12pt加粗，正文10pt |
| 列宽 | 自适应内容，最小12字符宽 |
| 边框 | 细边框 `thin border`，颜色 `#B4C6E7` |
| 冻结 | 首行冻结（Freeze Top Row）|
| 筛选 | 启用自动筛选（Auto Filter）|
| 数字格式 | 金额保留2位小数，百分比保留1位小数 |

### 1.3 工作表命名规范

```
{类型}_{内容简述}
```

示例: `诊断_店铺总览` / `产品_ABC分级` / `竞品_对比矩阵`

## 二、Markdown报告标准

### 2.1 结构要求

```markdown
# {报告标题}

> **商家**: {店铺名称}
> **诊断日期**: {YYYY-MM-DD}
> **报告版本**: v{X.X}

---

## 总体判断
{一句话结论}

## 行动清单

### P0（紧急-24h内处理）
- [ ] {具体动作}

### P1（重要-7天内完成）
- [ ] {具体动作}

### P2（优化-30天内推进）
- [ ] {具体动作}

## 详细分析
{按模块展开}

## 数据来源
{标注数据来源和获取时间}
```

### 2.2 数据表格规范

| 规则 | 说明 |
|------|------|
| 交替行 | Markdown中使用HTML表格实现交替色 |
| 对齐 | 数字右对齐，文字左对齐 |
| 单位 | 表头标注单位，数据行不重复单位 |

### 2.3 优先级标记

| 标记 | 含义 | 时限 |
|------|------|------|
| **P0** | 紧急——影响核心指标或存在风险 | 24小时内 |
| **P1** | 重要——影响效率或有明显提升空间 | 7天内 |
| **P2** | 优化——长期改善项 | 30天内 |

## 三、HTML报告标准

### 3.1 技术要求

| 规则 | 说明 |
|------|------|
| 编码 | UTF-8，自包含（无外部依赖）|
| CSS | 使用CSS变量定义主题色，内联`<style>` |
| 响应式 | 适配桌面端阅读，打印友好 |
| 字体 | 系统字体栈：`-apple-system, "Microsoft YaHei", sans-serif` |

### 3.2 CSS变量定义

```css
:root {
  --color-primary: #1F4E78;
  --color-success: #C6EFCE;
  --color-warning: #FFF2CC;
  --color-danger: #FFC7CE;
  --color-text: #333333;
  --color-bg: #FFFFFF;
  --color-row-alt: #DEEBF7;
}
```

### 3.3 三段式写作策略

| 段落 | 内容 | 读者 |
|------|------|------|
| **第一段：摘要** | 一页纸结论+关键数字+行动建议 | 老板/决策者 |
| **第二段：分析** | 分模块详细分析，含数据图表 | 运营负责人 |
| **第三段：附录** | 原始数据、方法论说明、参考资料 | 执行层/审计 |

### 3.4 证据等级标签

在HTML报告中使用以下标签标注数据可信度：

| 标签 | 含义 | 样式建议 |
|------|------|---------|
| 🟢 **强证据** | 多源交叉验证，高可信度 | 绿色标签 |
| 🔵 **较强证据** | 单一权威来源，较可信 | 蓝色标签 |
| 🟠 **推导结论** | 基于已知信息的合理推断 | 橙色标签 |
| ⚪ **待验证** | 需后台数据或人工确认 | 灰色标签 |

## 四、图片标准

### 4.1 尺寸规范

| 用途 | 尺寸 | 比例 | 说明 |
|------|------|------|------|
| **B2B主图** | 800×600px 以上 | **4:3** | 产品白底图/场景图 |
| **详情页图** | 1920×1080px 以上 | **16:9** | 长图详情中的模块图 |
| **PC端Banner** | 1920×600px | — | 旺铺首页/活动页横幅 |
| **移动端Banner** | 750×450px | — | 无线端店铺横幅 |
| **展会Banner** | 1920×650px | — | 线上展会专区展示位 |

### 4.2 图片质量要求

| 规则 | 说明 |
|------|------|
| 格式 | JPG（照片类）/ PNG（图表/透明）|
| 分辨率 | ≥72dpi（屏幕）/ ≥300dpi（印刷）|
| 文件大小 | 单图≤5MB |
| 水印 | 不加水印（平台规则），如需防盗图使用平台保护功能 |
| 背景 | 主图白底或场景化，禁止杂乱背景 |

## 五、文件命名规范

### 5.1 报告类文件

```
{店铺名称}_{报告类型}_{日期YYYYMMDD}
```

示例:
- `ABC公司_店铺诊断报告_20260608.xlsx`
- `XYZ公司_竞品分析_20260608.md`
- `DEF公司_运营周报_20260608.html`

### 5.2 产品类文件

```
{产品名称}_{能力维度}
```

示例:
- `CNCFresingMachine_标题优化.md`
- `LEDPanel_卖点撰写.md`
- `YogaMat_详情页策划.md`

### 5.3 版本控制

| 场景 | 命名方式 |
|------|---------|
| 初版 | `_v1.0` |
| 修订 | `_v1.1`（小改）/ `_v2.0`（大改）|
| 终版 | `_FINAL` |

## 六、证据等级标注体系

> 适用于所有Agent输出中引用的数据和结论。

| 等级 | 标记 | 定义 | 使用场景 |
|------|------|------|---------|
| **强证据** | 🟢 | 多源交叉验证，数据一致 | 平台官方数据+第三方报告+实际验证 |
| **较强证据** | 🔵 | 单一权威来源，可信度高 | 平台后台数据/官方文档 |
| **推导结论** | 🟠 | 基于已知信息的合理推断 | 行业趋势推断/竞品推测 |
| **待验证** | ⚪ | 需后台数据或人工核实 | 未经验证的卖家自述/推测性数据 |

**使用示例**:
```
该产品类目月均搜索量约50万次 🟢（来源：平台关键词指数 2026-05）
竞品A的月成交额估计在$80K-120K之间 🟠（基于排名和转化率推算）
建议将MOQ从500降至200以提升询盘量 ⚪（需A/B测试验证）
```

## 七、警告标记规范

> 涉及需人工审核的敏感字段，必须添加警告标记。

### 7.1 需标记的字段类型

| 字段类型 | 风险说明 |
|----------|---------|
| ⚠️ **价格数据** | 涉及商业机密，需确认是否为最新/准确价格 |
| ⚠️ **交期承诺** | 影响履约评分，需确认实际产能匹配 |
| ⚠️ **认证承诺** | 涉及合规风险，需确认证书真实有效 |
| ⚠️ **产能数据** | 影响客户预期，需与实际产线匹配 |
| ⚠️ **专利声明** | 涉及知识产权风险，需法务确认 |

### 7.2 标记格式

```
{数据内容} ⚠️ [待人工确认: {原因}]
```

**示例**:
```
交货周期: 15-20个工作日 ⚠️ [待人工确认: 需与生产部门核实当前排产情况]
持有CE认证 ⚠️ [待人工确认: 需核实证书有效期及覆盖产品范围]
月产能50万件 ⚠️ [待人工确认: 需确认是否含外协产能]
```

## 八、微信/IM精简格式

> 适用于需要即时转发给商家的场景，一条消息传达核心信息。

### 8.1 格式原则

| 原则 | 说明 |
|------|------|
| 一行一指标 | 便于手机端阅读 |
| 数字前置 | 关键数据放最前面 |
| 总字数控制 | 单条消息≤300字 |
| 无表格 | IM不支持表格渲染，用文字替代表达 |
| 分级标记 | 用emoji标记优先级（仅IM场景允许）|

### 8.2 模板示例

```
📊 {店铺名}诊断速报

⭐ 星等级: {X}星（目标{Y}星，差距{Z}分）
📦 精品率: {X}%（健康线50%）
⏱️ 及时回复: {X}%（达标/需改善）
💰 P4P消耗: ¥{X}/月，单商机成本¥{Y}
📈 询盘转化: {X}%（行业均值{Y}%）

🔴 P0紧急: {一句话描述}
🟡 P1重要: {一句话描述}

详细报告已生成，稍后发送完整版。
```

## 九、Agent输出自检清单

每次输出文件前，执行以下检查：

- [ ] 配色是否遵循规范（表头深蓝、交替行、状态色）？
- [ ] 文件命名是否符合规范？
- [ ] 数据是否标注证据等级？
- [ ] 敏感字段是否添加 ⚠️ 警告标记？
- [ ] 报告是否包含行动清单（P0/P1/P2分级）？
- [ ] 图片尺寸是否符合平台要求？
- [ ] Excel表是否冻结首行+启用筛选？
- [ ] HTML报告是否UTF-8自包含？
