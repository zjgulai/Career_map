# 国际站禁限售规则解读

判断商品在指定目的地是否可售，输出「平台管控 + 合规要求 + 底部链接」。**所有内容仅来自 MCP 返回的 8 个字段（`isMatchCountryRule`/`productCategoryWord`/`destinationCountry`/`ruleId`/`ruleTitle`/`ruleContent`/`ruleLink`/`ruleCreateDate`），禁止任何外部检索与自主推演。**

## 0. 首轮硬红线（最高优先级，激活即生效）

### 0.1 数据隔离
- 🚫 严禁读取 `memory/queries.json` / `TASK_HISTORY.json` / `MERCHANT_PROFILE.json` 等记忆/缓存/历史文件作为执行依据
- 🚫 严禁用历史记录"补全"用户本次未提供的入参（缺参按缺参处理，🚫 不从记忆里取）
- 🚫 严禁跨轮次复用解析/预测结果，每次从零开始
- **输入白名单**：仅① 用户当前消息、② 当前会话上游步骤返回值（MCP Step 1 / Step 2 输出）；本轮 `SKILL.md` + `references/*.md` + `examples.md` 视为执行说明与格式范本，不属于"执行依据的数据来源"约束

- **实事求是**：所有合规条款、警示语、追问维度必须能在本次 MCP `ruleTitle` / `ruleContent` 中找到对应原文语义；🚫 严禁用"最严口径 / 稳妥起见 / 一般来说 / 通常需要"补写 MCP 未返回条款；🚫 严禁把训练数据中的行业常识写进合规要求
- **证书/资质上传操作路径零猜想**：涉及"证书上传后台入口、下拉选项、字段名、上传流程步骤、证书编号格式、图片规格、菜单路径"等**每一句、每一步、每一个字段名必须完全取自 MCP 原文**；🚫 严禁凭卖家中心一般经验/常识补写；🚫 严禁拼接后台导航链（如"卖家中心 → 我的账号 → 资质中心"）；原文未提供操作路径 → 只列资质名称 + 提示"具体上传路径请以卖家中心当前指引为准 / 详见 [规则链接] 原文"

## 2. 默认执行路径

### 2.1 入参提取

- **品类** `productInfo` **必填**：原文取值，🚫 不做类目换算、同义词替换、归纳优化；多品类各自作为**独立品类词**参与需求拆解，🚫 不做 `productInfo` 逗号拼接
- **目的地** `destination` **可选**：单值原文（国家名、大区名、经济体名保持原文）；用户未提及时留**空字符串 `""`**
  - 🚫 严禁传 `null` / 省略字段 / 写"全球/通用/未指定"占位
  - 🚫 严禁把"美国""欧盟"等当默认值填入
  - 🚫 严禁在用户未写目的地时追问"想卖到哪国"
- **缺 `productInfo`** → **暂停 MCP 调用**，追问用户"想咨询哪个具体品类的禁限售规则"
- **缺 `destination`** → **不追问**，直接以空字符串传入 MCP 查全平台通用规则

### 2.2 需求拆解（笛卡尔积 或 用户明确绑定）

| 用户输入 | 拆解成 N 个独立需求（每行 = 1 次独立 MCP 调用） |
|---|---|
| 单品类 + 无目的地（"摩托车头盔能否卖"） | `{摩托车头盔, ""}` |
| 多品类 + 无目的地（"电池、电动车能否卖"） | `{电池, ""}` / `{电动车, ""}` |
| 单品类 + 单目的地（"卖到美国"） | `{X, 美国}` |
| 单品类 + 多目的地（"美国、欧盟和英国"） | `{X, 美国}` / `{X, 欧盟}` / `{X, 英国}` |
| 多品类 + 单目的地（"电池、电动车 → 美国"） | `{电池, 美国}` / `{电动车, 美国}` |
| 多品类 + 多目的地（"电池、电动车 → 美国、欧盟"） | 笛卡尔积 4 个 |
| **用户明确绑定**（"电池销往美国、电动车销往欧盟"） | 按绑定 `{电池, 美国}` / `{电动车, 欧盟}`（🚫 不做笛卡尔积） |

规整用户中文顿号「、」、中文逗号「，」、"和/及/与"、"以及/还有"等为**分隔符**，目的地词与品类词本身保持原文。

### 2.3 MCP 两步式调用（需求级并联 + Step 2 轮询）

**Step 1 唯一调用方式**（每需求一次，多需求并联发起，🚫 不轮询、🚫 不重发）：

- **模板 A（仅品类）**：
  ```bash
  accio-mcp-cli call prohibited_rule_interpretation --json '{"request": {"destination": "", "productInfo": "<品类词>"}}'
  ```
- **模板 B（品类 + 目的地）**：
  ```bash
  accio-mcp-cli call prohibited_rule_interpretation --json '{"request": {"destination": "<目的地>", "productInfo": "<品类词>"}}'
  ```

**Step 1 铁律**：

- 🚫 严禁改动 JSON 结构（`request` 外层必留、字段名严格拼写为 `destination` / `productInfo`）
- 🚫 严禁额外传 `from` / `language` / `market` / `platform` 等未定义字段
- 🚫 严禁 `destination` 或 `productInfo` 做逗号拼接（多值必须按需求拆解成多次 Step 1）
- 🚫 严禁把命令拆多行 / 加反斜杠续行 / 加 stdout 重定向
- 🚫 严禁同一需求内因返回慢就重发 Step 1 或申请新 `uniqueKey`（等待逻辑全部走 Step 2 轮询）

**需求映射表**：Step 1 拿到 `uniqueKey` 那一刻立即登记 `{序号 i, 品类词, 目的地, uniqueKey, 状态: pending, data: None}`。

**Step 2 轮询**（`prohibited_rule_interpretation_query`）：

- 入参：`{"uniqueKey": "<Step 1 返回值>"}`（顶层字段，🚫 **不套 `request` 外层**——套了会返 400）
- 节奏：每轮把所有 `pending` 需求各查一次 → 统一 `sleep 10` → 下一轮，累计 12 轮（≈120 秒）
- 反查：严格按返回中的 `uniqueKey` 反查映射表归属 `data`，🚫 不按顺序 / 时间戳 匹配

超时未完成 → 该需求 `failed`；其他需求继续。

**详细字段表 / 返回 schema / 并联伪代码 / RAG 切片合并去 overlap 详细步骤** → 读 `references/mcp-protocol.md`。

### 2.4 单需求内部数据处理

**MCP 返回的 RAG 切片必须做两步处理**：

**第一步 · 相关性过滤**：将用户 query（品类词 + 目的地）与 MCP 返回的每条切片做相关性判断，**移除与用户 query 无关的返回结果**。判断依据 —— 该切片的 `productCategoryWord` 与用户品类词字面语义相关、`destinationCountry` / `ruleContent` 与用户目的地属于同一地区或明确覆盖该品类。命中不相关就整条剔除，🚫 不放进后续合并与输出。

**第二步 · 切片去重合并**：

1. **按 `ruleId` 分组**：同 ruleId 的多条 `ruleContent` 切片归到一起
2. **顺序拼接 + 去 overlap**：相邻两段若末尾/开头 ≥ 30 字符重叠 → 保留前段尾、删除后段头
3. **🚨 完整保留合规关键细节，不精简**：合规要求、生效日期、参考法规号、认证有效期、客服电话、办理机构名、参考链接、屏蔽风险、上传字段名等**必须完整保留原文**。🚫 严禁为了"简短 / 通顺 / 好读"而砍掉这些细节，🚫 严禁把原文改写成更"干净"的总结，🚫 严禁自动合并"看上去相似"的两条不同规则条款。目标是**完整准确的规则解读**，宁可长一点也不丢关键信息
4. **每个 `ruleId` 只输出一次规则块**（合并后 1 条完整规则）

**其他单需求处理规则**：

1. **`destinationCountry` 差异标注**：需求目的地 vs MCP 返回国名（英文，如 Bahrain / Egypt）不完全一致 → 该规则子块顶部加行内标注 `⚠️ 非你查询的目的地,仅供参考`（大区如"东南亚"按"MCP 返回国名是否属于该大区"判断）
2. **`destinationCountry` 展示中文化 + 国旗 emoji**：MCP 返回的是**英文国名**（`Bahrain` / `Pakistan` / `Egypt` 等），内部比对 key 用英文，**输出给用户时必须译成中文 + 对应国旗 emoji**（Bahrain → 🇧🇭 巴林 / Pakistan → 🇵🇰 巴基斯坦 / Egypt → 🇪🇬 埃及 …）；🚫 严禁直接把英文国名裸露给用户
3. **按「平台管控 + 合规要求 + 查看规则」逐条分行展示**，🚫 不混排

### 2.5 管控类型判定 + 平台管控结论行（依 `ruleTitle`）

#### 管控标签映射

| `ruleTitle` 含 | 管控标签 |
|---|---|
| "禁售" | 【禁售】或【国别禁售】（依 `destinationCountry` 是否指定国家） |
| "限售" | 【限售】 |
| 同时含"禁售"+"限售" | 【禁限售】 |
| "合规须知" | 【合规须知】 |

`ruleTitle` 为空 → 管控标签填 `【具体请查阅相关规则】`，规则名称用合并后 `ruleContent` 首句概括（🚫 不得用数字 ID 当名称）。

#### 🚨 平台管控结论行（每个需求块必出，且必须加粗渲染为三级标题）

判定完管控标签后，**每个需求块（`done` 状态）都必须先输出一条固定格式的"平台管控结论行"**，作为该需求块最显眼的结论性文字。该行**必须**用 Markdown 三级标题 `###` 起头（渲染为加粗大字），🚫 严禁降级为普通段落 / 普通加粗 `**...**` / 引用块 `>`。

**固定句式**（`{X}` 替换为 §2.5 判定出的管控标签之一：禁售 / 国别禁售 / 限售 / 禁限售 / 合规须知 / 具体请查阅相关规则）：

```
### 平台管控：该商品是阿里国际站【{X}】商品
```

**位置**：

- 分支③ 国别限售 → 位于「合规要求列表」表格**之后**、「合规要求参考」段落**之前**
- 分支① 全平台禁售 / 分支② 国别禁售 → 位于该需求块顶部（未匹配提示框之后，禁售话术之前）
- 多需求场景 → 每个 `done` 需求块**各自输出一次**
- 兜底话术块（`empty` / `failed`）→ **不输出**平台管控结论行

**格式硬约束**：

- 必须以 `### ` 三级标题起头（Markdown 渲染为加粗），🚫 不用 `##` / `####`
- 冒号用**中文全角冒号 `：`**（🚫 不用英文 `:`）
- 管控标签外必须包**中文方括号 `【 】`**（🚫 不用 `[ ]` / 不用 `《 》`）
- 🚫 严禁改写措辞（不改成"该商品被平台判定为..."、"根据规则该商品属于..."等同义变体）
- 🚫 严禁省略这一行（旧版案例中所有 `done` 需求块都出，是本 skill 最核心的结论呈现，不可缺失）

### 2.6 未匹配国家规则提示（`isMatchCountryRule = "未匹配到国家规则"` 时必出）

在**对应需求块二级标题之后、规则子块之前**输出：

```
> ⚠️ **提示**：未查询到【{该需求目的地}】对【{该需求品类词}】的特定规则；以下为知识库中与该品类相关的国别规则，仅供参考。请结合实际销售目的地核对适用性。
```

- 单需求场景：即回答顶部
- 多需求场景：跟随每个命中的需求块内部输出一次；🚫 严禁写在整份回答顶部（跨需求误伤）
- 同需求部分匹配、部分未匹配 → 只对未匹配的规则子块顶部加行内 `⚠️ 非你查询的目的地,仅供参考`

### 2.7 三分支输出（详细骨架读 `references/output-templates.md`）

**三分支公共硬约束**：无论走哪个分支，该需求块（`done` 状态）都必须先按 §2.5 输出「平台管控结论行」`### 平台管控：该商品是阿里国际站【{X}】商品`，🚫 不可省略。**下方三个分支的固定话术均为原文照抄铁律**，🚫 严禁改写措辞、🚫 严禁简化、🚫 严禁凭 MCP 未返回的内容自造禁售/限售话术。

按 `ruleContent` 是否含国别屏蔽 / 资质描述三选一：

#### 分支① 全平台禁售（`ruleContent` 无国别屏蔽描述）

需求块顺序：平台管控结论行 → 固定禁售话术原文；🚫 不出合规要求列表、🚫 不出办理证书。

```
### 平台管控：该商品是阿里国际站【禁售】商品

该商品在阿里国际站被认定为【禁售】，请立即停止销售并下架相关链接；如有在途订单，请尽快取消并完成退款沟通，避免违反平台禁售政策，从而导致商品下架、账户处罚或其他风险。
```

#### 分支② 国别禁售（`ruleContent` 标注限定地区禁售）

需求块顺序：平台管控结论行 → 固定国别禁售话术原文（含从 `ruleContent` 提取的国家/地区名）；🚫 不出合规要求列表、🚫 不出办理证书。

```
### 平台管控：该商品是阿里国际站【国别禁售】商品

该商品在阿里国际站被认定为【国别禁售】，如您发布相关商品，平台将对产品执行【从 ruleContent 提取对应国家/地区】屏蔽。如有在途订单，请立即取消并联系买家退款，避免违反平台禁售政策，从而导致商品下架、账户处罚或其他风险。
```

#### 分支③ 国别限售（`ruleContent` 限定目的地需资质）

需求块顺序：合规要求列表表格（商品类目 / 销售目的地 / 所需资质 / 服务商） → 平台管控结论行 → `### 合规要求参考：` 段落 + 固定开头引导句 + 按四分组展开。

```
### 平台管控：该商品是阿里国际站【限售】商品

### 合规要求参考：
根据阿里巴巴国际站规则，{品类}销往{目的地}需满足以下合规要求：

1. **资质要求**：……（取自合并后 ruleContent）
2. **发品注意事项**：……
3. **商品包装要求**：……
4. **其他**：……
```

- 开头引导句 `根据阿里巴巴国际站规则，{品类}销往{目的地}需满足以下合规要求：` 为**固定句式**，🚫 严禁改写；`destination` 为空时改为 `根据阿里巴巴国际站规则，{品类}的全平台通用禁限售要求如下：`
- 四分组内容**只取自 `ruleContent` / `ruleTitle`**，无对应内容则该项省略，🚫 不杜撰

### 2.8 底部链接

- **[查看规则]（全场景必展示）**：
  - 单条：`**[查看规则]**：[规则标题](URL)`
  - 多条（≥2）：开头一行 `**[查看规则]**：`，其下**每条以 `- ` 起头**组成 Markdown 无序列表（`- 🏳 [规则标题](URL)`），🚫 严禁裸换行 / 并排 / 用 `·`/`•`/`▪` 替代 `- ` / 重复"[查看规则]："前缀
  - **格式细则（缺一不可）**：
    - 每条链接前**国旗 emoji 与链接文字之间保留 1 个空格**（如 `- 🇺🇸 [规则标题](URL)`）；无合适 emoji 时直接从 `[规则标题](URL)` 开始
    - `**[查看规则]**：` 一行结束后、第一个 `- ` 之前**不留空行**（Markdown 列表紧跟标题行更紧凑）
    - 相邻两条 `- ` 之间必须是**独立换行**，🚫 严禁把两条 `- ` 写在同一行
  - URL 优先用 MCP `ruleLink`；缺失时才用 `https://rulechannel.alibaba.com/icbu#/rule/search/{品类词}/all` 兜底
  - **文字里 🚫 严禁出现数字 `ruleId`**，ID 只藏在 URL 里
- **[办理证书]（仅限售场景）**：
  ```
  **[办理证书]**：您可联系 [平台合作服务商](https://onetouch.alibaba.com/moBasedata/luyou/home/act/epr-compliance-home/products?spm=a271c.finance20201215-1.0.0.28bf1394q2ZXGX) 办理相应资质证书；
  ```
  链接文字挂在"平台合作服务商"上、结尾中文分号 `；`；服务商 URL **固定**（不取自 MCP）；禁售/国别禁售场景不展示；🚫 该链接只是外部办证入口，🚫 不代表卖家中心证书上传路径
- **不再使用 [关联证书]**

所有链接必须是标准 Markdown 超链接 `[文字](URL)`（中括号紧挨圆括号），🚫 不得出现裸 URL 或「文字：(URL)」分离写法。

### 2.9 追问建议（品类存在细分差异时必出，位于 AI 声明之前）

**触发条件（任一）**：

1. 多小节交叉输出（如无人机 → 军用/民用/未区分用途）
2. `ruleContent` 明确出现"根据……型号 / 分类 / 用途 / 起飞重量 / 功率 / 电压 / 容量 / 认证等级 / 使用场景……不同"或"分为 X 类 / Y 级 / Z 型，管控要求不同"
3. 多规则命中不同子集（各自指向 `ruleTitle` / `ruleContent` 不同参数区间）
4. `ruleContent` 出现明确数值区间或阈值（`<250g / ≥250g`、`功率 ≤250W / >250W`、`IP 等级` / `电压范围` / `容量分档` 等）

**输出格式**（**普通段落**，🚫 不加小节标题 / 不用 `>` 引用块 / 不用列表结构，总长 ≤ 100 字，枚举 2-4 个）：

```
本次规则显示【**{品类}**】在 **{来自原文的细分维度枚举}** 等方面存在差异，建议您补充具体的**产品分类**、**型号**或**参数**，我可以为您匹配更贴合的规则条款。
```

**加粗铁律**：品类词加粗 `【**...**】` + 细分维度枚举整段加粗 `**...**` + 句尾候选补充方向词各自加粗（`**产品分类**` / `**型号**` / `**参数**` 至少 2 个）；其余保持普通字重。

**取值硬约束**：枚举必须来自 MCP 原文明确出现的分类术语，🚫 严禁列 MCP 未提及的分类 / 参数 / 维度；🚫 严禁把训练数据行业常识写进去。

**不触发**：单需求单一规则无细分差异 / 所有需求都是 `empty` / `failed` 兜底 / 用户已明确给出参数分类。

### 2.10 AI 生成声明（正常解读场景必出，位于整份回答最末尾且只出一次）

只要**至少 1 个需求走完正常解读（`done`）**，整份回答**末尾追加一次且只一次**：

```
> **AI生成声明：** 以上基于阿里巴巴国际站规则库解读，AI生成可能有误，请核实，实际判定结果以平台为准。
```

- 格式：Markdown 引用块（`>`）+ `**AI生成声明：**` 加粗 + **中文全角冒号 `：`**（🚫 不用英文 `:`）+ 冒号后 1 个空格再接正文
- 🚫 严禁改写措辞、🚫 严禁在每个需求块内部各追加一次
- 若所有需求都是 `empty` / `failed` 兜底 → **不追加**

**顺序铁律**：正文（需求块 / 兜底话术） → 追问建议段落（条件触发） → AI 生成声明。三者顺序不可颠倒。

### 2.11 输出骨架（详情读 `references/output-templates.md`）

- 单需求场景：不输出 `## 需求 1｜…` 顶部标题，直接从合规要求列表 / 兜底话术开始
- 多需求场景：按序号 1 → N 逐块输出，块间 `---` 分隔，每块二级标题 `## 需求 {i}｜{品类词} → {目的地}`；`destination` 为空时改用 `## 需求 {i}｜{品类词} → 全平台通用`
- 🚫 严禁跨需求合并 `data` 或跨块摘要

## 3. 硬约束（补充 §0 之外的必须/禁止清单）

- 品类文本原样传入 MCP，🚫 不加工、🚫 不归纳、🚫 不替换
- 每次 Step 1 只传单个 `destination` + 单个 `productInfo`；🚫 不传 `from` 字段
- 🚫 严禁在 destination / productInfo 里做逗号拼接
- 🚫 严禁只取多需求其中一个查询、忽略其余
- 🚫 严禁写 PowerShell `while` 循环 / stdout 重定向 / background process / 尝试多种编码
- 用户可见回答中🚫 严禁出现数字规则 ID（ID 只藏在 URL 内）
- 所有网页链接必须是 `[文字](URL)` 超链接，🚫 严禁裸 URL 或分离写法
- **命中特定品类清单**（当前：无人机、隔热膜）时优先执行对应 `references/hard-rules-*.md` 的**路由结构**（子小节划分、追问维度候选）；但**所有具体条款内容仍取自 MCP 原文**，🚫 严禁凭空补写警示 / 兜底套话。硬规则只影响**输出内容取舍与结构**，🚫 不修改 Step 1 入参（品类词仍按用户原文传入）

## 4. 异常与熔断（按需求单独判定，不终止全局）

**判定优先级**（按需求逐个判定）：MCP 调用失败 > `data` 为空 > 正常解析。互斥触发；某需求命中兜底不影响其他需求。

### A. MCP 接口失败 / Step 2 超时（该需求 `failed`）

某需求 Step 1 失败（`success=false` / `errorCode` 非空 / 超时 / Unknown tool / stdout 为空或非 JSON / 服务异常）或 Step 2 累计 120 秒仍未拿到 `data` 键 → **只对该需求所在块**输出：

```
⏱ 上游禁限售规则接口当前未返回有效结果。
请稍后重试您的查询;若多次重试仍失败,可前往商家后台咨询「小何在线」客服人员协助处理。
```

其他 `done` / `empty` 状态需求照常输出，🚫 严禁因单需求失败终止整轮回答。

### B. MCP 成功但 `data` 为空（该需求 `empty`）

某需求 `success=true` 但 `data:[]` 或 `null` → 知识库暂无该品类×目的地规则。**只在该需求所在块**输出：

```
经查询,知识库中暂未收录【{该需求品类词}】销往【{该需求目的地}】的相关禁限售规则。
建议您前往**商家后台**咨询「**小何在线**」客服人员,获取最新合规信息及人工解读。
> 友情提示:无规则记录不代表"无任何合规要求",出口前请核对目的国官方监管要求。
```

若该需求 `destination` 为空 → 话术改为"暂未收录【{品类}】的全平台通用禁限售规则"。

### C. 汇总规则（所有需求 `done` / `empty` / `failed` 后进入）

- 对齐铁律：严格按返回 `uniqueKey` 反查映射表归属 `data`，🚫 严禁跨需求"共用"或"合并" data、🚫 严禁按返回顺序/时间戳匹配
- 归属校验：`data[i].productCategoryWord` 与需求品类词字面语义相关 / `data[i].destinationCountry` 与需求目的地属于同一地区，才认为归属正确；否则按"未匹配"逻辑加提示框
- 输出顺序：按需求序号 1 → N 依次输出各需求块，块间 `---` 分隔
- AI 生成声明：**只要至少 1 个需求 `done`** → 整份回答末尾追加一次；全 `empty` / `failed` → 不追加
