# BI 数据分析提示词工程

将真实接口数据与提示词对齐，系统性加固计算准确性，使 DeepSeek-V3/V4-Pro 生成 BI 报告的数值准确率 ≥ 99%。

## 核心工作流

### Phase 1：接口数据解析

**目标**：建立「接口实际字段」的完整认知，不依赖设计文档。

```
1. 读取真实接口返回（JSON / CSV / txt pipe-separated）
2. 提取所有字段名、类型、值域范围
3. 识别：哪些字段可为负？哪些字段绝对值可>1？
4. 验证计算口径（如毛利率 = 毛利/营收 还是毛利/GMV，用反推法确认）
```

**反推口径示例**：
```python
implied_revenue = actual_gtm_gross_profit / actual_gtm_gross_profit_rate
revenue_ratio   = implied_revenue / actual_sales_amount
# 若 revenue_ratio ≈ 0.82~0.95 → 分母是营收
# 若 revenue_ratio ≈ 1.0 → 分母是GMV
```

---

### Phase 2：矛盾诊断（提示词 vs 接口）

**系统性对比**，找出以下四类矛盾：

| 矛盾类型 | 检查方法 |
|---|---|
| 字段名不匹配 | 逐一对照提示词引用字段 vs 接口实际字段名 |
| 提示词引用不存在的字段 | 列出提示词所有字段引用，核对接口是否返回 |
| 计算口径分歧 | 用真实数据验证公式（如毛利率分母） |
| 命名风格不一致 | camelCase vs snake_case，统一以接口为准 |

**输出**：字段映射表

```markdown
| 提示词引用 | 接口实际字段 | 状态 |
|---|---|---|
| gmv_actual | actual_sales_amount | ✅ 已对齐 |
| gross_margin | actual_gtm_gross_profit_rate | ✅ 已对齐 |
| revenue | 不存在 | ❌ 需删除或改为"数据不足" |
| yoy | 不存在 | ❌ 需删除 |
```

---

### Phase 3：边界场景枚举

**扫描真实数据，识别所有非正常值**：

```python
# 检查清单（用 Python 扫描）
for row in data:
    if row['actual_gtm_gross_profit_rate'] < 0:          # 毛利率为负
    if abs(row['actual_gtm_gross_profit_rate']) > 1:     # |rate| > 1
    if row['budget_gtm_gross_profit'] < 0:               # 预算为负
    if row['budget_sales_amount'] == 0:                  # 预算为零
    if row['actual_sales_amount'] / row['budget_sales_amount'] > 2:  # 超额200%
```

**每个边界场景必须对应一条明确处理规则**：

| 场景 | 规则 |
|---|---|
| `budget < 0` | 不输出达成率，标注"预算为负，不适用" |
| `budget = 0` | 不输出达成率，标注"预算为0，无法计算" |
| `rate < 0` | 标注 🚨，报告中保留负号 |
| `\|rate\| > 1` | 标注"极端异常，请核查" |
| 达成率 > 200% 且 budget < 100万 | 标注"预算基数极小，参考意义有限" |

---

### Phase 4：计算规则加固（CoT 模板）

**原则**：每条计算规则 = 步骤 + 正确示例（含中间过程）+ 禁止示例（Wrong/Right 对）

**模板**：
```markdown
### {指标名} 计算规则

**步骤：**
1. 检查前置条件（分母是否合法）
2. {公式，用字段名而非变量名}
3. 结果转换（单位、精度、符号）

**正确示例（逐步）：**
原始值：X
步骤1：X ÷ Y = Z
步骤2：Z × 100 = W
结果：W%  ✅

**禁止：**
- ❌ {错误做法1}（{错误原因}）
- ❌ {错误做法2}
```

**最高频错误防范（必须覆盖）**：

1. **pp 方向词矛盾**：pp 为负时，文字必须写"下降 X.XXpp"，禁止"提升 -X.XXpp"
2. **毛利率字段当变化量用**：`actual_gtm_gross_profit_rate` 是当期值，不是变化量，pp = 当月rate - 上月rate
3. **贡献分母用错**：分母必须是同维度同月所有行之和，禁止用 overall 整体值
4. **金额单位忘换算**：接口单位是元，展示必须转万/亿，忘乘100或忘除1e4是常见错误
5. **毛利率口径混用**：确认分母是营收还是GMV，不得用接口未提供的字段反算

---

### Phase 5：自我核查模板

在 SYSTEM PROMPT 中要求模型每个维度计算后执行核查：

```markdown
【自我核查（每维度必须执行）】
1. 贡献占比合计：{各行之和} = {值}%（是否≈100%？允许±0.2%浮点误差）
2. 量级校验：{整体指标}约{量级}（是否合理？）
3. 方向校验：当月{值} {>/< } 上月{值} → 应为{正/负}环比，与计算结果是否一致？
4. pp方向词：pp={值} {'>'if>0 else '<'} 0 → 文字应写"{'提升' if pp>0 else '下降'}"，是否一致？
5. 异常完整性：以下对象触发异常规则，是否全部出现在【异常项汇总】中？
```

---

### Phase 6：标准答案锚定

**对每个核心指标，用独立 Python 脚本计算标准值**，内置到提示词第八部分：

```markdown
## 标准答案（{数据月份}，用于核对）

> 模型输出后对照此节，误差超过 0.1% 视为计算错误。

| 指标 | 标准值 | 计算过程 |
|---|---|---|
| GMV达成率 | **102.7%** | 598,652,806.45 ÷ 582,682,855.73 = 1.0274 |
| GMV环比 | **-9.4%** | (598,652,806.45 - 660,904,506.21) ÷ 660,904,506.21 = -0.0942 |
...
```

---

### Phase 7：输出分割线设计

用 SYSTEM PROMPT 强制隔离推理过程与输出结果：

```
【区域一：计算过程】
逐步计算，每步写出原始值、公式、中间结果。
完成后执行自我核查。
此区域不进入最终报告。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

（最终报告从分割线后开始）
```

## DeepSeek-V3/V4-Pro 特性说明

| 特性 | 建议 |
|---|---|
| 支持 Thinking Mode | 数值计算任务开启，在 prompt 中强制 CoT |
| 对 Wrong/Right 负例对响应好 | 比单纯"不要XXX"更有效，每条规则都附禁止示例 |
| 长上下文末尾注意力下降 | 重要规则在提示词开头重复一遍（"任务三明治"） |
| 通用模型，非计算器 | 必须逐步计算+自我核查，不能直接给公式让模型跳步 |
| temperature=1.0 适合数据分析 | 官方推荐；Thinking Mode 开启时 temperature 无效，改为优化 prompt |

## 验证清单

提示词写完后，逐项核对：

- [ ] 所有字段引用已对照真实接口核实
- [ ] 接口不存在的字段已标注"数据不足，无法判断"
- [ ] 每条计算规则有正确示例 + 禁止示例
- [ ] 覆盖了全部边界场景（负值、零值、极端超额）
- [ ] pp 方向词规则明确（负pp→"下降"，不可写"提升-X"）
- [ ] 贡献分母规则明确（同维度之和，非整体GMV）
- [ ] 单位换算规则明确（万/亿临界值，精度位数）
- [ ] 内置了标准答案（用独立脚本验证过）
- [ ] SYSTEM PROMPT 包含分割线和自我核查要求
- [ ] 用 Python 脚本跑过全量数值核对，准确率 ≥ 99%
