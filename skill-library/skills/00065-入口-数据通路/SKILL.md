# Skill 1 · 入口 & 数据通路

> 职责：引导账号绑定 → 判断数据通路 → 收集基本信息 → 品类解析与行业类型打标
> 输出：上下文变量包，供 Skill 2-4 使用

---

## Phase 1 · 引导绑定 + 自动检测账号状态

### 执行步骤

**Step 1：先输出引导语**（输出后立即执行检测，无需等待用户回复）

> 您好！欢迎使用**行业全景分析专家**。
>
> 告诉我您的经营品类和入驻时长，我将为您生成一份完整的行业全景分析报告，涵盖以下六大维度：
>
> | 模块 | 内容 |
> |------|------|
> | 📊 **A · 市场规模** | 全球产值、产地分布、竞争格局、行业进入门槛 |
> | 📈 **B · 行业增长态势** | 24个月询盘趋势、淡旺季规律、飙升子类目 |
> | 🌍 **C · 买家市场分析** | Top买家国画像、各市场头部竞品品牌解析 |
> | 🛋️ **D · 热销产品分析** | 子类目热度与蓝海机会、价格带与MOQ分布 |
> | 🔭 **E · 前瞻趋势洞察** | 流行元素、节庆备货日历、C端热销信号 |
> | ✅ **F · 合规认证壁垒** | 目标市场认证要求、关税、ESG趋势 |
>
> 报告末尾还将结合您所处的经营阶段，输出**可落地的运营执行建议**。
>
> ---
>
> 在开始之前，建议先完成一个小步骤：
> 打开「国际站生意助手」插件，绑定您的国际站店铺账号。
>
> 绑定后可额外获得：国际站平台实时行业数据 + 您的店铺与同行均值/优秀值实时对比分析。
>
> 我将为您检测账号绑定情况，请稍候……

**Step 2：执行 MCP 检测（不等用户，紧接在引导语后立即调用）**

```bash
accio-mcp-cli call data_advisor_shop_summary --json '{"advisorQueryParam": {"statisticsType": "30d"}}'
```

### Step 3：根据返回结果输出检测结论并自动分流

**情况 A：返回 `success: true` 且有数据**
→ 标记 `ROUTE = A`，紧接引导语输出检测结论：

> ✅ 检测完成！已识别到您绑定的国际站店铺账号，欢迎进入**数据增强模式**。
>
> 本次报告将整合：
> - 国际站数据参谋实时行业数据（T-2）
> - Jungle Scout 跨平台竞品与亚马逊数据
> - 您的店铺数据与同行均值 / 优秀值实时对比
>
> 请告诉我您的经营品类和在国际站的经营时长，马上开始分析。

**情况 B：返回 `success: false` 或无数据或报错**
→ 暂不标记通路，先输出提示并等待用户选择：

> ℹ️ 检测完成。暂未检测到已绑定的国际站店铺账号。
>
> 绑定账号后，报告将额外包含：
> - 国际站平台实时行业数据（询盘趋势、买家分布、子类目热度等）
> - 您的店铺数据与同行均值 / 优秀值实时对比
>
> **建议您现在前往「国际站生意助手」插件完成店铺账号绑定**，绑定后重新发送消息即可进入数据增强模式。
>
> 如果暂时不方便绑定，也可以直接开始分析——报告将基于公开权威数据（Fortune Business Insights、Grand View Research 等）为您生成完整的六大模块报告。
>
> **请选择：**
> - 回复「已绑定」→ 重新检测，进入数据增强模式
> - 回复「直接分析」→ 基于公开数据立即开始

### 情况 B 用户选择处理

**用户回复「已绑定」**：
→ 重新执行 Step 2 MCP 检测
  - 检测成功 → 标记 `ROUTE = A`，输出情况A的欢迎语，继续 Phase 3
  - 检测仍失败 → 提示「暂未检测到绑定信息，可能需要稍等片刻或检查插件连接状态，您也可以选择直接分析」，再次等待用户选择

**用户回复「直接分析」或任何非「已绑定」的回复**：
→ 标记 `ROUTE = B`，输出：

> 好的，马上开始！报告将基于公开权威数据为您生成，每条数据均标注来源和时间。
>
> 请告诉我您的经营品类和在国际站的经营时长，马上开始分析。

## Phase 2 · 数据通路判断

根据 Phase 1 结果，设定全局通路标记：

| 状态 | 通路标记 | 数据获取方式 |
|------|----------|------------|
| 已绑定国际站店铺 | `ROUTE = A` | MCP 优先，MCP 无法覆盖时降级 web_search + 标明来源 |
| 未绑定 / 跳过 | `ROUTE = B` | 全程 web_search，优先调用行业权威数据源指引清单，标明来源 |

### 通路 A · MCP 降级规则

当 MCP 调用失败（返回 `success: false` 或超时）时：
1. 不重试，立即降级
2. 改用 web_search 获取对应数据
3. 在输出中标注：`（数据来源：[来源名称]，非平台实时数据）`
4. 继续执行，不中断报告流程

### 通路 B · web_search 来源优先级

执行 web_search 时，按以下优先级检索：

**第一优先：行业专属权威来源**（见附录：行业数据源索引）

**第二优先：通用来源**
- Google Trends（品类搜索热度）
- SimilarWeb（竞品网站流量）
- LinkedIn 行业洞察（B2B 采购趋势）
- 各国商务部 / 经济部公开统计数据

**输出规范**：每条数据必须标注来源名称及发布时间，格式：
`（来源：XXX，YYYY年MM月）`

## Phase 3 · 基本信息收集

### 收集内容

向用户提问，一次性收集以下两项信息：

**问题 1：您目前主营什么品类？**
> 请用自然语言描述，例如：「户外家具」「运动护具」「LED 灯具」「宠物零食」

**问题 2：您在阿里巴巴国际站上经营了多久？**
> 请选择最接近的阶段：
> - 0-30 天（智能破冰期）
> - 31-60 天（智控流量期）
> - 61-90 天（智赢商机期）
> - 91-120 天（智造爆款期）
> - 121-180 天（智赢交易期）
> - 180 天以上（进阶增长期）

### 存储变量

```
CATEGORY_INPUT = 用户输入的品类描述（原文保留）
OPERATION_STAGE = 用户选择的阶段标签
OPERATION_DAYS = 对应天数范围
LIFECYCLE = 新手期 / 成长期 / 稳定期
```

生命周期映射：
- 0-90 天 → `LIFECYCLE = 新手期`
- 91-180 天 → `LIFECYCLE = 成长期`
- 180 天以上 → `LIFECYCLE = 稳定期`

## Phase 4 · 品类解析 & 行业类型打标

### Step 4-1 · 获取 cateId

调用 MCP 工具将自然语言品类描述转为平台类目 ID：

```bash
accio-mcp-cli call data_advisor_category_infer --json '{"categoryDesc": "{{CATEGORY_INPUT}}"}'
```

- 成功 → 取返回的 `cateId`，存储为 `CATE_ID`
- 失败 → 尝试调用备用工具：

```bash
accio-mcp-cli call data_advisor_category_prediction --json '{"categoryParam": {"categoryDesc": "{{CATEGORY_INPUT}}"}}'
```

- 两次均失败 → 告知用户：「品类识别暂时遇到问题，将基于您描述的品类名称直接进行分析」，`CATE_ID = null`，继续执行

### Step 4-2 · 行业类型打标

根据 `CATEGORY_INPUT` 和 `CATE_ID` 对应的品类特征，从以下 7 种类型中进行多标签判断（可同时命中多个）：

| 类型标签 | 判断依据 | 典型品类 |
|----------|----------|----------|
| `时尚消费型` | 颜色/风格迭代快，审美驱动购买 | 服装、饰品、箱包、家纺、墙纸、节庆装饰 |
| `节庆周期型` | 需求高度依赖特定时间节点 | 圣诞装饰、礼品、玩具、婚庆用品、烟花 |
| `技术驱动型` | 新功能/新形态迭代替代旧品 | 消费电子、智能家居、新能源配件、无人机 |
| `工业采购型` | 理性采购为主，B端功能导向 | 机械设备、五金工具、工业原材料、建材、化工 |
| `成分功效型` | 成分/原料爆火驱动品类需求 | 美妆、护肤、保健品、功能性食品、宠物营养品 |
| `季节气候型` | 气候/季节强驱动，南北半球错位机会 | 户外用品、取暖/制冷设备、防晒/防水产品 |
| `赛事驱动型` | 大型赛事触发爆发式备货需求 | 运动装备、球类、应援产品、体育周边 |

**打标规则**：
- 一个品类可同时命中多个标签
- 优先选择最具体的标签（专属术语命中 > 完整覆盖 > 部分沾边）
- 存储为 `INDUSTRY_TAGS = ["标签1", "标签2", ...]`

### Step 4-3 · 输出判断结果，等待用户确认

向用户输出：

> 我已识别您的品类为：**[CATEGORY_INPUT]**
>
> 对应国际站类目：**[类目名称]**（ID: [CATE_ID]）
>
> 行业类型判断：**[INDUSTRY_TAGS]**
>
> 基于以上判断，接下来的分析报告将重点关注：[根据标签列出对应的核心分析维度]
>
> 如有偏差，请告知我，我会及时调整。确认无误后，我们开始生成报告。

### Step 4-4 · 处理用户纠错

- 用户确认 → 进入 Skill 2
- 用户纠正品类 → 重新执行 Step 4-1 和 4-2
- 用户纠正行业类型标签 → 直接更新 `INDUSTRY_TAGS`，进入 Skill 2

```
ROUTE            = A / B

```
