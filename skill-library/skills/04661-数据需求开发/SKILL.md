# 数据需求开发

根据业务需求生成 ODPS SQL 代码和 DataWorks 节点配置。覆盖从需求理解到代码生成的完整链路。

## 模式路由

收到用户需求后，先判断属于哪种模式：

| 模式 | 触发条件 | 输入 |
|------|---------|------|
| **有模板** | 用户提供了样例 SQL 或现有代码，要求基于模板修改/扩展 | 样例 SQL + 新需求描述 |
| **无模板** | 用户只描述需求，没有现成代码参考 | 表清单 + 需求描述 |

## 有模板模式

### 执行流程

1. **理解样例**：分析用户提供的样例 SQL，提取以下信息：
   - 涉及的表和字段
   - JOIN 关系和条件
   - 聚合逻辑（GROUP BY、窗口函数等）
   - 过滤条件（WHERE、分区限定）
   - 输出字段和格式

2. **理解新需求**：明确用户想要修改或扩展的内容：
   - 新增/删除字段
   - 修改过滤条件
   - 修改聚合维度
   - 新增数据源

3. **生成代码**：基于样例结构，生成新的 ODPS SQL：
   - 保持原代码的风格和命名规范
   - 遵循 [ODPS SQL 编码规范](references/odps-sql-codestyle.md)
   - 确保分区限定完整（`ds = '${bizdate}'` 等）
   - 包含必要的 SET 语句（如 `SET odps.sql.decimal.odps2 = true`）

4. **输出节点配置**：如需创建 DataWorks 节点，生成对应的 spec：
   - 节点类型：ODPS_SQL
   - 调度配置：根据业务需求确定周期（日/小时）
   - 依赖：基于输入表自动推导上游依赖
   - 资源组：使用项目默认资源组（或用户指定）

### 输出格式

```markdown
## 需求理解

{对新需求的简要总结}

## 生成代码

```sql
{完整的 ODPS SQL 代码}
```

## 节点配置建议

- 节点名称: {建议的节点名}
- 调度周期: {日/小时}
- 上游依赖: {依赖的表/节点}
- 资源组: {资源组}
```

## 无模板模式

### 执行流程

1. **需求澄清**：如果用户提供的需求不够明确，追问以下信息：
   - 涉及的表有哪些？（表名或业务描述）
   - 需要什么粒度的数据？（明细/汇总）
   - 时间范围？（T+1 增量/全量历史）
   - 输出格式？（表结构要求）
   - 是否有特殊业务规则？（去重、关联、过滤等）

2. **表发现**：使用 dataworks skill 的搜表能力定位相关表：
   - `search_table.py --topic <主题词>`
   - `identify.py "表名关键字"`
   - `query_columns.py "表名"` 查看字段结构

3. **SQL 生成**：基于发现的表结构和需求，生成 ODPS SQL：
   - 优先使用 JOIN 而非子查询（性能考虑）
   - 所有表必须加分区限定
   - 日期处理使用标准函数（`TO_CHAR`、`DATEADD` 等）
   - 聚合场景考虑数据倾斜（GROUP BY 字段选择）

4. **验证建议**：生成后给出验证建议：
   - 如何抽样验证数据正确性
   - 常见的数据质量问题检查点
   - 性能预估（数据量、JOIN 复杂度）

### 输出格式

```markdown
## 需求理解

{对需求的结构化总结}

## 涉及的表

| 表名 | 用途 | 关键字段 |
|------|------|----------|
| {表名} | {用途} | {字段} |

## 生成代码

```sql
{完整的 ODPS SQL 代码}
```

## 验证建议

- 抽样检查: {建议的验证 SQL}
- 数据质量: {常见问题和检查方法}
- 性能注意: {性能风险点}
```

## 通用规范

### SQL 风格

- 关键字大写：`SELECT`、`FROM`、`WHERE`、`JOIN`
- 表名/字段名保持原样（不强制小写）
- 缩进使用 4 个空格
- 复杂查询每行一个主要子句

### 分区限定规则

- 所有表访问必须有分区过滤
- 日调度任务：`ds = '${bizdate}'`
- 小时调度任务：`ds = '${bizdate}' AND hh = '${hh}'`
- 历史全量：`ds <= '${bizdate}'`

### 命名建议

- 节点名：`{biz_domain}_{data_layer}_{table_name}`
- 临时表：`tmp_{creator}_{bizdate}_{seq}`
- 输出表：`{dwd|dws|ads}_{domain}_{entity}_{granularity}`

## 与外部 Skill 的协作

- **dataworks-datastudio**：节点创建、工作流配置、发布上线
- **dataworks**：表结构查询、字段发现、血缘分析
- **odps-sql-codestyle**：SQL 编码规范校验（如环境中有此 skill）
