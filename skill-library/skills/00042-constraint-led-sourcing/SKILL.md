# Constraint-led sourcing

Turn the request into a constraint ledger before retrieval:
- object: product vs supplier, platform/country, exact required count;
- mandatory properties, optional preferences, explicitly excluded properties;
- evidence needed for each property;
- previously returned product and supplier IDs, and whether "more" means new products or new factories.

A requirement is pass / fail / unverified. Only candidates passing all mandatory properties count as verified matches. Put incomplete leads in a separate section, never pad a requested count with near matches.
"Own factory", "mature sample available" and "customization" are distinct properties; a reseller's product photo does not verify any of them.
If the user changes a reference product, update only the changed properties. A new visual reference does not silently relax a chemical, material or manufacturing constraint. If the new request conflicts, clarify the precise conflict.
For more factories, deduplicate by supplier identity across turns, not just URL. Report newly verified suppliers separately from old ones and distributor reference products.

Discover and inspect available search/detail/image tools; use the named platform. No invented endpoints, no promises of suppliers' capabilities. Public business contact links are acceptable; never invent private buyer contacts.
Return requested count, verified count and candidate rows with product/supplier identity, price currency/basis, MOQ, required property verdicts, source URL, image source if requested, and next verification.
Preserve uncertain values, units and trade terms. Do not call an empty search market absence.
For unavailable sourcing, deliver partial verified rows and exact missing properties. Prepare inquiry drafts only; do not send inquiries or publish products.
If the named platform cannot be searched or supplier detail is inaccessible, keep that platform as the target. State whether the gap is candidate access, a required factory property, or commercial terms; do not substitute Amazon listings as verified 1688 suppliers. Ask for candidate links or a platform export with supplier identity and the missing fields, and explain which checks can then be performed. If links still cannot be opened, request the relevant page text/export rather than promising link access. Public alternative-source leads may be shown separately where useful, with their source and unverified properties, but do not count them toward a platform-specific verified shortlist. If there are no verified matches, return zero verified matches plus the exact next verification, not a claim that no such factories exist.
Do not end a numbered shortlist request with only a broad supplier-search card and a suggestion to compare it later. Inspect returned candidate details and produce the requested per-candidate constraint assessment in this turn. Broadening retrieval is allowed to discover leads, but does not relax acceptance criteria: keep non-matching or unverified leads separate from qualified results, and state the qualified count (including zero). If a tool exposes only an opaque card without inspectable candidate evidence, say that this tool cannot substantiate the shortlist; do not call the card a completed shortlist. Supplement through available public sources where feasible without inventing private supplier facts.

If still incomplete, follow the shared response contract: offer multiple feasible choices with Agent-led candidate/property research or a narrower comparison first, optional user links/exports last. Do not end solely with an input request. Put the actual consulted platform/page beside each supplier claim; an unverified factory/sample property stays unverified even when a product link exists.
