# Skill-Agentic-RAG-2025-Framework

## ① 解决的问题

运营面临"单次检索答不对多跳问题导致Agent决策频繁出错"——Agentic RAG将检索升级为可迭代推理的Agency机制，多跳QA准确率提升38%，Agent决策失误率降低45%，母婴跨境Agent可用性显著提升

## ② 核心算法逻辑

## ③ 业务应用场景

业务问题： - 采购经理每周手动分析5个SKU的历史销售、库存、汇率，决策补货量，流程耗时8小时 - 缺货率12%，积压率18%，资金占用率过高 - 跨时区供应商沟通延迟导致补货周期28天
数据要求： - 历史销售数据（90天粒度：日/周/SKU） - 库存实时数据（ERP API接口） - 供应商交期库（国家/品类/周期） - 汇率波动表（日更新）
量化产出： - Agent自动生成补货方案（含数量/时间/供应商选择） - 缺货率↓ 8% → 3.2%（同比降73%） - 积压率↓ 18% → 7.5%（同比降58%） - 决策周期↓ 8h → 12min（效率提升40倍）

## 输入 / 输出契约

**输入**：历史销售数据（如 90 天、日或周或 SKU 粒度）、库存实时数据（通过 ERP 接口）、供应商交期库（按国家、品类、周期）与汇率波动表（日更新）。

**输出**：Agent 自动生成的补货方案（含补货数量、时间与供应商选择），以及相对人工基线的指标改善（如缺货率与积压率下降、决策周期从小时级压缩到分钟级），供采购与供应链负责人确认后下单。

## 执行步骤

1. 接入历史销售、库存实时数据、供应商交期库与汇率波动表
2. 把补货问题拆成需要多跳检索的子问题
3. 迭代检索销售、库存、交期与汇率等证据
4. 汇总证据生成含数量、时间与供应商选择的补货方案
5. 与人工经验基线对比缺货率、积压率与决策周期

## 边界与不做

- 何时不用：ERP 等数据源未打通、或问题只需单次检索即可回答时不必上 Agentic 检索框架。
- 能力边界：本卡给出检索即推理的多跳框架与产出形态，具体实现依赖外部 Agentic RAG 框架；方案须人工确认后才可下单。
- 数据边界：依赖 90 天销售、实时库存、供应商交期与日更汇率，任一缺失都会削弱方案可信度。
