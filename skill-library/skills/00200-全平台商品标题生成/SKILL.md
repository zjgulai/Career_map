# 全平台商品标题生成

根据商家提供的商品素材，生成符合目标平台规则的高质量商品标题。支持 11 个电商平台，默认生成 3 条差异化标题供商家选择。

---

## 文档地图（Document Map）

Agent 根据识别到的目标平台**按需加载**对应的 reference 文件。

| 文档 | 用途 | 何时加载 |
|------|------|----------|
| [references/alibaba-international.md](references/alibaba-international.md) | 国际站标题/卖点生成详细规则 | 目标平台为国际站（默认）时 |
| [references/platform-rules.md](references/platform-rules.md) | 其他平台标题规则合集 | 目标平台为淘天/1688/Amazon/AE/LAZADA/京东/Shopee/TikTok/Shein/Shopify 时 |

## 核心流程

### Step 1：输入校验

#### 必填项检查

商品素材至少满足以下**一项**才能生成。**商品图片是最优素材**：图片能提供外观、材质、结构等文本无法完整传达的信息，生成的标题更准确，应始终鼓励商家提供图片。

| 素材类型 | 判定标准 |
|---------|---------|
| 商品图片（推荐） | 用户上传图片 / 提供图片链接 |
| 足够明确的文本素材 | 包含产品中心词（如"wpc wall panel"、"南非醉茄贴"），可附带属性/规格/关键词 |

**素材不足时的处理：**
- 仅有泛词（如"帮我写标题"、"生成一个发品标题"，无任何商品信息）→ 追问："为了生成标题更加精准，建议上传商品图片（也可以提供商品名称/描述）"
- 仅有文本素材（无图片）→ 正常生成，但需在生成背景说明中自然提醒商家："本次基于文字描述生成，上传商品图片可以让标题更贴合实际商品、更精准"
- 有图片 → 正常生成，以图片为最高优先级输入源

#### 非必填项收集（从 query 中提取，不追问）

- 具体要求：生成条数、字数限制
- 目标平台
- 属性、卖点、关键词、详情
- 目标市场/人群
- 同款簇信息

**注意**：非必填项缺失时不追问，直接基于已有素材生成。

---

### Step 2：意图识别

#### 2.1 识别目标平台

从 query 中识别目标平台关键词：

| 平台关键词 | 路由目标 |
|-----------|---------|
| 国际站、Alibaba、alibaba.com、ICBU | → 国际站规则 |
| 淘宝、淘天、天猫 | → 淘天规则 |
| 1688、阿里巴巴（中文站） | → 1688规则 |
| 亚马逊、Amazon | → Amazon规则 |
| 速卖通、AE、AliExpress | → AE规则 |
| LAZADA、来赞达 | → LAZADA规则 |
| 京东、JD | → 京东规则 |
| Shopee、虾皮 | → Shopee规则 |
| TikTok、TikTok Shop | → TikTok规则 |
| Shein、希音 | → Shein规则 |
| Shopify | → Shopify规则 |
| **未点明任何平台** | → **默认国际站规则** |

**来源平台 vs 目标平台区分规则：**
- "基于1688的标题帮我生成国际站标题" → 1688是来源，国际站是目标
- "把这个Amazon链接的标题改成国际站格式" → Amazon是来源，国际站是目标
- "搬品"、"搬家"、"迁移" 语境中的平台为来源平台
- 若只提到一个平台且是"生成/写标题"语境 → 该平台为目标平台

#### 2.2 识别具体要求

| 要求类型 | 识别规则 | 默认值 |
|---------|---------|--------|
| 生成条数 | 商家提及具体数字（如"生成20个"、"写5条"） | 默认 3 条 |
| 字数限制 | 商家明确提及（如"不超过120字"、"90-100字符"） | 按目标平台规则 |
| 全套方案 | 商家提及"标题+卖点"、"标题+关键词+卖点"（仅限国际站） | 标题3条 + 卖点1条 |
| 目标市场/人群 | 如"东南亚"、"法语买家"、"美国市场" | 不限定 |
| 关键词/SEO | 商家指定核心词或要求覆盖热搜词 | 从素材中提取 |

### Step 3：规则注入生成

#### 3.1 优先级原则

```
商家 query 显式诉求 > 平台默认规则
```

- **字数/字符约束**：商家诉求优先，但不得高于平台规则上限
- **条数约束**：商家诉求优先
- **关键词/SEO**：商家指定词优先覆盖
- **目标市场/人群/风格**：商家诉求优先
- **无具体要求**：走目标平台默认规则

#### 3.2 加载平台规则

- 目标平台为国际站 → 读取 [references/alibaba-international.md](references/alibaba-international.md)
- 目标平台为其他 → 读取 [references/platform-rules.md](references/platform-rules.md) 中对应平台章节

#### 3.3 输入源优先级

```
商品本身信息（图片、属性、卖点、关键词、详情等） > 同款簇数据 > 图搜数据
```

#### 3.4 差异化生成策略

当生成多条标题时（默认3条），按以下策略差异化，展示优先级自上而下：

| 策略类型 | 侧重点 |
|---------|--------|
| **SEO 关键词型**（推荐） | 买家热搜/搜索核心词最大化曝光，抢主流量 |
| **场景人群型** | application/使用场景/目标人群/目标市场 |
| **卖点差异型** | 视觉卖点/独特优势/差异化亮点，突出竞争力 |
| **长尾组合型** | 长尾关键词+修饰词组合，覆盖细分/低竞争度流量 |
| **属性规格型** | 型号/规格/核心属性差异化，利于精准匹配与筛选 |

**默认3条时**：取前3种策略（SEO关键词型 + 场景人群型 + 卖点差异型）。
**商家要求更多条数时**：按优先级循环使用5种策略。

#### 3.5 差异化约束

- **去重**：任意两条不得核心词组合与前置侧重雷同；同一关键词不得在多条中以同一句式复用，重复率不得超过 60%
- **一致性**：所有生成内容均需与图片/属性/事实一致，硬事实不得改写
- **标签**：每条标题附方向标签（如「SEO 关键词型」），便于商家理解差异并选择
- **字符数硬约束（最高优先级）**：每条标题严格不超过目标平台字符上限（含空格）。各平台上限：国际站≤128、AE≤128、Amazon≤75、Shopee≤120、淘天≤60字符（30汉字）、1688≤60字符（30汉字）、京东≤60、TikTok≤200、Shein建议60-100、Shopify≤255。若商家指定了更短的字数限制，以商家要求为准。生成时预留安全余量，不要顶着上限写；超长时按"场景词 → 修饰词 → 变体词"顺序从末尾削减，保留核心产品词和关键属性词完整。最终以 Step 4 的命令行实测为准

---

### Step 4：质量检查

生成标题后、输出前，过一遍以下 checklist。发现问题**直接修正**，不重新生成，最多 1 轮（字符数校验除外，见 4.1，必须修剪至合规才能输出）。

#### 4.1 通用检查（所有平台）

| 检查项 | 规则 | 修正方式 |
|--------|------|---------|
| 条间重复度 | 任意两条核心词重复率 > 60% | 替换重复词为同义词/调整词序结构 |
| **字符数合规（必须用命令实测）** | 禁止心算估计。对每条标题执行命令实测字符数（含空格），超出平台硬上限（具体值见 3.5 字符数硬约束，商家指定更短限制时以商家为准）即不合规 | 按"场景词→修饰词→变体词"从末尾削减后**重新实测**，直至全部合规才能输出 |
| 事实一致性 | 标题内容与图片/属性明显矛盾（如材质、规格不符） | 删除无依据的描述，替换为输入源中的真实信息 |
| 格式规范 | 大小写、介词位置、特殊符号不符平台要求 | 直接修正格式 |
| 平台禁用词 | 命中目标平台的禁止用词（如淘天的绝对化用词、Amazon的夸大词等） | 删除禁用词 |

**字符数实测方法**（跨平台，Windows/macOS 通用）：

1. 将待校验的标题逐行写入临时文件（如 `titles.txt`，每行一条）
2. 用 node 实测每条的字符数：

```bash
node -e "require('fs').readFileSync(process.argv[1],'utf8').split(/\r?\n/).filter(Boolean).forEach(t=>console.log(t.length+'\t'+t))" titles.txt
```

- 输出第一列即字符数（含空格），中英文均按字符计数，逐条对照平台硬上限判断
- 禁止使用 `wc`、heredoc 等仅限 Unix 的写法，避免 Windows 环境失败

#### 4.2 国际站额外检查

若目标平台为国际站，在通用检查基础上**额外执行敏感词静态校验**，命中则删除：

- top, best, hot selling, only, unique, perfect, Exclusive
- 联系方式（电话、微信、whatsapp、telegram、网址）
- 色情/违规词
- 疑似品牌词：非用户明确提供的品牌名（如标题中出现知名品牌 Samsung、Nike 等而用户素材未提及）→ 删除，用产品属性词/场景词补位

### Step 5：格式化输出

输出标题方案前，用 1-2 句话简要说明生成背景（识别到什么商品、走的哪个平台规则），语气自然，不要套模板。若质量检查有修正则顺带提一句，全部通过则不必刻意说明。

#### 标准输出格式（多条标题）

输出时确保标题内容在视觉上最突出（比如加粗等方式），推荐理由作为辅助说明弱化展示，整体要协调有美感。核心原则：标题 > 标签 > 推荐理由。

```
方案A（推荐）：SEO 关键词型
{标题内容}
推荐理由：{简要说明为什么推荐，关键词选择逻辑}

方案B：场景人群型
{标题内容}
推荐理由：{简要说明场景/人群定位逻辑}

方案C：卖点差异型
{标题内容}
推荐理由：{简要说明卖点差异化逻辑}
```

#### 全套方案输出格式（标题+卖点，仅国际站）

```
## 标题方案

方案A（推荐）：SEO 关键词型
{标题内容}
推荐理由：xxx

方案B：场景人群型
{标题内容}
推荐理由：xxx

方案C：卖点差异型
{标题内容}
推荐理由：xxx

## 卖点

{卖点1简述}: {详细内容}
{卖点2简述}: {详细内容}
{卖点3简述}: {详细内容}
```

#### 单条输出格式（商家只要1条时）

```
{标题内容}

推荐理由：{简要说明}
```

## 边界与约束

### 与"标题优化"的区分

| 场景 | 路由 |
|------|------|
| 用户有具体商品ID + "优化/提分/改标题" | → alibaba-product-optimization |
| 用户无商品ID + "生成/写/起标题" | → 本 Skill |
| 用户提供商品链接 + "参考这个生成标题" | → 本 Skill（不解析链接内容，引导用户提供图片或粘贴商品名称/描述） |
| 用户提供商品链接 + "优化这个标题" | → alibaba-product-optimization |

### 不做的事

- 不自动发布商品（生成标题后由商家决定是否使用）
- 不调用工具查询商品数据（当前版本不解析商品链接/商品ID，链接场景引导用户提供图片或文字素材）
- 不生成非标题内容（除非商家明确要求全套方案）
- 不追问非必填信息（仅当图片和文本素材全部缺失时追问一次，其他信息有多少用多少）
- **不读取 Memory / 历史对话中的商品信息**：每次标题生成只基于当前对话中用户提供的素材（图片、文字描述、链接），禁止从 Memory 或历史上下文中提取其他商品的属性、标题、类目等信息混入本次生成，避免串品
