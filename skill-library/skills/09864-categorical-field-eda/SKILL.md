# Categorical Field EDA

## 单一职责

本 Skill 只负责对分类型字段进行业务导向的探索性数据分析，并输出：

- 字段质量判断
- 类别分布洞察
- 稀有类与异常类识别
- 与目标变量或业务结果的关系分析
- 字段处理建议
- 可转化为业务动作的解释

本 Skill 不负责：

- 连续变量 EDA
- 整体数据集自动化 EDA
- 建模训练
- 因果推断
- 最终商业策略拍板
- 文本原始清洗本身

## 使用边界

适用于以下字段：

- 名义型变量：国家、平台、声量来源、情绪标签、诉求主题、产品品类、达人类型
- 序数型变量：风险等级、满意度等级、问题严重程度、用户生命周期阶段
- 布尔型变量：是否投诉、是否提及物流、是否提及过敏、是否包含购买意图

不建议直接套用于以下字段：

- 高基数 ID：post_id、comment_id、user_id、sku_id、campaign_id
- 未结构化自由文本：评论原文、帖子正文、私信全文
- 本应是连续变量但被粗暴离散化且无业务定义的字段

## 核心方法论

分类型 EDA 的目标不是“做频数统计”，而是回答五个问题：

1. 这个字段真实吗？
2. 这个字段稳定吗？
3. 这个字段的类别结构合理吗？
4. 这个字段与业务结果或目标变量有关吗？
5. 这个字段后续该如何处理、如何进入业务决策？

在任何统计动作之前，先做字段语义审计。  
不要把少数类自动视为异常，也不要把 unknown 自动视为噪声。  
在 VOC 和社媒聆听数据中，低频类别、模糊标签、unknown、other 往往恰恰对应高风险议题、边缘市场信号或分类体系缺陷。

## 适用于 VOC / 社媒聆听数据时的额外原则

对于母婴出海 VOC 场景，分类字段的价值常体现在以下方面：

- 平台差异：TikTok、Instagram、Amazon、Reddit、Facebook Group 的用户表达方式不同
- 国家差异：同一问题在不同国家可能对应不同监管、文化和购买偏好
- 育儿阶段差异：pregnancy、newborn、infant、toddler 的诉求结构完全不同
- 议题敏感性：过敏、成分安全、物流破损、售后态度等低频词类不能机械并入 other
- 情绪与风险并不等价：负面情绪高不等于业务影响最大，要结合议题类型、传播平台与扩散潜力判断

## 标准工作流

### 第一步：字段语义审计

先确认：

- 字段业务定义是什么
- 是名义型、序数型还是布尔型
- 理论上应有哪些取值
- 是否存在映射表、标签字典或分类标准
- 是否可能混入非法值、测试值、系统默认值、模型误分类结果

在 VOC 场景中还要额外确认：

- 该字段是人工标注、规则抽取还是模型分类生成
- 字段取值是否会随着标签体系迭代而变化
- 不同平台、语言、国家是否采用了同一口径

### 第二步：质量检查

至少检查以下指标：

- 缺失率
- unknown / other / unclassified 占比
- 去重后类别数
- top1 类别占比
- 稀有类别数
- 是否存在单一类别或近单一类别
- 是否存在平台或国家造成的结构性缺失

### 第三步：单变量分布分析

输出：

- 每个类别的样本数与占比
- Top 类别及累计占比
- 长尾结构
- 类别口径污染
- 是否存在业务上不合理的取值
- 是否存在跨语言映射不统一

### 第四步：业务异常与稀有类判断

区分以下几类情况：

- 非法值：乱码、空格值、测试值、错误标签
- 口径污染：同义标签拆成多个值
- 真正稀有但重要的类别
- 无业务意义的低频长尾类别
- 分类器置信度不足导致的伪稀有类

这一阶段必须结合业务，而不是只根据频数做判断。

### 第五步：与目标变量或业务结果关系分析

如果存在目标变量或业务结果，检查：

- 各类别对应的目标率 / 风险率 / 转化率 / 复购率 / 升级率 / 退款率
- 相对整体均值的 lift
- 样本量是否足够
- 差异是否稳定
- 差异是否具备业务意义

若适用，可使用：

- 列联表
- 卡方检验
- Cramér's V
- 类别目标率对比
- 分国家 / 分平台 / 分阶段的分层分析

### 第六步：输出处理建议

对每个字段至少给出一类结论：

- 保留原样
- 统一映射
- 合并长尾
- 保留稀有类并单独标记
- 单独设置 Missing / Unknown 类
- 作为描述变量保留但不入模
- 删除
- 采用特定编码方式处理
- 要求重新定义标签体系

## 工作原则

- 字段语义优先于统计描述
- 业务含义优先于机械规则
- 少数类不等于异常类
- unknown 不一定是脏数据，也可能是关键行为信号
- VOC 标签要考虑生成机制，不可把分类结果当作绝对真值
- 输出必须包含决策建议，而不只是图表说明

## 交付要求

输出结果时，必须覆盖以下部分：

1. 字段定义与适用性判断
2. 数据质量检查结果
3. 类别分布与长尾结构
4. 稀有类 / 异常类解释
5. 与目标变量或业务结果关系
6. 字段处理建议
7. 对业务或内容团队可执行的启发

不要只输出 `value_counts()` 风格的描述。  
不要只给“建议画柱状图”这类浅层建议。  
必须把分析结论翻译成业务上能消费的语言。
