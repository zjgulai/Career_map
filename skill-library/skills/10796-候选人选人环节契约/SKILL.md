# KOL Hunter · 候选人选人环节契约

本技能是**产品局部技能（L2）**，随 `KOL-Hunter` 产品打包，只在挂载该产品处可见。它不重复岗位方法（那是 L1 `p2s-kol-creator-matching` 的职责），只钉死**本产品的口径、字段与分级**——即「同一条提示词里，岗位技能负责怎么想，本技能负责产出什么形状」。

## ① 本环节要什么

输入是人在预设 UI 里填的选人三件套，输出是一份**可直接拿去谈**的候选名单。判据只有一条：**名单上每一行都必须能回答「为什么是它、为什么不是隔壁那个」**。

## ② 六维口径（本产品唯一事实之家）

分值 0–100，加权求和得总分。权重只写在这里，提示词拼装与打分工具都从这里读——改口径只改这一处。

| 维度 | 权重 | 取值来源 | 说明 |
| --- | --- | --- | --- |
| 受众匹配 `audience` | 0.25 | `market` 命中、`category` 与品类相关、`fanActiveRate` | 市场不对，后面全白算 |
| 内容相关 `relevance` | 0.15 | `category` 与 `contentScore` | 能不能把这个产品讲明白 |
| 互动质量 `engagement` | 0.15 | `interactRate`、`hitVideoCnt` | 真实互动而非粉丝数 |
| 转化能力 `conversion` | 0.25 | `roi365d`、`orderCnt365d`、`salesScore` | 带货的真本事 |
| 品牌安全 `safety` | 0.10 | `refundRate`（低者优） | 退款率高 = 口碑风险 |
| 性价比 `value` | 0.10 | `projectCostUsd` 对 `{{budget}}`、`gmv365d / projectCostUsd` | 预算内每美元买到多少产出 |

## ③ 分级阈值（总分）

| 分级 | 阈值 | 含义 |
| --- | --- | --- |
| **主推** `primary` | 总分 ≥ 75 且 `budgetFit` 为真 | 值得单独开一轮谈判 |
| **测试** `test` | 60 ≤ 总分 < 75 且 `budgetFit` 为真 | 小预算试一条内容再决定 |
| **排除** `exclude` | 总分 < 60 或 `budgetFit` 为假 | 写清排除理由，避免下一轮重复捞人 |

**预算硬约束**：`projectCostUsd > {{budget}}` 一律 `exclude`，无论总分多高。理由要写明是「超预算」还是「不匹配」，两者不得混为一谈。

**分级只能降不能升**：阈值判出的分级是算术结果，由工具给出。你可以**降级**（例如发现品牌安全或合规风险），且必须写明降级理由；**不得升级**。这条由 `run.mjs` 机检——升级会直接判契约违规。

## ④ 预估 ROI 折减

预估 ROI **不得**直接抄 `roi365d`——那是别人家产品的历史成绩。本产品的规则：

```
预估 ROI = roi365d × (0.5 + 0.5 × audience/100) × (0.7 + 0.3 × relevance/100)
```

即：受众越不匹配、品类越不相关，历史 ROI 打折越狠。折减后的值必须四舍五入到一位小数，并在理由里给出折减前原值，让人看得见打了多少折。

## ⑤ 输出契约

只输出符合 `schemas/candidate-list.json` 的 JSON。字段名、枚举值以 schema 为准，**不要自创字段**，不要输出解释性前后文。每行候选必须带：六维分、总分、分级、预估 ROI、一句话理由、下一步动作。

## ⑥ 变量（由预设 UI 采集）

| 占位 | 来源 | 缺省行为 |
| --- | --- | --- |
| `{{product}}` | 输入字段 `product` | 必填，缺则拼装报错 |
| `{{market}}` | 输入字段 `market` | 必填，缺则拼装报错 |
| `{{budget}}` | 输入字段 `budget` | 必填，缺则拼装报错 |

## ⑦ 边界

- 不替人做最终决定：本环节只到「主推 / 测试 / 排除」，签约与报价谈判是人的事。
- 不编造池外达人：名单只能来自本次提示词里给出的候选人池事实；池子不够就说不够。
- 不做合规裁决：广告标识与平台规则由 L1 `p2s-kol-creator-matching` 的三轨验证覆盖。
