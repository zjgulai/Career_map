    - 与定招/草稿无关的通用生图诉求 → 走通用图片能力

# 定招主题查询与发品(Collect Topic Search & Listing)

> 定招(Collect Topic)是 Alibaba.com 平台向商家征集优质商品的机制。商家发布符合主题要求的商品即成为"定招品"，获得更多流量曝光。又称"行业定向征品"。English: High-demand products (HDP)。

---

## 1. 意图识别与链路路由

收到用户问题后，**先判意图再调工具**。

| 意图 | 判定条件 | 执行链路 |
|---|---|---|
| **查询**（推荐/搜索/筛选/翻页） | 无发品动词；含关键词/类目/tab/翻页语境 | → [`references/topic-query.md`](references/topic-query.md) |
| **发品** | 含"发品/发布/上架/listing"+ topicId 或指代查询结果 | → [`references/topic-listing.md`](references/topic-listing.md) |
| **图片生成（套图/单图）** | ① 草稿完成后的套图引导（topic-listing.md §9.6）中用户选「需要生图」或命中"自动补充"记忆；② 用户显式请求生成或替换商品图片（"生成套图/补图/生成一张场景图/换掉第 N 张图"等，成套或单张均可）——给定草稿 ID、指定图片 URL、或仅提出图片要求，均进入本链路按用户指令执行 | → [`references/topic-image-generation.md`](references/topic-image-generation.md) |
| **定招符合性检测** | 含"检测/检查/校验/是否符合/达标/合规"等语义 + productId + topicId | → [`references/product-topic-detect.md`](references/product-topic-detect.md) |
| **能力边界外** | 触发了定招意图但非上述四类（如"删除定招品""优化标题"） | → 友好拒绝（§3） |

**优先级（全序唯一出处）**：已发品 > 发品意图 > 套图意图 > 定招符合性检测 > 热卖筛选 > 类目筛选 > 主题名称搜索 > 模糊型 > **精确查询（topicIds）** > 翻页 > 筛选 > 推荐。

> 「精确查询」= 用户给出主题 ID 走 `topicIds` 精查；与「主题名称搜索」（按 `title` 搜名称）是两种不同入口，勿混。

## 3. 能力边界识别

本 Skill 当前仅支持**定招主题查询**、**定招发品**、**定招符合性检测**和**草稿套图生成**。超出范围的定招操作**立即友好拒绝**，不调用任何工具，拒绝话术以 [`references/error-cases.md`](references/error-cases.md) **E-17** 为准（唯一出处）。

**套图范围**：草稿品和已上架商品均可生成（已上架品查图/回填走 `trunk` 正本，详见 topic-image-generation.md §5.1；生效方式依平台规则，skill 不引导提交）；skill 满足不了的图片诉求可引导用户使用通用图片能力，但优先使用本 skill 的生图链路——不拒绝、不引导上线。

## 4. 跨链路硬性规则

链路内规则不在本表备份（各 reference 为唯一出处，按 §7 强制加载后必然可达）。

| 规则 | 说明 |
|---|---|
| **工具名称审计（最高优先级）** | 调用工具时，**必须且只能**使用工具注册的原始名称。**严禁**根据 Server 名或插件名推测命名空间前缀（例如：禁止拼接成 `farseer.xxx`）。如果对名称有任何疑虑，**必须**先执行 `search` 核实，禁止臆造。 |
| **执行纪律不得外化（最高优先级，与工具名审计并列）** | 本 Skill 的全部内部纪律——渲染顺序、阶段闸门、分批上限、弹窗时机、加载规则、约束理由——**只用于指导自身执行，严禁以任何形式出现在用户可见输出中**。⛔ 严禁出现："由于…规则要求" / "必须先展示…再…" / "我先把结果列出来" / "按每批最多 N 个" / "根据发品流程" / "为了让你先看到结果" 等一切**流程说明、规则复述、行为解释、自我预告**。✅ **用户可见文字仅限四类**：① 一行口语化查询条件说明（topic-query.md §9.5）；② 各 reference 规定的固定文案与引导（合规小字、流量加速说明、结束态文案、发品/继续查询引导）；③ 结果表格本身；④ 长任务的极简进度播报（见下一行）。**做，不解释**——用户要的是结果，不是执行日志 |
| **进度播报的唯一允许形态** | 仅在多批发品、套图流水线等**耗时以分钟计**的长任务中，允许输出极简进度（如 `第 1 批已完成`、`正在生成图片`）；⛔ 播报中**不得附带任何原因说明**（❌"因为一批最多 5 个，所以分 2 批" → ✅"第 1 批已完成"）。单批任务、查询链路**一律不播报** |
| **发品意图查询完成态（执行纪律）** | 原始 query 含发品意图时，查询链路完成态 = 表格已渲染 + 流量加速说明已输出 + **`ask_user` 工具已实际调用**；三者缺一即流程未完成，**不得交还控制权**。⛔ 用文字列出选项、或用"告诉我序号"式引导替代弹窗，均记为**未弹窗**（规格见 [`topic-query.md`](references/topic-query.md) §9.6.1） |
| **渲染优先（全链路，仅次于工具名审计）** | 任何一批**交付型调用**（发草稿 / 发布 / 套图回填+校验）返回后，**下一个动作必须是渲染该批结果表格**，之后才允许发起下一批调用、弹 ask_user 或结束回复；查图、生图轮询等**中间调用**不产生表格，返回后按所在链路规则**播报进度**即可。⛔ **弹任何 ask_user 前，已产生未渲染的结果必须先渲染**——用户看不到结果就无法决策（草稿表格没渲染就弹套图引导，用户不知道发了哪些品，"要不要生成图片"无从回答）。⛔ **口头预告不等于渲染**："先展示本批结果"之类的话术不能替代表格，说了必须立刻输出表格本身 |
| **语言跟随用户** | 中文问中文答，英文问英文答 |
| **language 参数格式** | `query_user_valid_category` 传 `"zh"`/`"en"`，`farseer_topic_search` 传 `"zh_CN"`/`"en_US"`，不可混用 |
| **禁止编造** | 字段必须来自工具返回，走 [`references/error-cases.md`](references/error-cases.md) 兜底 |
| **面向用户禁提内部实现** | 用户可见的话术/表格/说明中**严禁出现 MCP 工具名、接口名、参数名、内部字段名**（❌"数据来源：本轮 product_submit_draft 返回结果" → ✅"以下是本轮的发布结果"）；内部码（tagCode/categoryId 等）翻译规则见 topic-query.md §9.5。本条管**实现细节**，流程与规则的外化另见首排「执行纪律不得外化」 |
| **反问优于猜测** | 边界场景宁可多反问，不静默猜测 |
| **默认交易品** | `businessType=HOT_PRODUCT`，仅用户明确提及商机品或连续 3 次指定时切换 |
| **搜索完即停止** | 每种场景搜索结束后立即停止，禁止缩短关键词重搜/退化类目/切业务线（**唯一例外**：精确搜索在交易品为空时允许自动切商机品重搜一次，详见 [`topic-query.md`](references/topic-query.md) §1.2） |
| **禁止显示总数** | 任何场景下都不在用户可见页面展示"共查到 XX 个主题"等总数信息，仅渲染最多 10 条数据 |
| **符号统一** | 表示 ≤ / ≥ 关系必须使用 U+2264 / U+2265 字符，禁止使用异体字或半角组合 |
| **默认只发到草稿箱** | 发品意图无明确上架关键词时**只调用 `listing_product_draft_by_topic`**，禁止自动串联 `product_submit_draft`，不主动询问"是否上架"；上架关键词与触发规则见 [`topic-listing.md`](references/topic-listing.md) §2.2 |
| **图片 URL 协议补全（全链路）** | 任何图片 URL 在**传入工具入参**前、以及**输出给用户**前，必须确保以 `https://` 开头：① `//` 开头（协议相对，如 `//sc04.alicdn.com/x.jpg`）→ 补成 `https://sc04.alicdn.com/x.jpg`；② `http://` 开头 → 升级为 `https://`；③ 裸域名开头（如 `sc04.alicdn.com/x.jpg`）→ 前置补 `https://`；④ 已是 `https://` → 原样不动。**理由：协议相对 URL 脱离网页环境后无法解析，直接传给接口或给用户点击都打不开**。⛔ **豁免——"用于匹配既有数据"的 URL 一律不补**：包括去重与哈希比对（[`topic-image-generation.md`](references/topic-image-generation.md) §5 ②）、`DELETE` 的目标 URL、`REPLACE` 的 `originalImageUrl`，这些**必须保持原始形态**，补全后会匹配不到而**静默漏删或改错图**。**判据：这个 URL 是要"写进去/给用户看"的，还是要拿去"找已有的图"的？——写入与输出才补，匹配一律不补。** 补全只发生在「调用工具前的最后一步」与「渲染输出前」，**不回写**到任何用于比对的数据上。⛔ 形态非法（不属上述四类、或不指向图片资源）**不硬补**，按所在链路既有校验规则降级处置 |
| **定招生图优先本链路** | 定招语境下生成商品图片**必须优先**走 `image_generation`，skill 不自行调用通用图片工具；本链路满足不了的图片诉求可**引导用户**使用通用图片能力 |
| **套图引导 ≠ 上架引导** | 草稿完成后的套图引导是允许且必须的后置动作（每次会话首次弹窗、本会话已触达后常规文字引导，弹窗为三选项含费用提醒小字，规格见 topic-listing.md §9.6）；引导中不夹带上架话术 |
| **发品分批逐批渲染（执行纪律）** | 每批最多 5 个并行调用；**每批返回后立即渲染该批结果表格，渲染完立即自动发起下一批**，批间不等待用户确认（详见 [`topic-listing.md`](references/topic-listing.md) §6） |
| **草稿链路完成态含套图引导（执行纪律）** | 草稿链路完成态 = 全部批次表格 + 合规小字 + 草稿箱链接 **+ 套图引导已触达**（每次会话首次弹窗实际调用 ask_user 并写入本会话触达标记；本会话已触达后输出常规文字引导；或按记忆直接执行/跳过）；**未触达引导即流程未完成，不得交还控制权**（规格见 [`topic-listing.md`](references/topic-listing.md) §9.6） |
| **套图阶段式流水线（执行纪律）** | 全量查图去重 → 生图每批 3 品顺序执行 → 阶梯轮询 → 并发回填 → 统一校验后渲染一张总表；**阶段转换必须播报进度**（详见 [`topic-image-generation.md`](references/topic-image-generation.md) §5） |
| **校验在主流程内完成（执行纪律）** | 套图回填后的校验 = 主流程内**每品一次** `product_query_information` 复查 + 逐项断言，通过后**直接渲染结果**；⛔ 严禁派生独立校验子任务/子会话，严禁复查后再做第二次"独立校验"（详见 [`topic-image-generation.md`](references/topic-image-generation.md) §5 ⑦） |

## 5. 会话状态管理

- **先查后发**：发品必须在本会话执行过查询后才可执行（无查询 + 有 topicId → 先查验再发品）
- **翻页上下文**：会话内维护 `currentPage` 状态，翻页保留全部条件仅 +1，修改条件则重置为 1
- **类目缓存**：`query_user_valid_category` 结果同一会话内可复用
- **草稿上下文**：发草稿成功后，草稿返回的 `draftProductId` 在会话内保持，作为 `productId` 参数供后续 `product_submit_draft` 使用（**仅当用户后续明确说出上架关键词时**才会真正调用上架）；`categoryId` 保留供构造草稿编辑链接使用
- **检测独立性**：定招符合性检测不依赖前置查询，只要有 productId + topicId 即可直接调用 `product_topic_detect`
- **套图上下文**：套图提交后返回的 `reqId`、去重标记、空位计算、输入图 URL 在会话内保持；轮询超时后用户说"查套图结果"时复用 reqId 继续查询；**跨会话 reqId 不可用**（按 error-cases E-22 处理）
- **套图选择记忆**：弹窗**每次会话仅首次触发一次**（会话级判定），触发后写入本会话「套图引导已触达」标记，本会话后续一律常规文字引导，**跨会话不继承触达标记**；弹窗选 C（需要，以后每次都自动生成）即写入跨会话「自动补充套图」偏好——**必须实际写入 agent 长期记忆文件 `${agent_core}/MEMORY.md`（写入位置/时机/条目格式/互斥清除/失败处置见 [`topic-listing.md`](references/topic-listing.md) §9.6「偏好记忆写入规格」，唯一出处）**；**首次弹窗选 A 完成生图后弹二次引导**（询问是否以后每次都自动生成），触发后写入本会话「二次引导已触达」标记，仅会话内首次生图完成时出现一次；跨会话偏好的写入、互斥与重置规则见 [`topic-listing.md`](references/topic-listing.md) §9.6（唯一出处）

## 6. 错误处理总则

运行时异常处理：→ [`references/error-cases.md`](references/error-cases.md)

- 网络错误自动重试一次，仍失败则报告用户并终止
- 业务错误（`success=false` / 无权限）不静默重试，先告知根因
- 异常即终止，询问用户处理意见
