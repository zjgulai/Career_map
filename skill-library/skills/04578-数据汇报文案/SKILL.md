# 数据汇报文案

> 一句话直击核心数字，三段叙事让老板 30 秒看懂你的业绩。

---

## 0. 前置：读取团队配置

执行任何步骤前，**必须**先按以下顺序读取配置：

1. 读取共享 profile：`~/.qoderwork/plugins/config/team-profile.md`
2. 读取本插件配置：`~/.qoderwork/plugins/config/pm-output-engine/QODERWORK.md`

重点关注以下章节（如果存在且已填写）：

- `## 输出风格` —— 尤其是「汇报文案风格」和「汇报叙事结构」两项
- `## 业务规则` —— 尤其是「指标口径定义」和「红线」两项

**如果配置文件不存在或仍含 `[PLACEHOLDER]` 标记：**
停下来，回复用户：
> "这个插件需要先配置一下，运行 /pm-output-engine:onboarding 大概 10 分钟，
> 本插件所有 skill 都依赖它。否则输出会是通用模板，可能不符合你的实际流程。"

不要继续执行后续步骤。唯一例外：用户明确说"先用默认配置试试"。

## 1. Step 1：明确汇报上下文

通过提问或从用户输入中提取以下信息。**缺一不可**，信息不全时主动追问：

| 要素 | 说明 | 示例 |
|---|---|---|
| **汇报对象** | 老板 / VP / 跨部门 stakeholder | "给 VP 周报" |
| **汇报目的** | 展示成果 / 预警风险 / 争取资源 / 复盘 | "展示 Q2 上线成果" |
| **核心指标** | 要汇报的 1-3 个关键指标 | "相机发起率" |
| **数据范围** | 时间区间、人群、产品线 | "6月1日-6月8日，全量用户" |
| **对比基准** | 环比 / 同比 / vs 目标值 / vs 实验对照 | "对比上线前一周" |

### 追问规则

- 如果用户只说了指标名没说时间范围 → 追问时间范围
- 如果用户只说了"数据变好了"没说具体数字 → 追问具体数据或提供 ODPS 查询
- 如果用户没说汇报对象 → 默认按"直属老板"处理，但口头确认一次

---

## 2. Step 2：获取数据

根据数据来源选择路径：

### 路径 A：ODPS 数据直拉（已连接 ODPS 时）

1. 检查 QODERWORK.md 中 `## 已连接的工具` → ODPS 状态是否为 ✓
2. 从 `## 业务规则 → 常用 ODPS 表映射` 获取对应表名和项目
3. 从 `## 业务规则 → 指标口径定义` 获取计算方式
4. 生成并执行 SQL，遵守以下红线：
   - **禁止** `SELECT *` 不带 `LIMIT` 查生产表
   - **必须** 指定分区条件
   - **必须** 在 SQL 注释中标注口径和日期范围
5. 将查询结果整理为结构化数据，进入 Step 3

### 路径 B：用户手动提供数据

1. 用户直接给出数据（文字、截图、或文件）
2. 确认口径：指标是怎么算的？分子分母分别是什么？
3. 确认时间粒度：日级 / 周级 / 月级
4. 将数据整理为结构化格式，进入 Step 3

### 数据校验（两条路径都要做）

- 检查数据是否有明显异常（如单日跌零、数值突增 10 倍等）
- 如发现异常，**先向用户确认**，不要直接用异常数据写文案
- 检查样本量是否足够支撑结论（UV < 100 时标注"小样本"）

---

## 3. Step 3：识别关键叙事

基于结构化数据，按以下逻辑自动识别最适合的叙事角度：

### 3.1 寻找最佳提升窗口

- 扫描时间序列，找到**连续提升**最长的区间
- 如果有多段提升，选**幅度最大**且**持续最长**的那段
- 记录：起始值、终止值、起止日期、持续天数/周数

### 3.2 计算三个核心数字

| 数字 | 计算方式 | 格式 | 示例 |
|---|---|---|---|
| **绝对 pp 提升** | 终止值 − 起始值（百分点） | 保留 2 位小数 + "pp" | "+14.92pp" |
| **相对 % 提升** | (终止值 − 起始值) ÷ 起始值 × 100% | 保留整数 + "%" | "+28%" |
| **稳定时长** | 达到新高后维持的天数/周数 | 整数 + "天/周" | "连续 4 周" |

### 3.3 判断叙事类型

根据数据走势选择主叙事类型：

| 走势特征 | 叙事类型 | 适用场景 |
|---|---|---|
| 指标明显上升（pp ≥ 2） | **提升叙事** | 功能上线、策略生效 |
| 指标明显下降（pp ≤ -2） | **下降叙事** | 故障、竞对冲击、季节性 |
| 指标波动小（pp < 2） | **稳定叙事** | 大盘稳固、护城河 |
| 先升后稳 | **突破-稳定叙事** | 最常见的汇报场景 |
| 先降后升 | **V 型反转叙事** | 问题修复后恢复 |

---

## 4. Step 4：三段叙事结构

这是本 skill 的核心输出框架。所有汇报文案都遵循这个结构，但根据叙事类型调整语气和侧重。

### 标准三段叙事（提升/突破-稳定型）

**Segment 1 —— 绝对 pp 提升（What happened）**

直接陈述指标的绝对变化，用百分点（pp）表达：

```
[指标名]从 [起始值] 提升至 [终止值]，绝对提升 [X]pp。
```

示例：
> 相机发起率从 53.08% 提升至 68.00%，绝对提升 +14.92pp。

**Segment 2 —— 相对 % 提升（How significant）**

用相对百分比说明这个变化的"含金量"：

```
相对提升 [Y]%，[可选：对比说明含金量]。
```

示例：
> 相对提升 28%，相当于每 4 个用户中多出 1 个使用相机。

**Segment 3 —— 稳定平台（Sustainability）**

说明这不是一次性峰值，而是可持续的结构性提升：

```
此后连续 [N] [天/周] 稳定在 [区间] 高位，[可选：说明结构性原因]。
```

示例：
> 此后连续 4 周稳定在 67%-69% 高位，说明提升来自用户行为结构性变化而非短期运营刺激。

### 下降叙事变体

当指标下降时，三段结构调整为：

1. **影响量化**：下降了多少 pp，影响了多少用户
2. **根因定位**：拆解是哪个环节/人群/渠道导致的
3. **止损/恢复计划**：已采取什么措施，预计多久恢复

示例：
> 相机发起率从 68% 下降至 61%，绝对下降 -7pp（-10%）。拆解发现主要由 Android 端新版灰度导致，影响约 120 万日活用户。已于 6/5 回滚灰度版本，当前恢复至 66%，预计本周末恢复至 68% 水位。

### 稳定叙事变体

当指标平稳时，三段结构调整为：

1. **水位定位**：当前处于什么水位，在历史中属于什么水平
2. **稳定性量化**：波动范围有多大，连续多久保持稳定
3. **下一步机会**：在稳定基础上，下一个增长点在哪

示例：
> 相机发起率连续 8 周稳定在 67%-69% 区间，波动幅度 < 2pp，处于上线以来最高水位。下一步增长点在于提升相册入口的转化率，当前仅 42%，有较大空间。

### V 型反转变体

1. **低点定位**：跌到了多少，什么原因
2. **恢复速度**：多快恢复，恢复的驱动力
3. **超额恢复**：是否超过了下跌前的水位

示例：
> 6/1 因服务异常，相机发起率从 68% 骤降至 52%（-16pp）。团队 4 小时内定位并修复问题，次日恢复至 65%，3 天后回升至 70%，超过故障前水位 +2pp。

## 5. Step 5：生成一句话摘要

用于日常站会、群消息、钉钉/飞书汇报等快速沟通场景。

### 格式要求

- **长度**：20-40 字，一句话
- **必含要素**：指标名 + 核心数字 + 时间范围
- **可选要素**：对比基准、原因
- **禁止**：只说"提升显著"不给数字、只给数字不说时间段

### 模板

```
[时间范围] [指标名] [核心变化]，[一句话原因/意义]。
```

### 示例

> 6/1-6/8 相机发起率从 53%→68%（+15pp），新版引导策略效果显著。

> 本周 DAU 环比 +8.3%，连续 3 周正增长，突破 Q2 目标值。

---

## 6. Step 6：生成完整汇报段落

用于周报、月报、给老板的正式汇报文档。

### 结构

```
【一句话摘要】（来自 Step 5）

【详细叙事】（来自 Step 4 的三段叙事，组合为一段连贯文字）

【数据明细】（可选，列出关键数字表格）

【下一步计划】（1-2 句话，说明接下来要做什么）
```

### 格式要求

- 纯文本输出（非 HTML），可直接粘贴到聊天/文档中
- 数字一律保留 2 位小数（pp）或整数（%）
- 时间范围必须明确标注起止日期
- 如果有对比基准，必须注明是什么基准
- 段落之间用空行分隔，不要用 markdown 标题符号

## 7. 分支逻辑总结

```
用户输入
  │
  ├─ 有数据 ──────→ 校验数据 → Step 3 识别叙事类型
  │                                   │
  │                                   ├─ 提升 → 标准三段叙事
  │                                   ├─ 下降 → 下降叙事变体
  │                                   ├─ 稳定 → 稳定叙事变体
  │                                   └─ V型  → V型反转变体
  │
  └─ 无数据 ──────→ 尝试 ODPS 查询
                      │
                      ├─ 成功 → 校验数据 → Step 3
                      └─ 失败 → 请用户提供数据
```

## 8. 输出格式规范

### 必须遵守

- **纯文本**：输出为可直接粘贴的纯文本，不使用 HTML 标签
- **数字格式统一**：pp 保留 2 位小数，% 保留整数，用户量用"万"为单位
- **时间标注**：每个数字都必须关联明确的时间范围
- **口径标注**：如果指标口径可能有歧义，在末尾用括号注明
- **来源标注**：如果数据来自 ODPS 查询，注明表名和查询日期

### 禁止事项

- 禁止只给相对 % 不给绝对 pp（或反过来）
- 禁止不标注时间范围就给出数字
- 禁止 cherry-pick 数据点（只选最好/最差的一天）
- 禁止用"大幅提升""显著增长"等模糊词替代具体数字
- 禁止在样本量 < 100 时不标注"小样本，结论待验证"
- 禁止在因果归因不充分时使用"因为""导致"等因果表述，改用"关联""同步"

## 9. 常见陷阱

### 陷阱 1：只报相对 % 不报绝对 pp

**错误示范**：
> "转化率提升了 50%！"（实际是从 2% 提升到 3%，只有 1pp）

**正确做法**：
> "转化率从 2.00% 提升至 3.00%（+1.00pp，相对 +50%）。"

永远同时给出绝对值和相对值，让读者自己判断含金量。

### 陷阱 2：时间范围模糊

**错误示范**：
> "DAU 增长了 10%。"（跟什么时候比的？上周？上月？去年同期？）

**正确做法**：
> "6/1-6/7 日均 DAU 环比上周（5/25-5/31）增长 10%。"

### 陷阱 3：Cherry-pick 最好的一天

**错误示范**：
> "6/5 发起率达到 72%，创历史新高！"（但 6/6-6/8 已经回落到 65%）

**正确做法**：
> "6/1-6/8 日均发起率 67%，其中 6/5 达到峰值 72%（受运营活动拉动），活动后回落至 65%，整体水位较上周 +3pp。"

### 陷阱 4：因果归因过于武断

**错误示范**：
> "因为上线了新版引导，发起率提升了 15pp。"（同期还有其他改动、节假日效应等）

**正确做法**：
> "新版引导上线后，发起率提升 +15pp。需注意同期还有 618 活动拉动，建议结合 AB 实验结果进一步确认因果关系。"

### 陷阱 5：忽略统计显著性

**错误示范**：
> "A 组转化率 5.2%，B 组 4.8%，A 组优于 B 组。"（样本量各 200 人，差异不显著）

**正确做法**：
> "A 组转化率 5.2%，B 组 4.8%，差异 0.4pp。当前样本量下（各 200 人）差异不具有统计显著性（p > 0.05），建议继续积累样本。"

### 陷阱 6：数字堆砌没有叙事主线

**错误示范**：
> "DAU 100万，PV 500万，转化率 3.2%，留存率 45%，ARPU 12元……"

**正确做法**：
围绕一个核心论点组织数字，其他数字作为支撑：
> "Q2 核心目标是提升用户活跃。DAU 从 92 万提升至 100 万（+8.7%），主要驱动力是相机功能的渗透率提升（+15pp），带动整体留存率从 41% 提升至 45%。"

## 10. 快速参考：叙事公式卡

### 提升型

```
[指标]从 X 提升至 Y（+Z pp，相对 +W%），
此后连续 N 天/周稳定在 [区间]，
说明 [结构性原因]。
```

### 下降型

```
[指标]从 X 下降至 Y（-Z pp，相对 -W%），
主要影响 [人群/渠道/环节]，涉及 [数量] 用户，
已采取 [措施]，预计 [时间] 恢复。
```

### 稳定型

```
[指标]连续 N 周稳定在 [区间]（波动 < Z pp），
处于 [历史水位描述]，
下一步增长点在于 [方向]。
```

### V 型反转型

```
[时间] 因 [原因]，[指标]从 X 骤降至 Y（-Z pp），
团队 [时间] 内修复，[时间] 恢复至 [值]，
当前已回升至 [值]，超过故障前 +W pp。
```

## 12. 完整执行清单

每次执行时，按此清单逐项确认，确保产出质量：

**准备阶段**
- [ ] 已读取 QODERWORK.md 配置（`## 输出风格` + `## 业务规则`）
- [ ] 已明确汇报对象、目的、核心指标、时间范围、对比基准（五要素缺一不可）
- [ ] 数据已获取（ODPS 直拉 或 用户手动提供）

**数据校验**
- [ ] 数据无明显异常（如单日跌零、数值突增 10 倍等）
- [ ] 样本量充足（UV < 100 时标注"小样本，结论待验证"）
- [ ] 口径已确认（分子、分母、过滤条件）

**叙事构建**
- [ ] 已识别叙事类型（提升 / 下降 / 稳定 / V 型反转）
- [ ] 三个核心数字已计算：绝对 pp（2 位小数）、相对 %（整数）、稳定时长
- [ ] 已选择对应叙事变体的三段结构

**产出检查**
- [ ] 一句话摘要已生成（20-40 字，必含指标名 + 核心数字 + 时间范围）
- [ ] 完整汇报段落已生成（摘要 + 叙事 + 明细 + 下一步）
- [ ] 同时包含绝对值（pp）和相对值（%）
- [ ] 所有数字都标注了时间范围
- [ ] 没有 cherry-pick 数据点（只选最好/最差的一天）
- [ ] 因果归因有充分依据（不充分时用"关联"替代"因为/导致"）
- [ ] 纯文本格式，可直接粘贴到聊天/文档中
