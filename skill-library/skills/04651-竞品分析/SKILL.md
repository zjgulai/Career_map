# 竞品分析 —— Compete

电商频道 UX 竞品分析工具。从截图到报告的全流程自动化。

## 读取配置（自动生成，请勿删除）

执行任何动作前，读 `~/.qoderwork/plugins/config/super-design-studio/QODERWORK.md`。
- 文件不存在或仍含 `[PLACEHOLDER]` → 停下来，回复用户运行 `/super-design-studio:onboarding`，不要继续。
- 本 skill 会用到配置里的：## 业务规则（频道/产品线定位）、## 命名规范、## 输出目录偏好
- 配置没覆盖到的字段：反问用户 → 把答案写回 QODERWORK.md → 继续。不要在内存里假设默认值。

## 触发语

- "分析竞品"
- "对比一下 [竞品名]"
- "看看 [竞品URL] 怎么做的"
- "竞品报告"

## 执行流程

### 1. 接收与确认

1. 解析用户输入，提取竞品 URL 列表
2. 如果用户只给了竞品名而非 URL，用 web search 搜索找到对应页面 URL
3. 向用户确认待分析 URL 列表和分析维度偏好
4. 如果用户未指定维度，使用默认四维度：配色、布局、交互模式、信息架构

### 2. 长截图截取（浏览器自动化）

**前提：需要浏览器自动化 MCP 已连接。**

检查 `## 已连接的工具` 中浏览器自动化状态：

**已连接（✓）：**
1. 对每个竞品 URL，调用浏览器自动化进行分段截取：
   - viewport 宽度设置为 375px（移动端）和 1440px（桌面端），各截一份
   - 分段截取：从页面顶部开始，每段 1000px 高度，滚动截取直到页面底部
   - 将分段截图拼接为完整长截图
2. 截图保存到 output/{case-id}/compete/screenshots/ 目录
3. 命名规则：{竞品域名}-{viewport}-{序号}.png

**未连接（✗）：**
1. 告知用户："浏览器自动化未连接，无法自动截图。请手动截取竞品页面长截图并上传。"
2. 提供截取指导：建议使用浏览器开发者工具或截图插件，按 375px 和 1440px 两种宽度截取
3. 等待用户上传截图后继续

### 3. 视觉差异分析

对每个竞品，从以下四个维度进行分析：

**配色维度：**
- 主色调、辅助色、强调色提取
- 价格/促销色 vs 常规内容色的区分策略
- 色彩情绪和品类调性匹配度
- 与百亿补贴频道色系的异同

**布局维度：**
- 页面整体结构（头图、导航、商品列表、底部）
- 卡片/模块比例和间距节奏
- 信息密度对比（每屏展示商品数量）
- 滚动节奏和模块切换方式

**交互模式维度：**
- 核心交互方式（滑动、点击、展开、折叠）
- 价格展示交互（翻转、动效、倒计时）
- 商品详情进入方式
- 筛选/排序/分类导航模式

**信息架构维度：**
- 核心层级结构（频道 → 品类 → 单品）
- 利益点展示策略（价格折扣、历史价、补贴力度）
- 信任标识布局（正品保障、品牌认证）
- 用户动线设计（浏览 → 比较 → 决策 → 购买）

### 4. 趋势提炼

1. 跨竞品共性模式：在 3 个以上竞品中都出现的设计模式
2. 差异化亮点：某竞品独有的、效果可能更好的设计创新
3. 行业趋势方向：从多个竞品共同变化方向推断的趋势
4. 反模式警告：多个竞品都在用但实际体验不佳的模式

### 5. 生成对比报告

组装为结构化竞品对比报告，包含：

**报告结构：**
```
1. 分析概览（分析目的、竞品列表、分析维度）
2. 竞品逐个分析（截图 + 四维度评分 + 关键发现）
3. 横向对比矩阵（维度 x 竞品的评分表格）
4. 趋势提炼（共性模式 + 差异化亮点 + 行业趋势）
5. 优化建议（基于竞品分析对本频道设计的具体建议）
6. 附录（原始截图、数据来源标注）
```

**输出格式：**
- HTML 版（带嵌入式截图，可直接在浏览器查看）
- Markdown 版（纯文本，适合文档协作）

**来源标注（遵循 QODERWORK.md 共同护栏 - 引用来源标注）：**
- 截图 → `[浏览器自动化截取 — {日期}]`
- 竞品公开数据 → `[web search — {来源URL}]`
- 分析推断 → `[模型分析 — 待人工确认]`

## 长截图技术方案

浏览器自动化长截图截取的核心技术细节。

### 分段截取策略

1. **viewport 设置：**
   - 移动端：width=375px, deviceScaleFactor=2（Retina 清晰度）
   - 桌面端：width=1440px, deviceScaleFactor=1
   - 高度固定为 1000px/段（避免单段过大导致内存溢出）
2. **滚动与截取：**
   - 从 `scrollY=0` 开始，每段截取 `window.scrollTo(0, scrollY)` 后等待 500ms（确保懒加载内容渲染）
   - overlap 区域：每段底部 10%（100px）与下一段顶部 10% 重叠，用于拼接对齐
   - 终止条件：`scrollY + viewportHeight >= document.body.scrollHeight`
3. **等待策略：**
   - 每次滚动后等待 500ms（`waitForTimeout`）
   - 如果页面有图片懒加载，额外等待 `networkidle` 事件（最多 3s）
   - 对于 SPA 页面，首次加载额外等待 2s（确保框架初始化完成）
4. **段数限制：**
   - 单个页面最多截取 30 段（约 30000px 高度），超过则截断并在报告中标注"页面过长，已截断"

### 拼接算法

1. **基于 overlap 区域匹配：**
   - 取上一段底部 100px 和当前段顶部 100px 作为匹配区域
   - 逐行比较像素值（容差 RGB 各通道 ±5），找到最佳匹配偏移量
   - 如果匹配失败（偏移量 > 20px），回退到固定步长模式（步长 = 段高度 - overlap）
2. **拼接输出：**
   - 创建画布：width = viewport 宽度, height = 各段有效高度之和
   - 逐段绘制，每段起始 y = 前段 y + 段高度 - overlap 偏移量
   - 输出 PNG（quality=90）以控制文件大小
3. **文件大小控制：**
   - 最终长图如果超过 10MB，自动降采样至 deviceScaleFactor=1 重新生成
   - 对于超长页面（>20 段），输出分段拼接图而非单一长图

### 失败降级方案

当浏览器自动化截取失败时，按以下优先级降级：

1. **自动重试（最多 2 次）：**
   - 首次失败后等待 3s 重试
   - 第二次失败后切换 viewport 宽度（375 → 390 或 1440 → 1280）重试
2. **手动上传 + URL 记录：**
   - 提示用户手动截取长截图并上传
   - 必须记录竞品 URL 和截取时间，确保截图可追溯
   - 用户上传的截图命名为 `manual-{竞品域名}-{viewport}.png`
3. **部分截图模式：**
   - 如果只能截取部分段落（如页面中途加载失败），使用已截取段落生成"部分分析报告"
   - 在报告中明确标注哪些段落缺失，以及缺失原因

## 分析维度详述

四个核心分析维度的详细评估标准和方法。

### 配色分析

1. **主色/辅色/中性色提取：**
   - 使用截图颜色采样（取页面面积占比 >5% 的颜色作为主色）
   - 辅色：面积占比 1%-5% 的颜色，通常用于按钮、标签、图标
   - 中性色：灰阶色系（#333、#666、#999、#F5F5F5 等），用于文字、背景、分割线
2. **色相分布对比：**
   - 将每个竞品的颜色映射到 HSL 色相环，绘制色相分布图
   - 对比各竞品在暖色区（红/橙/黄）vs 冷色区（蓝/绿/紫）的分布比例
   - 特别关注促销色（通常为红色/橙色系）的使用频率和面积
3. **色彩一致性评估：**
   - 同竞品内不同页面的色彩一致性（主色是否贯穿）
   - 价格信息色彩是否与促销氛围协调
   - 无障碍对比度检查（文字/背景对比度是否达到 WCAG AA 标准 4.5:1）

### 布局分析

1. **信息密度：**
   - 每屏（viewport）展示的可交互元素数量（商品卡片、按钮、链接）
   - 高密度（>15 元素/屏）vs 低密度（<8 元素/屏）的定位差异
   - 首屏信息密度 vs 页面平均密度的对比
2. **模块比例：**
   - 头图/Banner 区域占首屏的比例（全幅 / 半屏 / 迷你）
   - 商品列表区域单卡片宽高比（1:1 / 3:4 / 16:9）
   - 导航/筛选区域的屏幕占比
3. **留白策略：**
   - 模块间距（紧凑 <8px / 适中 8-16px / 宽松 >16px）
   - 卡片内边距和内容间距的节奏感
   - 页面两侧留白（全宽铺满 vs 居中限宽）

### 交互分析

1. **导航模式：**
   - 顶部导航 vs 底部导航 vs 侧边导航
   - Tab 切换 vs 下拉筛选 vs 侧滑面板
   - 返回/关闭的交互方式（手势 / 按钮 / 两者兼有）
2. **反馈机制：**
   - 加载状态：骨架屏 / 旋转动画 / 进度条
   - 操作反馈：点击涟漪 / 缩放动画 / 震动反馈
   - 空状态：插图 + 引导文案 / 纯文字提示
3. **手势支持：**
   - 左右滑动切换（商品图片 / Tab / 卡片）
   - 下拉刷新 / 上拉加载更多
   - 长按操作（收藏 / 分享 / 快捷菜单）

### 信息架构

1. **页面层级：**
   - 核心路径深度：从频道首页到商品详情页的点击次数
   - 层级结构类型：扁平型（≤2 层）vs 深层级（≥4 层）
   - 面包屑/返回路径的可见性
2. **内容分类：**
   - 商品分类维度（品类 / 品牌 / 场景 / 价格区间）
   - 分类入口的可视性和可达性
   - 交叉分类的处理（一个商品属于多个分类）
3. **入口设计：**
   - 核心功能入口的位置和视觉权重
   - 搜索入口的显著程度
   - 辅助功能（客服、帮助、反馈）的入口位置和层级

## Pitfalls / 质量红线

- **不编造竞品数据** — 不要编造竞品的用户量、转化率、GMV、DAU 等业务数据。如果截图模糊或无法看清某个数值（如价格），标注"[截图中不清晰]"而非猜测。所有数值型结论必须来自截图可见内容或公开可查证的数据源。
- **截图必须标注截取时间和 URL** — 每张截图必须在报告中标注 `[浏览器自动化截取 — {日期} — {URL}]`，手动上传的截图标注 `[用户手动截取 — {日期} — {URL}]`。无法追溯来源的截图不得用于分析结论的支撑证据。
- **分析结论必须有截图证据支撑** — 每一条分析结论都必须引用至少一张截图作为证据。"该竞品的信息密度较高"必须附带具体截图位置和元素计数。无证据支撑的结论标注为"[推断 — 待验证]"。
- **不做"XX 竞品更好所以我们也要做"的简单对比** — 竞品分析的价值在于理解设计决策背后的逻辑，而非简单模仿。优化建议必须说明"为什么这个设计在我们的业务场景下也适用（或不适用）"，结合百亿补贴频道的用户画像和业务目标论证。
- **趋势提炼要区分"已验证的趋势"和"初步观察"** — 在 5 个以上竞品中都出现的模式标记为"已验证趋势"；在 2-4 个竞品中出现的标记为"初步观察"；仅 1 个竞品使用的标记为"个案亮点"。不得将个案亮点当作行业趋势呈现。
- **不要跳过确认步骤** — 即使 URL 看起来明确，也要向用户确认分析维度偏好，避免生成用户不需要的分析内容。
- **不要脱离业务语境给建议** — 优化建议必须结合百亿补贴频道的业务特点（价格敏感型用户、促销氛围、信任建设），不要给出通用 UX 建议。
- **长截图拼接要注意完整性** — 分段截取后拼接时，检查是否有遗漏段落或重复区域。如果页面有懒加载内容，需要等待加载完成后再截取。
- **移动端和桌面端都要分析** — 电商频道移动端流量占比通常 >80%，不要只分析桌面端。
- **报告中区分事实和推断** — 截图里看到的是事实，"这个设计可能提升了转化率"是推断，必须明确区分并标注来源。
