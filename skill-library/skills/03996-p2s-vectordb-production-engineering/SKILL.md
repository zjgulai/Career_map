# Skill-VectorDB-Production-Engineering

## ① 解决的问题

工程团队面临"向量数据库召回质量随数据增长到千万量级后断崖下降"——向量DB生产工程从索引参数/分片策略/ANN算法三层优化，千万级Recall@10从62%提升至88%，查询P99延迟降至80ms以内

## ② 核心算法逻辑

向量数据库生产工程三层决策框架

## ③ 业务应用场景

业务问题： - 用户搜"新生儿防尿布疹护理套装"，需在50ms内从120万SKU中返回Top10相关商品 - 传统keyword搜索召回率仅68%(漏掉"尿布疹膏+护理湿巾"组合品) - 大促期间QPS从500激增至8000，系统经常超时
数据要求： - 120万商品 × (768维文本向量 + 512维图像向量) = 1.54GB向量数据 - 日均查询50万次，大促10倍流量 - 向量更新频率：新品上架5分钟内生效
量化产出： - 多模态融合向量(文本0.6权重+图像0.4权重)召回率提升至94% - P99延迟从280ms降至42ms(采用热冷分层+HNSW索引) - 大促QPS从8000稳定处理，无超时

## 输入 / 输出契约

**输入**：需商品向量数据（卡页示例 120 万商品、768 维文本向量加 512 维图像向量）、日均查询量与大促峰值、向量更新频率要求，商品与查询级粒度。

**输出**：产出三层优化方案与指标对比（卡页记录召回率提升至 94%、P99 从 280ms 降至 42ms、大促 QPS 8000 稳定处理），供检索平台与推荐团队使用。

## 执行步骤

1. 盘点向量规模、维度、更新频率与查询量
2. 重组索引结构（热冷分层与分片策略）
3. 选择 ANN 算法并调优索引参数
4. 融合文本与图像向量做加权检索
5. 压测大促峰值 QPS 下的 P99 延迟与召回率

## 边界与不做

- 向量规模在十万级以内且延迟达标时，分层与分片改造收益有限
- 只做检索工程质量优化，不负责向量模型的语义效果
- 商品图片与文本须为授权数据，向量库不得写入用户 PII
- 本技能承载的是**规则与契约产物**（DAG 定序规则 / 熔断阈值与退避策略 / 置信门控与判据），不是执行器；真正的编排与冻结动作由模型外的确定性控制层执行。
