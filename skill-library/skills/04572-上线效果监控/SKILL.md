# 上线效果监控

## 读取配置（必须）

执行前先读 `~/.qoderwork/plugins/config/pm-data-toolkit/QODERWORK.md`：

- **不存在或含 [PLACEHOLDER]** → 停止，告知用户："这个插件需要先配置一下，运行 /pm-data-toolkit:onboarding 大概 10 分钟，本插件所有 skill 都依赖它。否则输出会是通用模板，可能不符合你的实际流程。"
- **已配置** → 继续执行，读取以下段落：
  - `## 常用 ODPS 表映射` —— 确定要查询的表
  - `## 指标口径定义` —— 确定指标计算方式
  - `## 输出风格` —— 确定报告风格和格式
  - `## 业务规则` —— 确定红线和标准流程

## 触发场景

用户说"监控效果"、"看看上线后数据"、"检查指标是否正常"、"异动检测"、"稳定性分析"等关键词时触发。

## 执行流程

### Step 1: 明确监控范围

询问用户：

1. **需求名称** —— 哪个功能/需求上线了？
2. **上线日期** —— 具体哪天上线的？（用于划分前后对比窗口）
3. **核心指标** —— 要监控哪些指标？（从 QODERWORK.md 的指标口径定义中选择，或用户提供）
4. **监控周期** —— 要看上线后多少天？（默认 7 天，可延长至 14/30 天）

### Step 2: 确定基线期

根据上线日期确定对比窗口：

- **上线前期（基线）**：上线前 14 天（排除最后 2 天，避免灰度污染）
- **上线后期（观察）**：上线后第 3 天开始（前 2 天数据不稳定，跳过）
- **同比对齐**：去年同期，必须星期几对齐（周一对周一）
- **环比对齐**：上周同一天（星期几对齐）

### Step 3: 拉取数据（ODPS SQL）

如果 ODPS 已连接（QODERWORK.md 中 `## 已连接的工具` 显示 ✓）：

```sql
-- 示例：拉取上线前后数据（按天聚合）
SELECT
    ds,
    COUNT(DISTINCT user_id) AS uv,
    COUNT(*) AS pv,
    COUNT(DISTINCT CASE WHEN event_type = 'convert' THEN user_id END) AS convert_uv,
    -- 其他指标...
FROM {表名}
WHERE ds BETWEEN '{上线前14天}' AND '{上线后N天}'
    AND {过滤条件}
GROUP BY ds
ORDER BY ds;
```

如果 ODPS 未连接：
- 提示用户："请提供上线前后的每日数据（Excel/CSV），包含日期和各指标值。"
- 等待用户上传文件后继续。

**MA7 平滑**：对每个指标计算 7 日移动平均（需至少 7 天数据，不足 7 天时不计算，标记为 N/A）。

### Step 4: 稳定性分析（SPC 方法论）

对每个指标执行以下分析：

#### 4.1 统计过程控制（SPC）

- **计算基线期均值（μ）和标准差（σ）**
- **控制上限（UCL）** = μ + 2σ
- **控制下限（LCL）** = μ - 2σ
- **判断规则**：
  - 超出 UCL/LCL → **异动**（红色标记）
  - 连续 3 天上升 → **上升趋势**（橙色标记）
  - 连续 3 天下降 → **下降趋势**（橙色标记）
  - 连续 5 天在均值同侧 → **偏移信号**（黄色标记）

#### 4.2 趋势检测

- **连续 N 天单调变化**（N ≥ 3）→ 趋势信号
- **MA7 斜率**：最近 3 天的 MA7 变化率，超过 ±5% → 显著趋势

#### 4.3 异动检测

- **单日异动**：当天值超出 μ ± 2σ
- **连续异动**：连续 2 天超出 1.5σ（更敏感）
- **异动严重度**：
  - 超出 2σ → 中等级别
  - 超出 3σ → 高级别

#### 4.4 环比/同比对比

- **WoW（环比）**：本周 vs 上周，星期几对齐
- **YoY（同比）**：今年 vs 去年同期，星期几对齐
- **计算公式**：(当前值 - 对比值) / 对比值 × 100%
- **对齐规则**：周一对周一，周日对周日（避免周末效应）

### Step 5: 生成监控报告（HTML）

产出 HTML 报告，包含：

#### 5.1 Stat Cards（指标卡片）

每个核心指标一张卡片：
- **当前值**：最新一天的值
- **环比变化**：WoW 百分比，带箭头（↑/↓/→）
- **7 日趋势**：MA7 箭头方向
- **状态标签**：稳定（绿色）/ 趋势（橙色）/ 异动（红色）

#### 5.2 趋势图（Chart.js）

每个指标一张折线图：
- **X 轴**：日期
- **Y 轴**：指标值
- **多条线**：实际值、MA7、UCL、LCL
- **标注**：上线日期（垂直虚线）、异动点（红色圆点）

#### 5.3 异动告警区

如果有异动：
- **红色背景区块**
- **异动摘要**：哪个指标、哪一天、偏离多少
- **告警文案**（可直接复制到钉钉群）

#### 5.4 结论区

- **一切正常** → 绿色提示："核心指标稳定，上线效果符合预期。"
- **出现异动** → 红色提示："指标 XX 在上线后第 N 天出现异动，环比 +X%，超出 2σ，建议进一步归因。"

### Step 6: 生成告警文案

**格式模板**：

```
【上线监控告警】
需求：{需求名称}
上线日期：{上线日期}
监控指标：{指标名}
异动时间：上线后第 {N} 天（{具体日期}）
当前值：{当前值}
环比变化：{WoW 变化}%
基线均值：{μ}，标准差：{σ}
偏离程度：超出 {X}σ
建议动作：{进一步归因 / 持续观察 / 无需处理}
```

**精炼版（适合钉钉群）**：

```
{需求名}上线后第{N}天，核心指标{指标名}{当前值}，环比{WoW变化}%，{整体稳定/出现异动}。
```

## 分支逻辑

### 多指标同时监控

如果用户要监控 3-5 个指标：
- 并行计算每个指标的 SPC 控制限
- 在报告中分区块展示（每个指标一张卡片 + 一张图）
- 异动告警按严重度排序（3σ > 2σ > 趋势）

### 异动处理

如果检测到异动：
- **高亮显示**：红色背景 + 红色圆点标记
- **生成告警文案**：按上述模板生成
- **建议下一步**：提示用户运行 `/漏斗归因诊断` 进行根因分析

### 全部稳定

如果所有指标均稳定：
- **绿色摘要**："上线 {N} 天，{指标数} 个核心指标均稳定，无异常信号。"
- **趋势总结**：哪些指标有上升/下降趋势（即使未触发异动）

### ODPS 连接状态

- **已连接** → 自动执行 SQL 查询，拉取数据
- **未连接** → 提示用户提供数据文件（CSV/Excel），手动输入后继续

## 常见陷阱（必须避免）

1. **上线第一天数据不可靠** —— 灰度流量不完整，前 2 天数据波动大，建议从第 3 天开始分析。在报告中明确标注"前 2 天为灰度期，数据仅供参考"。

2. **同比必须对齐星期几** —— 周一对周一，周日对周日。不对齐会导致周末效应干扰判断。计算 YoY 时先确认去年同一天是星期几，偏移到相同星期。

3. **MA7 在数据不足 7 天时不计算** —— 上线后前 6 天没有完整 MA7，标记为 N/A，不要强行用不足 7 天的数据计算移动平均。

4. **异动告警必须同时给出绝对值和相对变化** —— 只说"超出 2σ"不够直观，必须同时给出"当前值 XX，环比 +X%"，让业务方快速理解影响程度。

5. **不能只看均值，要看分布（P50/P90）** —— 均值会掩盖极端情况。对于耗时、金额等偏态分布指标，必须同时看 P50（中位数）和 P90（90 分位数），避免被平均值误导。

6. **环比和同比混淆** —— 环比是 WoW（vs 上周），同比是 YoY（vs 去年同期）。报告中必须明确标注是环比还是同比，不要混用。

7. **异动不等于问题** —— 异动是统计信号，不一定是业务问题。正向异动（指标上升）可能是好结果。报告中要区分"正向异动"和"负向异动"，并给出业务判断建议。

8. **忽略节假日效应** —— 春节、国庆、双 11 等节假日会导致指标大幅波动。基线期如果包含节假日，要排除或单独标注，避免误判。
