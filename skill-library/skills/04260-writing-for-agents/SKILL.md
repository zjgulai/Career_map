这是编写任何 agent 会消费的文档时的参考：一个技能、一份 `AGENTS.md` / `CLAUDE.md`、一份通过指针抵达的文档。包装形式各不相同，但写法是相通的：同一组杠杆让每一份文档都变得可预测，因为 agent 每次运行走的是同一个_过程_，而不是产出相同的输出。

当你编写的文档是技能时，请阅读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)，了解 frontmatter、调用方式选择以及 router 技能。

## 上下文指针

**上下文指针（context pointer）**是 agent 上下文中的一个引用：它点名某份上下文之外的材料，并编码了抵达这份材料的条件。技能的 description 是一个指针；`AGENTS.md` 中点名某份文档的一行文字也是同一类对象。决定 agent 何时抵达该材料、抵达得有多可靠的，是指针的_措辞_，而不是指针的目标。一个「必须有」的目标配上一个措辞无力的指针，就是一个 variance bug（方差型缺陷：行为随运行而波动的 bug）：先打磨措辞，只有在打磨无效时才把材料内联进来。

指针做两件事：说明材料是什么，并列出应当触发抵达它的**分支（branches）**（分支是文档处理的某个独立情形，因此不同运行会走文档的不同路径）。常驻加载的指针，每个词在每一轮都要付出代价，所以它比正文更值得严格修剪：

- **把引导词（leading word）前置**：指针正是靠它完成触发工作的。
- **每个分支一个触发词。**给同一个分支换名的同义词，等于把同一个分支写了两遍；合并它们，只保留真正不同的分支。
- **删掉正文已经承载的标识信息。**

## 两种负载

你添加的每份文档、每个指针，都在消耗两种预算之一：

- **上下文负载（context load）**是常驻加载材料对 agent 窗口造成的成本：一行 `AGENTS.md`、一条技能 description、任何每一轮都躺在上下文里的东西——无论是否触发，都在消耗 token 和注意力。
- **认知负载（cognitive load）**是落在人身上的成本：存在哪些文档、何时该去翻哪一份。人是索引。这不是需要最小化的成本：它是人类主动权的代价；在人类判断重要的地方花掉它，在人类判断不重要的地方移除它。

只通过指针抵达的材料，以指针自身那一行的代价换取了免除上下文负载；完全没有指针的材料，则完全依靠认知负载。

## 信息层级

一份文档由两种内容构成：**步骤（steps）**（agent 按顺序执行的动作）和**参考（reference）**（按需查阅的定义、规则、事实）。两者可以任意混合：全是步骤（一份配方）、全是参考（评审规则、本技能），或者兼而有之。核心决策是每一块内容放在**信息层级（information hierarchy）**的哪一级——这是一个按 agent 对材料的需求紧迫程度排序的阶梯：

1. **文件内步骤（in-file step）**是第一层级：agent 要做什么，按顺序排列。
2. **文件内参考（in-file reference）**按需查阅。它常常是一组合法的平级集合（一次评审的所有规则都放在同一级），这是合理的安排，不是坏味道。
3. **披露式参考（disclosed reference）**被推到单独的文件里，通过上下文指针抵达，只在指针触发时才加载。范围从同文件夹的相邻文件，一直到存放在任何地方、任何文档都能指向的完全外部参考。

往下推得太少，顶层就会臃肿；推得太多，又会把 agent 真正需要的材料藏起来。这种张力就是决策的全部。

**渐进式披露（progressive disclosure）**就是沿阶梯向下移动（移出主文件、藏到指针之后），让顶层保持易读。它主要不是 token 优化：这是保护层级的方式。分支是判断披露与否最干净的标准：每个分支都需要的就内联，只有部分分支会抵达的就推到指针之后。当文档包含步骤时，本应披露出去的文件内参考会淹没这些步骤，把「注意到它们」变成抛硬币：这是一个 variance 杠杆，而不只是可读性杠杆。

**就近放置（co-location）**是文件内的配套手段：层级决定一块内容放_多靠下_，就近放置则决定它落位之后_什么与它相邻_。把一个概念的定义、规则和注意事项放在同一个标题之下，而不是散落各处，这样读到一部分时它的邻居也随之而来。检验标准：文档读起来应该像专门写给 agent 的文档。归组过的材料读起来就是这样，散落的则不是。（与重复（duplication）不同：重复是把同一个含义写在两处；散落是把一个含义拆碎到多处。）

**蔓延（sprawl）**是这里的失败模式：文档就是太长了——哪怕每一行都是有效且独特的。注意力在冗长中被摊薄，每多一行，就多一行需要维持相关性的内容。解药就是层级：把参考披露到指针之后，按分支或序列拆分，让每条路径只携带它需要的内容。

## 步骤与完成标准

每个步骤都结束于一个**完成标准（completion criterion）**——告诉 agent 工作已完成的那个条件。有两个属性使它成为杠杆：

- **清晰度（clarity）**：agent 能分辨「完成」与「未完成」吗？模糊的边界（比如「达成理解」）会招致**过早完成（premature completion）**：步骤还没真正做完就结束，注意力滑向_做完_本身。仍在前方的可见步骤（**完成后的后续步骤（post-completion steps）**）提供牵引力；标准的清晰度则是阻力。按顺序防守：**先打磨边界**（局部且廉价）；只有当边界不可化约地模糊_且_你确实观察到仓促完成时，才通过拆分序列把后续步骤藏起来。隐藏只在跨越真实的上下文边界时才有效（一次交接或一次 subagent 派发；内联调用会让后续步骤留在上下文里，什么也清除不掉）。
- **要求强度（demand）**：它要求多少。「每个被修改的模型都逐一核实」会迫使深入彻底的工作，而「产出一份变更清单」不会。要求强度驱动**实干活（legwork）**——agent 在工作内部所做的挖掘，它潜藏在措辞之中，而不是被写成独立的一步。而且它不局限于步骤：「每条规则都已应用」约束的是一组平级参考，正如「每个步骤都已完成」约束的是一条序列——这就是纯参考型文档依然带有穷尽性标准的方式。

最强的标准既可核验，又穷尽无遗。

## 何时拆分

把一份文档拆成两份，会消耗两种负载之一，所以只有当拆分确实值得时才拆：

- **按序列拆分**：当完成后的后续步骤会诱使 agent 草草应付眼前这一步时，把这一串步骤拆开。让后续步骤不可见，会在当前任务上逼出更多实干活。也要警惕反向操作：合并序列会让每个步骤的后续步骤暴露给接下来的内容，招致过早完成。
- **按调用方式拆分**，技能特有：参见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 引导词

**引导词（leading word）**是一个已经活在模型预训练里的紧凑概念，agent 在运行文档时用它来思考（_lesson_（课程）、_fog of war_（战争迷雾）、_tracer bullets_（示踪弹，一种先打通端到端路径的探路式实现））。它始终作为单个 token 反复出现，从不作为句子出现，由此累积出一个分布式定义，用最少的 token 锚定一整片行为区域——靠的是征用模型已有的先验。自己造词也行，只要你把它定义清楚；但人造的词征用不到任何先验：预训练词汇免费提供的东西，你得用定义 token 来付账；所以先找现成的词。

它锚定两次。在正文里是_执行_：每次这个词出现，agent 都会触及同一行为；在平级参考内部，它把注意力聚焦到要寻找的某一类事物上。在指针里是_调用_：当同一个词同时存在于你的提示词、文档和代码库中时，agent 会把这套共享语言与该材料联系起来，并更可靠地抵达它。

主动寻找用引导词重构的机会。同一组三连概念在三个地方被逐字展开，一个指针花一整句话去比划一个想法——每一处都是渴望坍缩成单个 token 的段落：

- 「fast, deterministic, low-overhead」→ _tight_（一个 _tight_ 的循环）。
- 「a loop you believe in」→ _red_，把一个模糊的关卡变成二元的可观察状态（循环在 bug 上变 _red_，或者不变）。

你赢两次：更少的 token，以及一个更锐利的钩子，让 agent 的思考有着落。默认每份文档都带着可以被引导词取代的重述。去把它们找出来。

**否定式表述（negation）**是这个杠杆旁边的失败模式：用禁止来引导，会把被禁止的行为拖进上下文，让它变得_更_可用，而不是更不可用。_不要想大象_，于是大象就成了全部；否定只是一个弱修饰语，被强激活的概念会盖过它，所以禁令读起来半像是「去做这件事」的指令。要提示**正面的**：陈述目标行为（「写单行注释」），让被禁止的行为永远不被说出口。禁令只有在它是你无法正面表述的硬性护栏时才有立足之地；即便如此，也要把它与正面目标配对，让注意力落在该做什么上。

## 修剪

- 让每个含义只有一个**单一事实来源（single source of truth）**：一个权威的位置，这样改变行为只需在一处编辑。**重复**（同一个含义出现在多处）要付出维护和 token 的代价，还会把某个含义在层级上的显眼程度吹高到超出它实际的位次。（它是引导词的意外反面：引导词是故意重复 token，从不重复含义。）
- **环境（environment）**也是事实来源（`package.json` 脚本、配置文件、目录布局、`--help` 输出），而一份复述它的文档就是一份**缓存**：一次查找的副本，只有当这次查找代价高昂时它才配得上那份负载。缓存那些 agent 靠看找不到的东西：不成文的约定、某个选择背后的原因、没有任何配置会坦白的坑。把「一个文件、一条命令」就能完成的查找留给环境，它们在那里不会过期。
- 逐行检查**相关性（relevance）**：这一行还和文档要做的事有关吗？一行文字失去相关性，要么是因为它从来与任务无关（纯粹的铺陈，或者本应披露出去的分支），要么是因为它所描述的行为或世界变了，它随之过期。更短的文档更容易保持相关。没有修剪纪律，默认的命运就是**沉积（sediment）**：一层层过时的内容沉淀下来——因为添加让人安心，删除让人忐忑——直到你不得不一层层凿穿它们，才能找到仍然有效的东西。
- 逐句排查**空操作（no-op）**：一条模型默认就会遵守的指令，付出负载却什么也没说。检验标准（「它相对默认行为改变了什么吗？」）是相对模型的，不是相对读者的：两个人在一条 no-op 上有分歧，其实是他们对默认行为有分歧，要通过实际运行文档来解决，而不是靠争论。当一句话不通过检验时，删掉整句话，而不是删几个词。这个检验同样给引导词打分：一个弱到打不过默认行为的词（agent 已经差不多够彻底时写 _be thorough_（要彻底））就是 no-op，修复方式是换一个更强的词（_relentless_（不留情面）），而不是换一种技巧。
