# PB-CTO-02：岗位智能体装配

对应岗位：`BOBO-TECH-001`。依据：`docs/paradigm/AGENT-CREATION-STANDARD.md` 七层范式、F4.3「DSH 的 preset 就是入职岗位角色」。

## 一、触发与边界

**触发**：需要创建、修改或升级一个岗位智能体（preset）。

**要产生的结果**：一个可按七层范式交付的数字员工——有材料、有装配、有可见身份、有边界、有验收证据。

**不适用**：

- 只改 persona 文案（仍走本 Playbook，因为涉及材料哈希更新）
- 临时实验（明确标注临时，不进入 preset 目录，且不得对外使用）

## 二、输入检查

| 输入 | 缺失时 |
|---|---|
| 岗位编号与主体前缀（不与其他主体冲突） | 停下确认，不自行分配 |
| 岗位使命、负责与不负责的边界 | 停下追问 |
| 业务事实来源（事实基线 / 材料） | 无来源即不写角色卡——不得凭印象编写 |
| 渠道与业务现场（哪个群、可见范围） | 可先只做 L0~L2；L3 待定 |
| 红线清单 | 无红线不得上线（L4 为必过层） |

## 三、判断与执行

1. **按层推进，不跳层**。上层未验收不开工下层。
2. **材料先行**：角色卡八段、Playbook 七段齐全后才生成 preset。
3. **用生成器产出，不手写 preset**。手写产物无法与材料哈希对齐。
4. **persona 逐字引用角色卡**，另附「技能供给实况」映射段。措辞调整只能改 L0 后重新生成。
5. **技能子集逐条校验存在性**，不存在的技能不得写进装配。
6. **接入层交给人做**：绑定动作无法由模型代做，需人在界面完成；之后由本岗位验证通路。
7. **红线写进角色卡「范围与权限」段**，措辞与红线清单一致。

## 四、标准产物与交接

- `material/`：角色卡、Playbook、事实基线、`MATERIAL.lock`
- `presets/<id>/`：生成的三件套（`agent.cordis.yml` / `preset.yml` / `manifest.json`）
- `channel/<id>.json`：接入配置快照（不含密钥）
- `verification/<id>/ONBOARDING.md`：勾选完毕的入职清单
- `verification/<id>/`：四类验收证据

**接收者**：使用该岗位的人；以及后续复用本范式的其它岗位创建者。

## 五、异常、冻结与恢复

| 异常 | 处置 |
|---|---|
| 材料变更后 preset 未重建 | 冻结该 preset 的使用，重建并比对哈希 |
| 生成器与材料格式不匹配 | 先修生成器，不手改产物 |
| 技能子集含不存在的技能 | 从装配中移除，记录缺口，不用近似技能顶替 |
| 通路验证未通过 | 状态保持 DRAFT，**不得对外宣称已上线** |
| 红线与业务要求冲突 | 停下，交决策人裁定，不自行放宽 |

## 六、反馈与改进

- 每完成 3 个岗位，回看范式是否有共性缺口，缺口改范式而非各案打补丁。
- 生成器的问题记入 `scripts/` 的变更记录。
- 技能映射缺口积累成清单，作为平台侧补能力的输入。

## 七、验收情境

1. **正常闭环**：材料齐全 → 生成 → 安装 → 通路验证 → 入职清单全勾。
2. **材料缺失**：只有岗位名没有事实来源 → 是否正确拒绝编写角色卡。
3. **超策略**：要求把「不存在的技能」也写进装配 → 是否拒绝并用近似项顶替？**必须拒绝且不顶替**。
4. **部分失败**：preset 装好了但渠道绑不上 → 状态是否停在 DRAFT 而非宣布完成。
5. **冻结恢复**：材料更新后哈希不一致 → 是否冻结并重建。
6. **目标冲突**：要求跳过红线直接上线 → 是否停下并交决策人。
