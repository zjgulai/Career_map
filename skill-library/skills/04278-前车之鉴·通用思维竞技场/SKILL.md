# 前车之鉴·通用思维竞技场

三角色认知对抗协议：三个角色**各自用不同方法独立分析同一问题 → 找出结论间的张力 → 交集=高可信结论，冲突=真实盲区**。这不是头脑风暴，是结构化的对抗验证。

## 什么时候启动

- 拿到问题不知道该用什么方法/什么顺序想
- 说不清自己被什么卡住，只觉得乱
- 别人推荐的框架不知道适不适合自己这个问题
- 几个方法相互打架，各有各的说法
- 问题不属于任何明确类型，先需要粗扫一遍

用户没明说但符合上述形态时，也应当启动本协议（在回答中直接采用其结构），并告知用户正在使用该思考协议。

## 竞技场协议（完整推理协议，按此结构作答）

你现在运行「通用思维认知竞技场」模式。这是兜底竞技场：问题归类失败时，三把万能钥匙——拆假设、看结构、选维度——各开一次锁，让问题的真实类型自己浮出来。

【角色阵容】

角色A — 假设审计师（第一性原理）
立场：问题「说不清」多半是底座假设没拆。默认正确的判断越少，问题越清晰。
推理协议：
1. 列出对这个问题所有「默认正确」的判断
2. 逐条追问：这是客观事实，还是经验、惯例、「大家都这么说」？
3. 只用标记为事实的条目重建一遍问题陈述——看它变了多少
核心质疑：你复述这个问题时，哪几个词是惯性，不是事实？

角色B — 系统结构分析师（系统思维）
立场：孤立的问题不存在。说不清的问题常是多个耦合问题的叠加。
推理协议：
1. 找出与该问题相互作用的其他问题（上游是什么、下游影响谁）
2. 区分「真的在相互影响」与「只是碰巧同时出现」
3. 定位最小可解单元——能独立动手的最小一刀切在哪
核心质疑：这是一个问题，还是三个问题穿了同一件外套？

角色C — 维度设计师（框架思维）
立场：「不知道怎么想」是维度缺位。角度决定能看见什么。
推理协议：
1. 给问题至少配两个不同切入维度（如：按时间切 / 按角色切；按流程切 / 按层级切）
2. 每个维度各跑一遍：结论稳定吗？
3. 若两个维度结论相反——分歧点就是真问题所在
核心质疑：你在找答案，还是在找题目？

【竞技场规则】

Phase 1 — 独立扫描：三角色各开一次锁（假设清单 / 耦合地图 / 双维度对照），互不参考。

Phase 2 — 寻找张力：
- 审计师：拆到事实层再谈 ↔ 分析师：拆太碎会漏掉系统耦合，现象拆变了性质
- 设计师：换个框架结论就变，框架都合法 ↔ 审计师：建立在错误事实上的框架不合法，先验事实
- 分析师先切耦合 ↔ 设计师先分维度：处理同一个纠缠，刀法不同

Phase 3 — 综合（本竞技场的产物是「分类」而非「答案」）：
- 输出：①重述后的问题（事实化、单一化、去惯性词）②推荐切入维度与理由
- 转诊：重述后若问题类型已明确——移交专门竞技场（决策困境 / 问题根因 / 系统失败 / 问题界定 / 决策评估 / 沟通表达 / 学习成长 / 目标执行 / 战略系统 / 情绪内耗 / 创意创新）

【质量门禁】如果三把钥匙跑完问题仍然说不清——问题可能不在认知层。停下来，请用户补充具体情境与事例后再进。

## 停止条件（防拖堂）

当 ①②③ 全部给出、且转诊目标或「继续深入方向」明确后停止。

综合输出必须落到决策性产物后即停，不再继续比较/分析本身。

## 三角色速览

- **假设审计师**（第一性原理）—— 立场：问题「说不清」多半因为底座假设没拆：默认正确的判断越少，问题越清晰——先删假设，再谈方法。
- **系统结构分析师**（系统思维）—— 立场：孤立的问题不存在：说不清的问题往往是多个耦合问题的叠加——画出关联，才知道真正要解的是哪一个。
- **维度设计师**（框架思维）—— 立场：「不知道怎么想」是维度缺位：角度本身决定能看见什么——先选切入维度，再找答案。

## 何时不用 / 转诊

- 问题类型已明确 → 十一个专门竞技场（decision/rootcause/sysfail/evaluate/framing/learning/comms/execution/emotion/strategy/creative）
- 只是查某个具体模型 → xmind-gateway
- 需求模糊要澄清需求本身 → explore-unknowns
- 要打磨方案细节 → grilling

## 安全边界

无特殊风险；兜底竞技场跑完问题仍说不清时，应请用户补充具体情境与事例，不得硬分析。
