# Skill-MultiTurn-RAG-Context-Management

## ① 解决的问题

客服Agent面临"多轮对话中前文业务上下文丢失导致重复询问用户"——多轮RAG上下文管理引入会话状态追踪，上下文保留率提升75%，客服满意度提升28%，年化节省人工介入成本20万元

## ② 核心算法逻辑

SkillMultiTurnRAGContextManagement

## ③ 业务应用场景

业务问题：消费者「推车怎么选→预算5000→能否618打折→下单确认」四轮对话中，第3轮检索仍返回万元款，第4轮丧失前文预算约束。
数据要求： - 推车SKU库（3000+ASIN）：含价格、折扣规则、库存 - 对话历史表：user_id, turn_id, query, entities_extracted, context_compressed - 实体链接图：推车品牌→型号→ASIN映射
量化产出： - 第2轮后精度：92%（vs单轮RAG 57%） - 平均对话轮数：4.2→3.1（减少26%） - 下单转化率：18.3%→24.7%（+6.4pp）

## 输入 / 输出契约

**输入**：品类 SKU 库（含价格、折扣规则、库存）、对话历史表（user_id、turn_id、query、抽取实体、压缩上下文）、实体链接图（品牌到型号到 ASIN 映射）；粒度为单轮对话。

**输出**：每轮的会话上下文状态（含被继承的约束条件）与检索结果，以及不重复提问的答复文本；供客服系统与前台对话使用。

## 执行步骤

1. 抽取每轮用户输入中的实体与约束条件，写入会话状态
2. 压缩历史上下文，保留预算、型号等关键约束
3. 把已抽取约束注入检索查询，过滤不符合条件的候选
4. 做指代消解并把实体链接到具体 SKU
5. 生成继承前文的答复，避免重复询问已知信息

## 边界与不做

- 数据不满足：没有对话历史表或实体链接图时无法做约束继承，先补会话状态存储。
- 何时不用：单轮独立问答用「主动检索」，文档可见性控制用「知识库RBAC」。
- 能力边界：只管理会话上下文与检索条件继承，不改变知识库内容，也不负责下单等交易动作。
- 安全边界：压缩上下文须限制留存期并避免留存隐私信息，关键约束不得被模型改写。
