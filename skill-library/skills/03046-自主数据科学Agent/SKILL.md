# DeepAnalyze — 自主数据科学Agent

## 1. 算法原理

DeepAnalyze 的核心思想是**让LLM像人类数据科学家一样工作**——不是按预定义工作流执行固定步骤，而是自主决定下一步该做什么。

**五动作编排架构**：

| 动作 | 职责 | 触发条件 |
|------|------|----------|
| **Analyze** | 文本分析、任务规划、推理、反思 | 需要理解问题或调整策略时 |
| **Understand** | 读取并理解数据源（CSV/数据库/API） | 需要了解数据结构和内容时 |
| **Code** | 生成Python代码（Pandas/NumPy/Matplotlib） | 需要对数据进行操作时 |
| **Execute** | 在环境中执行代码并收集输出/错误 | Code动作后自动触发 |
| **Answer** | 生成最终报告或回答 | 任务完成时 |

## 输入 / 输出契约

**输入**：各平台导出的原始 CSV（SKU、销量、销售额、退货、广告 spend 等字段），文件级粒度即可；卡页第 4 段未给字段级规格，落地前需统一字段名与货币单位口径。

**输出**：结构化分析报告：关键发现、数据可视化与可执行建议；卡页示例把每周 4-6 小时的多平台汇总压缩到约 5 分钟，并使报告口径标准化。

## 执行步骤

1. 读取各平台 CSV 并识别字段，建立统一的分析底座
2. 规划分析方向：平台对比、时间趋势、TOP SKU、退货率异常
3. 写代码执行清洗与指标计算，生成趋势图与对比图
4. 基于执行结果反思，对异常项再写代码深挖原因
5. 生成结构化报告，给出关键发现与可执行建议

## 边界与不做

- 数据不满足时不用：原始数据尚未导出、字段口径不统一且无人确认时，自主分析会放大错误，应先做数据接入与口径对齐。
- 能力边界：本卡产出分析与报告，不做数据治理与生产级调度，结论需业务方复核后再用于决策。
- 代码模板以 exec() 执行模型生成的代码，仅限原型；生产必须沙箱隔离、白名单 API、设执行超时，禁止直接跑在业务主机。
