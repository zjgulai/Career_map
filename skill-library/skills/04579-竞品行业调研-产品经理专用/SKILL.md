# 竞品行业调研 —— AI 产品经理专用

> 为 AI 产品经理提供系统化的竞品对比分析和行业趋势研究能力，输出可直接用于汇报和决策的结构化调研报告。

---

## 0. 读取配置（每次执行前必须完成）

在开始任何调研之前，**必须先读取以下配置文件**，按照优先级依次读取：

1. **团队 Profile**：`~/.qoderwork/plugins/config/team-profile.md`
2. **插件配置**：`~/.qoderwork/plugins/config/pm-output-engine/QODERWORK.md`

读取后重点关注 `## 输出风格` 部分，提取以下配置项：

- **调研报告格式**：HTML 报告 / Markdown / Word（默认 HTML）
- **产出存放位置**：本地工作目录 / 指定路径
- **业务设定**：用于理解调研上下文和产品线定位

**配置缺失处理**：如果配置文件不存在或仍含 `[PLACEHOLDER]` 标记，提示用户：
> "这个插件需要先配置一下，运行 /pm-output-engine:onboarding 大概 10 分钟，本插件所有 skill 都依赖它。否则输出会是通用模板，可能不符合你的实际流程。"

不要继续执行，除非用户明确要求跳过配置。

## 1. 触发条件

当用户消息匹配以下任一意图时触发本 skill：

- 提到"竞品分析"、"竞品调研"、"竞品对比"、"竞争对手"
- 提到"行业研究"、"行业趋势"、"市场调研"、"赛道分析"
- 提到具体竞品名称并要求进行对比或评估
- 提到"SWOT"、"竞争格局"、"市场份额"、"定位分析"
- 要求输出竞品报告或行业分析报告

## 2. 调研模式判定（分支逻辑）

根据用户输入判定调研模式，共三种路径：

### 模式 A：竞品聚焦型

**触发信号**：用户明确列出 2 个以上竞品名称，或要求"对比 XX 和 YY"

**执行路径**：Step 1 → Step 2（竞品维度）→ Step 3 → Step 5 → Step 6

### 模式 B：行业趋势型

**触发信号**：用户提到行业方向、赛道趋势、市场格局变化

**执行路径**：Step 1 → Step 2（行业维度）→ Step 4 → Step 5 → Step 6

### 模式 C：全景调研型（竞品 + 行业）

**触发信号**：用户既提到竞品又提到行业趋势，或要求"全面调研"

**执行路径**：Step 1 → Step 2（双维度）→ Step 3 → Step 4 → Step 5 → Step 6

**判定不明确时**，使用 AskUserQuestion 向用户确认：

```
问题：本次调研侧重哪个方向？
选项：
  A. 竞品对比分析——聚焦具体产品功能、体验、定位对比
  B. 行业趋势研究——聚焦市场格局、技术趋势、增长机会
  C. 全景调研——两者都要，输出完整报告
```

## 3. 执行流程

### Step 1：界定调研范围

**目标**：明确调研对象、维度、深度，避免"大而全但无洞察"。

**操作**：

1. **确认调研对象**
   - 竞品模式：列出目标竞品清单（建议 3-5 个），请用户确认或补充
   - 行业模式：明确行业边界（如"AI 写作工具"而非泛"AI"）

2. **确认对比维度**（竞品模式适用）
   - 向用户推荐核心维度集，使用 AskUserQuestion 确认：
     ```
     问题：本次竞品对比重点关注哪些维度？（可多选）
     选项：
       A. 产品功能与技术能力
       B. 用户体验与交互设计
       C. 商业模式与定价策略
       D. 市场定位与用户群体
     ```
   - 若用户未指定，默认使用全部四个维度

3. **确认调研深度**
   - 快速扫描（1-2 轮搜索，概览级输出）
   - 标准调研（3-5 轮搜索，含数据和分析）
   - 深度调研（多轮搜索 + 框架分析，决策级输出）

4. **输出调研计划书**
   - 以简洁列表形式向用户展示调研计划：
     ```
     📋 调研计划
     - 调研模式：竞品聚焦型
     - 目标竞品：ChatGPT、Claude、Gemini、通义千问
     - 对比维度：产品功能、用户体验、商业模式、市场定位
     - 调研深度：标准调研
     - 预计输出：HTML 对比报告 + 策略建议
     ```
   - 用户确认后进入下一步

---

### Step 2：信息采集

**目标**：系统化收集公开信息，确保信息质量和覆盖面。

#### 2A. 竞品信息采集（竞品模式 / 全景模式）

对每个竞品执行以下搜索序列：

**第一轮：基础画像**
- WebSearch：`"{竞品名称}" 产品 功能 特点 {当前年份}`
- WebSearch：`"{竞品名称}" pricing 定价 商业模式`
- 提取：公司背景、产品定位、核心功能、目标用户群

**第二轮：深度信息**
- WebSearch：`"{竞品名称}" vs "{竞品名称2}" 对比 评测 {当前年份}`
- WebSearch：`"{竞品名称}" 用户评价 体验 优缺点`
- 提取：差异化特征、用户痛点、口碑评价

**第三轮：商业数据**（标准/深度调研适用）
- WebSearch：`"{竞品名称}" 市场份额 融资 营收 {当前年份}`
- WebSearch：`"{竞品名称}" 最新动态 产品更新 {当前年份}`
- 提取：市场表现、增长趋势、最近产品动向

#### 2B. 行业信息采集（行业模式 / 全景模式）

**宏观层**
- WebSearch：`"{行业名称}" 市场规模 增长率 {当前年份}`
- WebSearch：`"{行业名称}" 行业报告 趋势分析 {当前年份}`
- 提取：市场规模、增长率、发展阶段判断

**竞争格局层**
- WebSearch：`"{行业名称}" 竞争格局 主要玩家 市场份额 {当前年份}`
- WebSearch：`"{行业名称}" 融资 投资 热度 {当前年份}`
- 提取：主要玩家、市场集中度、资本动向

**技术趋势层**
- WebSearch：`"{行业名称}" 技术趋势 创新方向 {当前年份}`
- WebSearch：`"{行业名称}" AI 大模型 应用落地 {当前年份}`
- 提取：技术演进方向、新兴机会、潜在威胁

#### 2C. 信息整理

对采集到的信息按以下结构整理（内部工作区，不直接输出给用户）：

```
[竞品/行业名称]
├── 基础信息：公司/产品概况
├── 产品能力：功能列表、技术亮点
├── 商业信息：定价、商业模式、市场数据
├── 用户反馈：评价、口碑、NPS（如有）
└── 信息来源：URL 列表（用于后续引用标注）
```

### Step 3：结构化分析（竞品模式）

**目标**：将采集到的原始信息转化为结构化、可比较的分析框架。

#### 3A. 功能维度对比矩阵

以表格形式呈现各竞品在核心功能维度上的对比：

```
| 维度         | 我方产品    | 竞品 A     | 竞品 B     | 竞品 C     |
|-------------|------------|-----------|-----------|-----------|
| 核心功能 1   | ✅ 完整支持  | ✅ 完整支持  | ⚠️ 部分支持 | ❌ 不支持    |
| 核心功能 2   | ⚠️ 部分支持  | ✅ 完整支持  | ✅ 完整支持  | ⚠️ 部分支持 |
| 技术架构     | [描述]      | [描述]     | [描述]     | [描述]     |
| 定价策略     | [描述]      | [描述]     | [描述]     | [描述]     |
| 目标用户     | [描述]      | [描述]     | [描述]     | [描述]     |
```

**矩阵编制规则**：
- 定量数据优先：有具体数字的用数字（如"支持 32 种语言"）
- 定性标注辅助：无精确数据时用 ⭐ 评级（1-5 星）或 ✅⚠️❌ 标记
- 必须标注数据来源：在表格下方以小字注明信息来源

#### 3B. SWOT 分析（每个竞品 + 我方产品）

对每个竞品和我方产品各执行一次 SWOT 分析：

```
[产品名] SWOT 分析
┌─────────────────────┬─────────────────────┐
│ S - 优势             │ W - 劣势             │
│ · [内部优势 1]        │ · [内部劣势 1]        │
│ · [内部优势 2]        │ · [内部劣势 2]        │
│ · [内部优势 3]        │ · [内部劣势 3]        │
├─────────────────────┼─────────────────────┤
│ O - 机会             │ T - 威胁             │
│ · [外部机会 1]        │ · [外部威胁 1]        │
│ · [外部机会 2]        │ · [外部威胁 2]        │
│ · [外部机会 3]        │ · [外部威胁 3]        │
└─────────────────────┴─────────────────────┘
```

**SWOT 编制要求**：
- S/W 必须基于产品实际能力，不可臆测
- O/T 必须基于行业趋势和竞争态势，需有数据支撑
- 每个象限至少 3 条，不超过 5 条
- 优先级排序：最重要的排在最前面

#### 3C. 市场定位图（文字描述）

以二维坐标系描述各竞品的市场定位：

```
          高端/专业
              │
    竞品A ●    │    ● 我方产品
              │
  封闭/整合 ───┼─── 开放/生态
              │
    竞品B ●    │    ● 竞品C
              │
          大众/通用
```

**定位图规则**：
- X 轴和 Y 轴根据实际竞争维度选择（如"开放 vs 封闭"、"专业 vs 通用"、"高价 vs 低价"）
- 在报告中使用文字描述 + 示意图呈现
- 说明选择该维度作为坐标轴的理由

### Step 4：趋势识别（行业模式）

**目标**：从采集的行业信息中提炼出对产品决策有价值的趋势洞察。

#### 4A. 趋势分类框架

将识别到的趋势按 PEST 框架分类：

- **P（Policy / 政策）**：监管政策、合规要求、行业标准
- **E（Economy / 市场）**：市场规模变化、商业模式演进、资本流向
- **S（Society / 用户）**：用户行为变化、需求升级、新场景涌现
- **T（Technology / 技术）**：技术突破、基础设施变化、AI 能力演进

#### 4B. 趋势评估矩阵

对每个趋势进行评估：

```
| 趋势              | 影响程度 | 时间窗口  | 确定性 | 对我方影响        |
|-------------------|---------|----------|-------|-----------------|
| [趋势描述 1]       | 高/中/低 | 短/中/长期 | 高/中/低 | [具体影响描述]    |
| [趋势描述 2]       | 高/中/低 | 短/中/长期 | 高/中/低 | [具体影响描述]    |
```

#### 4C. 机会与威胁提炼

从趋势中提炼出：
- **战略机会**：我方可以切入的差异化方向
- **潜在威胁**：可能削弱我方竞争力的趋势
- **时间窗口**：各机会/威胁的紧迫程度

---

### Step 5：策略建议

**目标**：基于分析结果，输出可执行的策略建议。

#### 5A. 策略建议框架

根据调研模式输出不同层次的策略建议：

**竞品模式**：
1. **短期可执行动作**（1-4 周内可落地）
   - 功能补齐优先级排序
   - 差异化功能建议
   - 定价/运营策略调整

2. **中期策略建议**（1-3 个月）
   - 产品路线图参考
   - 技术投入方向
   - 市场定位调整建议

3. **长期关注点**（3-12 个月）
   - 竞争格局演变预判
   - 需要提前布局的能力

**行业模式**：
1. **赛道判断**：该行业/赛道是否值得加大投入
2. **切入时机**：当前进入的窗口期评估
3. **差异化方向**：基于趋势的蓝海机会
4. **风险预警**：需要警惕的行业风险

**全景模式**：以上两者合并输出。

#### 5B. 策略建议撰写原则

- 每条建议必须关联到具体的分析发现（不可凭空建议）
- 使用"因为 [发现]，建议 [动作]，预期 [效果]"的结构
- 标注优先级（P0/P1/P2）和预估工作量（小/中/大）
- 如涉及不确定信息，明确标注为推测并注明依据

## 4. 质量守则（Pitfalls）

在调研和报告撰写过程中，必须严格遵守以下原则：

### 4.1 信息来源标注——每条关键信息必须注明出处

- 所有事实性陈述（数据、排名、功能描述）必须标注信息来源 URL
- 报告末尾附完整"数据来源"列表
- 无法找到可靠来源的信息，标注"⚠️ 未经验证"
- 优先使用一手来源（官方网站、官方公告）而非二手来源（媒体报道、自媒体）

### 4.2 事实与推测严格区分

- **事实**：有数据/来源支撑的陈述，正常表述
- **推测**：基于有限信息的推断，必须使用"据推测"、"可能"、"预计"等限定词
- **观点**：分析师主观判断，必须使用"本报告认为"、"分析认为"等标记
- 在报告中使用不同的视觉样式区分（如推测内容使用斜体或特殊标记）

### 4.3 杜绝抄袭和洗稿

- 不得整段复制竞品官网、第三方报告的文字
- 信息必须经过理解和重新组织，用自己的语言表述
- 引用他人观点时需注明出处并适当转述
- 数据和图表需注明来源，不可直接搬运

### 4.4 避免常见分析陷阱

- **确认偏误**：不要只搜集支持预设结论的信息，主动寻找反面证据
- **幸存者偏差**：不只关注成功的竞品，也要分析失败案例和退出者
- **锚定效应**：不以第一个搜集到的竞品信息作为基准来评判其他竞品
- **过度泛化**：行业趋势不等于每个细分赛道都适用，注意限定范围
- **时效性陷阱**：AI 行业变化极快，确保使用最新数据，标注信息获取时间

### 4.5 竞品分析的职业道德

- 不搜集或使用非公开信息（泄露的内部数据、未公开的商业机密）
- 不鼓励或引导用户提供竞品的保密信息
- 分析结论应客观公正，不为了讨好用户而贬低竞品
- 竞品优势如实呈现，不刻意弱化

### 4.6 数据质量把控

- 市场规模等定量数据，必须标注来源和时间
- 如果不同来源的数据差异较大，列出多个数据源并说明差异原因
- 不可自行编造或估算具体数字（可以说"具体数据不详"，不可瞎编）
- 用户提供的数据需要验证，标注为"用户提供，未经独立验证"

### 4.7 报告可读性保障

- 避免堆砌信息，每个分析点都要有"所以呢"（So What）的解读
- 执行摘要必须让非专业读者在 30 秒内抓住核心
- 图表和表格要有明确的标题和结论引导
- 策略建议必须具体可执行，避免"加强技术创新"这类正确但无用的废话

## 5. 交互规范

### 5.1 用户输入解析

用户输入通常有以下几种模式，需要正确解析：

| 用户输入示例 | 解析方式 | 调研模式 |
|---|---|---|
| "帮我分析一下 ChatGPT 和 Claude 的对比" | 竞品：ChatGPT、Claude | 模式 A |
| "AI 写作赛道现在怎么样" | 行业：AI 写作 | 模式 B |
| "帮我做一个 AI 编程助手的全景调研" | 竞品 + 行业：AI 编程助手 | 模式 C |
| "看看 Notion AI 最近有什么动态" | 竞品：Notion AI（轻量级） | 模式 A 快速扫描 |
| "我们公司做 AI 客服的，帮我看看市场" | 行业：AI 客服 + 竞品识别 | 模式 C |

### 5.2 过程中沟通

- Step 1 完成后向用户展示调研计划并确认
- 信息搜集中如发现关键信息缺口，及时告知用户
- 报告生成前，先输出执行摘要请用户确认方向
- 报告生成后，询问是否需要调整或深入某个方向

### 5.3 迭代与追问

用户查看报告后可能会追问：
- "XX 竞品再详细分析一下" → 对该竞品补充搜索，更新报告对应章节
- "加一个竞品 YY" → 补充搜索新竞品，更新对比矩阵和 SWOT
- "策略建议再具体一点" → 细化建议，增加落地方案细节
- "导出成 PPT 格式" → 调用 pptx skill 转换报告
