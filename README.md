# Career_map · 三宝

这是“三宝”与个人职业全景的**公开、脱敏设计投影**：用一张可缩放的画布，把跨境电商企业从组织变革、经营场景、原子能力，到 Native Agent 产品与平台融合的讨论主线持续沉淀下来。

它不是已经运行的 AgenticOS，也不包含私有业务数据、凭据、本机资料、内部工作流或可直接执行的业务动作。

## 当前已确认的设计决定

**C-068：三条经营主链共享“经营事项”的语义骨架。**

新品经营、持续经营、新市场经营在能力拆解和跨链比较时，共用以下五个对照面：

1. 经营范围与版本
2. 证据、成立条件与未知
3. 可比较的经营选项
4. 业务依赖就绪
5. 实际结果、偏差与经验反馈

这不是一套新的统一流程、数据 Schema、万能 Agent、总评分、权限模型或 Harness 结论。三条主链仍保留各自不可替代的判断和交接。

## 从来源到平台的主线

```text
组织与经营场景
        ↓
产品、知识、方法、代码与场景来源的逐项证据核对
        ↓
有边界的原子 Skill 候选（不是直接把旧产品或函数搬过来）
        ↓
Skill Bundle → DSH Preset 候选 → Native Agent 产品矩阵
        ↓
三宝工作台与 AgenticOS 的后续融合设计
```

当前阶段只建立来源路由、能力边界和验证路径；尚未宣称完成原子 Skill 清单、53 个数字分身映射、DSH preset、运行时选型、系统接入或真实经营执行。

## 研究来源范围

首轮优先来源包括：

- [AI-Native-Organization](https://github.com/zjgulai/AI-Native-Organization)：组织变革、经营价值流与数字分身的来源设计；“3+50=53”是待逐项核对的组织目标，不是复制 53 套重复能力。
- [Sanbao](https://github.com/zjgulai/Sanbao)：三宝平台、工作台与数字员工的既有成果来源。
- [Kb2Agent](https://github.com/zjgulai/Kb2Agent)：知识、证据、方法与 Agent 连接的来源。
- `zjgulai` 的公开仓库目录：按“组织与场景 / 业务产品 / 知识与数据 / 运行基础设施候选”建立来源卡，而不是按仓库名称直接认定为 Skill。
- 已授权的产品能力目录与 VOA 端到端业务场景：逐项核验后再进入能力卡，不复制访问受限内容或真实业务数据。

每项来源都必须经过“来源证据 → 场景或知识对象 → 候选能力 → 适用范围与未解问题”的记录，才可能进入下一层组合。

## 下一研究关口

下一步不是一次性拆完全部产品，而是从优先来源开始建立可审查的来源卡：

1. 核对产品目录、公开仓库和已授权 VOA 场景的范围与版本；
2. 抽取候选能力的输入、输出、依赖、证据与失败边界；
3. 对照 C-068 的五个面向，识别跨链可复用部分与各链不可替代部分；
4. 在逐项确认后，才设计 Skill Bundle、DSH preset、Native Agent 产品矩阵和三宝平台接口。

## 发布边界

此仓库刻意不提交内部连续讨论记录、本机路径、浏览器运行态、第三方代码副本、密钥、会话信息或未审查的原型页面。公开画布仅表达已允许公开的设计轮廓；内部画布和原始资料仍在受控工作区持续演进。
