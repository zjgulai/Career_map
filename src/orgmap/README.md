# 三宝组织索引

新开的只读索引应用。现有 63 页无限画布网站保持原样，不迁移、不改写、不替换。

**设计态原型，不是运行系统。** 页面固定横幅与侧栏都写明这一点。

## 运行

```bash
python3 -I scripts/build-canvas-graph.py          # 重建 data/graph.js
python3 -m http.server 8765 --bind 127.0.0.1      # ESM 需要 http，不能用 file://
# http://127.0.0.1:8765/src/orgmap/
# http://127.0.0.1:8765/src/orgmap/?audit=1       # 可读性自检
```

## Day 1 · 数据层

唯一生成物 `data/graph.js`（`window.SANBAO_GRAPH`，267KB）。用 `.js` 不用 `.json`：`file://` 下
`fetch` 被 CORS 拦截，`<script src>` 不受影响。

| 层 | 来源 | 结果 |
| --- | --- | --- |
| 决策 | `.codex/context-pack.md` | 377 条 C-000..C-376 |
| 网络节点 | 33 张卡片的 `const nodes` | 20 个，坐标只取单页 `sanbao-agenticos-vision.html` |
| 关系 | 同上 `const relations` | 126 去重：123 可解析 + 3 引用未声明节点 |
| 席位 | `.codex/pilot/seat-registry.json` | 53（50 AGT + 3 MGT） |
| 核对 | `.codex/3plus50-roster.md` | 姓名与岗位名逐条比对 |

构建期断言：377 / 63 / 33 / 20 / 126 / 53，少一个即失败；关系端点必须在节点集内；
关系依据必须是已存在 C 号；名册与登记表必须一致。`--check` 重算并逐字节比对，过期 exit 1。

## Day 2 · 索引面（当前由 WebGL 绘制 2D 图元）

`index.html` + `app.js` + `layout.js` + `style.css`，three.js 以 ESM 本地 vendor，零构建。

**注意**：相机是正交、0° 倾角、`depthTest:false`，没有任何透视或遮挡。所谓层次只有
「偏移 3 个世界单位、7% 黑」的阴影矩形。**不要称它为 2.5D 或 3D**；它的准确描述是
「用 WebGL 批量画的 2D 板」。Day 3 给出了取舍。

**渲染分工**：Three.js 只画几何（板面、部门块、席位台、关系线、箭头），
**所有文字在 DOM overlay**，字号固定，不随相机缩放。

**相机**：`OrthographicCamera`，俯视，全局倾角 0°。没有透视，所以不存在近大远小。

**两块板**（tab 切换）：

- 组织席位：一级部门 = `plane`（4 个），二级部门 = `source_group`（12 个单元）。
  业务运营 35 席分 6 块；其余按登记表原样。3 个 MGT 单独放治理导轨，不列为部门。
- 经营网络：16 个节点按源数据 4×4 `row/col` 排布，4 个跨域镜头节点单列一行。
  关系线走「列缝 + 行缝」总线，不穿卡片；画在卡片下层，不遮挡文字。

**语义缩放（换表示，不缩字号）**：

| 缩放 | 席位 | 二级标签 | 治理铭牌 |
| --- | --- | --- | --- |
| ≥ 90% | 别名 + AGT 代码 | 显示 | 显示 |
| 45–90% | 仅别名（44px 紧凑） | 显示 | 显示 |
| < 45% | 隐藏，只留部门块 | 隐藏 | 隐藏 |

**自检**：`?audit=1` 用 `getBoundingClientRect` 断言可见标签两两不重叠、字号 ≥12px，
并按折线采样断言关系线不穿过非端点卡片。已通过 1440×900、1280×720、720×450（≈200% 缩放）
和 100% 手动缩放。

## 已知缺口

- 关系层没有 `status` 字段。候选/已确认在关系上不可表达，统一按 `baseline` / `feedback` /
  未标注着色，不派生。
- `seat-registry.json` 的 `catalog_ref` 53/53 指向不存在的 `docs/05-agents/role-catalog.json`。
  **席位到卡片没有权威映射，页面不提供跳转。**
- 53 席 `production_authorized` 全为 false，52 席 UNVERIFIED。页面不使用在线灯、头像、忙碌动画。
- 3 条关系（R-04/R-10/R-17）引用未声明节点 `accountability`，不绘制，只在侧栏提示。
- 现有 63 张卡片的 11px 字号（5,416 处）未修复；本应用不宣称它们已合规。
- `.codex` 与 `.superpowers` 不在版本控制内，覆盖断言没有自动触发点。

## 3D 展示页（`showcase.html`）

工作视图（`index.html`）保持不变：正交、0° 倾角、文字在 DOM，承担 C-032 验收。

`showcase.html` 是**独立的展示页**，用真透视做空间索引：

| 项 | 实现 |
| --- | --- |
| 相机 | `PerspectiveCamera(38)`，轨道拖拽 + 滚轮，可暂停自动旋转 |
| 组织空间 | 一级部门分层抬升，二级部门为区块台，席位为立柱，柱高映射 `tier`（T0 8 → T4 40） |
| 网络空间 | 节点为细柱，**柱高 = 被引用卡数**，关系为二次贝塞尔 Tube 曲线，抬到柱顶之上 |
| 着色 | 一级部门 4 色；`PARTIAL` 席位偏琥珀；关系线按主线/反馈/未标注分色并降透明 |
| 标签 | DOM overlay，逐帧投影，边缘 clamp，不参与遮挡 |
| 拾取 | Raycaster，点立柱 → 侧栏显示席位/节点详情 |
| 光照 | 环境光 + 定向主光（2048 阴影贴图）+ 冷色轮廓光 |

**它明确不是验收视图**：透视会让远处文字变小、立柱互相遮挡，正是 C-032 禁止的做法。
所以页头固定横幅「展示视图 · 不参与可读性验收」，侧栏写明「精确阅读请回工作视图」。

已验证：组织空间 50 个席位居柱 + 12 个区块台 + 3 个治理导轨；网络空间 20 个节点柱 +
123 条关系曲线；两侧点击均能取到正确对象。

访问：`/src/orgmap/showcase.html`（`?view=network` 直达网络空间）。

## Day 3 · 任务对比与杀点判定

### 先更正 Day 3 初稿的错误

初稿说「旧画布没有索引」，**不成立**。独立审查实测：

| 旧画布实际能力 | 覆盖率 |
| --- | --- |
| 每页「决策记录」对话框，一次点击列出 C-000 起的决策索引 | 40/63 页 |
| 每页「全部关系」面板，一次点击给出 69 条关系，含方向、传递对象、双 C 号 | 33/63 页 |
| 卡片之间的链接 | **0 条** |
| 默认 DOM 中渲染的 53 席位 | **0/63 页**（只存在于 1 页的 `<script>` 源码） |

所以旧画布不是「无索引」，而是**每页自带局部索引、但没有跨页导航，也没有席位视图**。

### 三项任务（修正后）

| 任务 | 旧画布 | 新索引 | 结论 |
| --- | --- | --- | --- |
| T1 找 AGT-021 的部门 | 无渲染视图，无法回答 | 1 次点击 | **索引赢**，但赢在新增的 seat-registry 数据，不在可视化 |
| T2 追「品牌定位→定价促销」依据 | 打开对应页 + 1 次点击「全部关系」，含 object 与 C-034/C-035 | 2 次点击，修复后同样给出 object 与双 C 号 | **平手**，不是优势 |
| T3 打开「产品市场准入」主卡 | 已知文件名时 1 次打开 | 2–3 次点击（冷启动含切 tab） | **旧画布更快**；索引的优势只在「不用知道 63 个文件里的哪一个」 |

**Day 3 的真实结论**：索引的价值是**全局可寻址**（20 节点网络 + 53 席位 + 跨页来源），
不是「读取关系更快」。关系阅读上旧画布已经做得更好，索引只是追平。

### 审查后修复的缺陷

- 侧栏原先只显示对方节点的 C 号，丢掉关系自身的 `object` 与双依据；已改为
  「方向 + 对象 + 关系 kind + 双方 C 号」。
- 侧栏的 53 / 0 / 52 / 1 原为硬编码，现从 `graph.js` 派生。
- 唯一的 `PARTIAL` 席位（AGT-006）原先没有视觉区分，现为虚线琥珀边框。
- `?audit=1` 原先只查顶层标签字号，漏掉卡内 9px/11px；现遍历子元素、检查
  `scrollWidth/scrollHeight` 截断，并把「线穿卡片」纳入失败条件，输出覆盖率
  （full / reduced / aggregate / empty），切 tab 与 resize 后自动重跑。
- 三档视口最终结果：1440×900、1280×720、720×450 两块板全部 PASS；
  720×450 组织视图进入 aggregate（只显示一级部门带），网络视图进入 tiny（只显示标题）。
- 网络视图在低缩放新增 tiny 模式（只显示标题），组织视图在低缩放进入 aggregate 模式
  （只显示一级部门带），避免出现「只有 4 个标签也算 PASS」的空断言。

### 杀点判定：three.js 没有提供 3D

实测渲染内容：91 个矩形 + 428 条线段 + 123 个箭头，全部在 `OrthographicCamera`、
0° 倾角、`depthTest:false` 下绘制。没有透视、没有倾斜、没有深度遮挡。
**这是用 WebGL 画的 2D 板，不是 3D 可视化。**

672KB 的 three 只承担「批量画矩形和折线」。三个可选方向：

1. **降级为 Canvas2D（最小 diff）或 SVG**：Canvas2D 约 70–90 行替换，SVG 约 90–120 行；
   功能不减，包体从 672KB 降到 0，同时消除双渲染栈的语义分叉
   （选中变暗、缩放可见性目前各实现一遍）。独立审查判定：**砍 three，不建议「留但降级」**。
2. **补真正的 3D**：独立「展示视角」，透视相机 + 15–20° 倾斜 + 视差，只用于汇报，
   不参与 C-032 验收；工作视图保持正交。
3. 维持现状：保留 three 但当 2D 画笔用，接受 672KB 与无 WebGL 降级路径。
4. **已采纳：保留 three，但只为独立的 3D 展示页服务**（本节的 `showcase.html`）。
   工作视图仍建议后续降级为 Canvas2D —— 那时 three 只需被展示页加载，
   工作视图的冷启动从 996KB 降到约 300KB。

### 这个原型不能证明什么

- 没有用户研究，n=1、非盲；所有点击数是脚本计数，不含滚轮、hover、读屏和思考时间。
- 不能证明 2.5D 提升空间记忆：没有立体显示，也没有对照实验。
- 不能证明可长期维护：`src/orgmap` 目前 0 个 git 跟踪文件，`.codex` / `.superpowers` 也不在版本控制内。
- 不能证明 63 张卡已经合规：11px 字号（5,416 处）仍未修复。
- 不能证明与旧画布的「决策记录 / 全部关系」面板等价：索引目前不渲染 377 条决策。
